# 트럭 추적 카메라 개선 v001

33초·30fps 작업본에서 f467–f565의 빠른 이동, 위치·회전의 급변, 화면 기울기를 수정했다. 차량과 화물의 타이밍은 유지했다.

- 작업본: `pnpline-33s-truck-camera-v001.blend`
- 전체 영상: `preview/pnpline-33s-truck-camera-v001.mp4` (1280×720, 30fps, 990프레임, 33초)
- 전후 비교: `review.html` — `python scripts/serve.py` 실행 후 `http://127.0.0.1:18789/review.html`
- 기존 프레임 대응표: `frame-map.csv` (33초 작업본과 동일)

## 수정 범위

카메라 보정은 f440–f620 안에서만 적용된다. f440–f467에서 부드럽게 시작하고, f590–f620에서 기존 카메라로 돌아간다. f467–f565 이동 속도의 중앙값은 약 18% 감소했다. 반 프레임 샘플에서 발견한 위치·회전 급변을 완화하고, 항구의 수직 방향에서 창고의 수직 방향으로 기준축을 천천히 연결했다. 이 기준에 대한 롤은 해당 구간에서 0.001° 미만이다. 구면 위 건물들의 서로 다른 기울기와 원근은 그대로 보인다.

원본 카메라를 덮어쓰지 않고 `S5_SMOOTH_CAMERA` 보정 부모를 추가했다. 월드 위치와 시선 방향을 10프레임 표준편차로 평활화하고, 최대 4프레임의 카메라 지연을 적용했다. 보정은 1/8프레임 간격의 선형 키로 저장한다. 카메라 렌즈·시프트 및 물류 애니메이션은 원본 그대로다.

## 검증과 재현

`scripts/inspect.py` → `scripts/build.py` → `scripts/measure.py` → `tests/test_camera.py` 순서로 검사한다. Blender 스크립트는 Blender 5.1의 Python 환경에서 실행한다. `scripts/verify_preservation.py`는 두 파일을 독립적으로 열어 기존 오브젝트·액션·메시·재질·타임라인을 비교하고, 수정 구간 밖 811프레임의 카메라 월드 행렬과 렌즈·시프트를 확인한다.

`scripts/render.py`로 f441–f619를 다시 렌더링한다. `scripts/encode.py`는 보존 검증을 통과한 기존 프레임과 새 프레임을 합쳐 정확히 990프레임을 인코딩하고, 프레임 수·재생률·길이·전체 디코딩을 확인한다. 최종 파일과 검증 요약의 해시는 `delivery.json`에 기록한다.

원본은 `../pacing-33s-v001/pnpline-33s-30fps-v001.blend`이며 `config.json`에 기록된 SHA-256을 기준으로 검사한다.

렌더 프레임, 로그, 계측 원시 데이터와 백업 파일은 `.gitignore`로 제외한다. 최종 Blender 파일과 MP4, 스크립트, 설정, 대응표, 검증 요약을 전달한다.
