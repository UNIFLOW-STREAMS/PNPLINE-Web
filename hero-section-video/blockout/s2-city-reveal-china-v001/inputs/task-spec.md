## 1. 목적과 이번에 바뀌는 결정

기존 중국 도시·항구 프록시는 유지한다. 도시 뒤에 콘셉트 이미지의 `CHINA` 입체 문자를 추가하고, S2 카메라를 재설계한다.

**컨테이너 근경 → 선박·항만·중국 도시·CHINA 공동 공개 → 출항 선박의 후방 사선 추적 → S3 구형 지구 항해.**

완료 조건:
S2의 연속된 공개 구간에서 선박·항만·주요 랜드마크의 특징부·낮은 수변 건축과 `CHINA` 다섯 글자가 함께 읽혀야 한다. 이후 같은 도시와 문자를 뒤로 남기고 같은 선박·곡면 바다를 따라 S3로 자연스럽게 이어져야 한다.

이번 사용자 요청으로 변경되는 사항:
- STEP 1의 본편 카메라 변경 금지는 **S2 범위에 한해 해제**한다.
- STEP 1에서 제외했던 **CHINA 입체 문자를 이번에는 필수로 제작**한다.
- 도시 전체 재모델링, 미국 도시, 스타일프레임, Higgsfield 생성은 여전히 제외한다.

이 변경을 작업 폴더의 decision-log.md에 남긴다. 과거 보고서와 STEP 1 명세를 소급 수정해 당시에도 허용됐던 것처럼 만들지 않는다.

## 3. 모델·추론 노력·스킬

**권장: GPT-6 Astra / High / 단일 작성 에이전트.**
카메라·시선·지역 좌표·경계 속도를 함께 다루는 작업이므로 High를 기본으로 권한다. 단순 파일 정리·반복 출력은 Medium으로 낮출 수 있다. High로 해결되지 않는 경계/좌표 문제에만 Extra High(xhigh)를 제한적으로 검토한다. Max를 기본값으로 사용하지 않는다.

이는 작업 난도에 대한 권고다. 계정의 실제 Codex 모델 선택기와 지원 추론 단계를 확인하고, 실제 사용값을 기록한다. 확인 불가 값은 unknown으로 둔다. 프롬프트의 모델명이 실행 모델을 자동 변경하지 않으며, 높은 추론 노력도 Blender 접근 권한을 대신하지 않는다.

Codex 환경에서 가용성과 지침을 확인할 최소 스킬:
- `superpowers:systematic-debugging`: 크롭·가림·타깃/회전 제어·경계 실패의 원인 분리.
- `superpowers:executing-plans`: T1~T6 순차 실행과 판단·진행 기록.
- `superpowers:test-driven-development`: 글자 부재·특징부 크롭의 실패 재현, 보호 범위·재실행·경계 회귀 검사.
- `superpowers:verification-before-completion`: 새 결과본의 재개방·렌더·재생·AC 증거 확인 후 판정.

스킬이 없으면 같은 절차를 수동 수행하고 미사용을 밝힌다. 확인되지 않은 Blender 전용 스킬·MCP를 있다고 가정하지 않는다. 기본 수단은 실제 설치된 Blender/bpy와 기존 렌더·검증 도구다. GUI에 의존하지 않아도 되지만 결과 이미지·영상 검토는 생략하지 않는다.

하나의 .blend를 여러 에이전트가 병렬 수정하지 않는다. 가능한 경우 최종 결과에 읽기 전용 독립 검토 1회를 수행한다. 자동 커밋·설치·push 등 스킬의 기본 절차보다 본 지시서의 승인 경계를 우선한다.

## 5. CHINA 입체 문자 명세

정확한 문자열은 ASCII 대문자 `CHINA`다. C–H–I–N–A의 순서와 다섯 글자를 모두 보존한다. `中国`로 바꾸거나 화면 자막으로 대체하지 않는다.

**외형:**
- 첨부 이미지처럼 굵고 넓은 블록형 입체 문자.
- 붉은 전면, 금색 계열 테두리/베벨, 두께가 읽히는 측면.
- 프록시 수준의 단순 형상·재질이면 충분하다. 정밀 장식·금속 텍스처는 불필요하다.
- 이미지의 정확한 폰트는 미확인이다. 내장 또는 사용권이 확인된 설치 폰트를 활용하고 근사·차이를 기록한다. 새 유료 폰트 구매나 무단 다운로드는 하지 않는다.
- 재개방 시 폰트가 없어 글자가 바뀌지 않도록 최종 표시 형상을 메시 등으로 보존하고, 문자열·폰트명·형상 생성 설정을 별도 기록한다. 폰트 파일은 인계물로 재배포하지 않는다.

**공간 배치:**
- 도시 뒤쪽의 중국 지역에 고정된 입체 오브젝트로 배치한다. 도시와 같은 세계에 속해야 한다.
- 대표 공개 구도에서 붉은 정면이 읽히도록 정적인 방향·위치·크기·자간을 설정한다.
- 지역 up과 실제 지지면을 확인한다. 기존 땅에 지지시키거나 문자에 필요한 최소 신규 기초를 만든다. 새 큰 전시판·별도 바다는 만들지 않는다.
- 건물이 글자 하단 일부와 겹치는 것은 허용한다. 그러나 각 글자의 식별 형태가 남아 다섯 글자를 읽을 수 있어야 한다. 단어를 추측해 채우는 수준은 실패다.
- 문자 전체를 넣으려고 선박·도시가 작은 점이 되는 구도를 채택하지 않는다. 반대로 도시를 가리는 거대한 붉은 벽으로 만들지 않는다.

**연속성:**
카메라 자식·빌보드·카메라 추종 회전·프레임별 크기 변경·표시 토글·컷으로 가독성을 만들지 않는다. 처음부터 끝까지 같은 위치·형태다. 다른 구간에서 자연스럽게 옆면/뒷면이 보이거나 화면 밖으로 나갈 수 있다. 모든 구간에서 읽히게 강요하지 않는다.

새 컬렉션과 소유 태그를 기존 `CN_CITY_PROXY_V001` 및 `cn_proxy_owner`와 구분한다. 예: `S2_CHINA_TITLE_V001`, `s2_reveal_owner`. 글자와 기초의 추가 목록을 명시하고 기존 프록시 데이터를 공유 수정하지 않는다.

이번 CHINA는 사용자가 요구한 장면 내 상징 문자다. 웹 UI·공개 콘텐츠 언어 정책 전체를 영문으로 바꾸는 결정은 아니다. 실제 시설·항구 소유의 증빙으로 설명하지 않는다.

## 6. 카메라 설계 기준

### 먼저 대표 구도를 찾는다

실제 S2 시간축에서 선박·항만·도시가 함께 보이는 공개 구도를 만든다. 원본과 새 카메라를 같은 프레임의 같은 선박 상태에서 비교한다.

시선 타깃 높이, 카메라 거리·높이·측방 위치를 조합한다. 카메라를 무조건 올리거나 렌즈만 넓히는 방법을 기본 해법으로 삼지 않는다. 선박을 전경, 항만·저층군을 중경, 랜드마크와 CHINA를 후경으로 읽히게 하는 방향을 우선 시험한다.

우선 확인할 특징은 방송탑의 두 구체·첨탑과 상부 개구부 타워의 개구부다. 전체 네 타워를 항상 모두 보여 줄 의무는 없다. 다만 탑의 잘린 몸체와 CHINA만 보이는 화면으로 도시 공개를 통과시키지 않는다.

### 대표 구도를 연속 경로로 연결한다

- **진입:** S1의 컨테이너 근경·기존 후퇴를 이어받는다. f96에서 갑자기 도시 조감도로 바꾸지 않는다.
- **공개:** 후퇴·상승·측면 이동과 시선을 연결해 선박, 도시, CHINA가 동시에 읽히는 연속 구간을 만든다. 한 프레임만 성공하거나 타이틀 앞에서 카메라를 정지하는 구성은 피한다.
- **이탈:** 도시를 읽힌 뒤 같은 해측에서 선미 쪽으로 이어져 출항 선박을 추적한다. 별도 도시 감상 컷, 도시를 다시 보러 돌아오는 왕복, 180도 급회전을 넣지 않는다.
- **접합:** 같은 선박과 바다를 따라 S3로 이어진다. 도시·문자를 따라 돌려고 지구를 회전시키지 않는다.

공개 구간은 `reveal_window=[f_start,f_end]`로 기록한다. 길이는 실제 출력에서 판정하며 근거 없는 고정 초수·화면 점유율을 합격 기준으로 만들지 않는다. 정지 스틸뿐 아니라 정상 속도에서 읽는 여유가 있는지 보고한다. 짧은 구간이라 읽히지 않으면 실패로 남긴다.

기존 f96/124/148/180/216은 전후 비교 지점이다. 이 다섯 지점을 반드시 새 키프레임·정지 지점으로 만들지 않는다. 이전 선박 점유율 64.2% 같은 결과도 이번 목표값으로 고정하지 않는다.

## 7. S1/S3 경계와 구현상 주의

### 기본 통합 범위

기본안은 f96과 f216의 기존 경계 상태를 보존하면서 S2 내부를 수정한다. S2 밖의 평가 카메라·타깃·렌즈는 원본과 같아야 한다. 경계의 위치·방향뿐 아니라 시선과 이동/회전 속도의 연속성을 확인한다.

### 경계 변경이 필요한 경우

S2 말미를 급히 원래 위치로 되돌려 보존 검사를 통과시키지 않는다. 범위 내에서 납득할 만한 경로가 성립하지 않으면:
1. 경계를 유지한 제한안과 목표 공개 구도의 차이를 제시한다.
2. 변경이 필요한 B12/B23 상태와 S1 말미 또는 S3 초반의 최소 변경 범위·복귀 지점을 보고한다.
3. 원본/통합본과 분리한 승인 대기 후보를 남긴다. 미접합 점프가 있으면 명시한다.
4. 승인 전 S1/S3 키를 수정하거나 최종 통합 완료로 판정하지 않는다.

과거 v004의 f217..251 접합을 그대로 재사용하지 않는다. 이후 v005에서 S3 경로가 다시 수정되었으므로, 현재 프록시 원본의 평가값이 접합 기준이다. 과거 승인 범위는 이번 신규 변경의 허가가 아니다.

### 카메라와 타깃을 실제 평가값으로 확인

과거 S2 구현에는 위치·Quaternion 회전을 프레임별 키로 베이크한 코드가 있다. 현재 저장본도 조사하고, `CAM_LOOK_TARGET`만 옮기면 본편 카메라가 따라온다고 가정하지 않는다. 카메라 위치·회전·타깃·렌즈의 실제 평가값과 렌더를 함께 검증한다.

지역 수면 up, 카메라 전방축, Quaternion 부호 연속성을 확인한다. 전역 spline이나 공유 Action을 수정해 S1/S3/다른 오브젝트까지 바꾸지 않는다. 소스와 저장 키의 결과가 같은 버전이 되도록 재현 경로를 남긴다.

과거 revise_s2.py는 base-v003 경로와 자체 출력 폴더를 전제로 하므로 그대로 실행하지 않는다. 이전 전체 생성기도 장면 초기화/덮어쓰기 위험이 있어 실행·import하지 않는다.

## 8. 출력 구조와 비교 방식

새 폴더 제안:
`hero-section-video/blockout/s2-city-reveal-china-v001/`
이미 존재하면 다음 버전을 사용한다. 아래 이름은 새 산출물 제안이며 현재 존재를 주장하지 않는다.

- `inputs/base.blend`, `inputs/reference.png`, `inputs/task-spec.md`, `inputs/manifest.json`: 보존 원본·입력 해시·명세.
- `baseline-with-title.blend`: 같은 새 CHINA 배치 + 기존 카메라. 카메라 효과 비교용.
- `master-s2-city-reveal-china-v001.blend`: 선택 결과. 승인 대기면 master 대신 candidate로 명명한다.
- `title-config.json`, `camera-config.json`: 문자 설정/지역 배치와 카메라 설계·공개 구간·허용 프레임.
- `scripts/`, `tests/`: 문자 추가·카메라 수정·보존/가시성/경계 검사·렌더의 재현 코드.
- `review/`, `preview/`: 대표 구도 비교, 본편 영상, 데이터·재생·재개방 증거.
- `report.md`, `decision-log.md`, `hashes.json`: 판정·변경 결정·산출물 연결.

비교는 다음 세 상태를 구분한다.
**원본 / 같은 문자+기존 카메라 / 같은 문자+수정 카메라.**
문자 배치를 바꾸면 비교 기준본도 같은 배치로 다시 만들어 카메라 효과와 혼동하지 않는다. 기존 도시 배치는 모두 동일하다.

입력과 출력의 동일 경로, 원본 해시 불일치, 기존 산출물 무통보 덮어쓰기, 중복 문자 생성은 거부한다. 저장본은 외부 핸들러 없이 재개방·렌더 가능해야 한다. 스크립트의 재실행은 동일 결과를 재현하거나 이미 적용됐음을 명확히 알려야 한다.

## 9. 실행·검증 순서

### T1 — 원본 재현과 RED 기록

실제 원본을 보존하고 기존 테스트를 실행해 기존 실패를 구분한다. f96/124/148/180/216과 S3 f278/330/450/456을 렌더한다. 타워 특징부의 크롭과 CHINA 부재를 기록한다.

새 문자 정확성·정적 배치·경계/보호 범위·가시성 검사부터 작성하고 구현 전 실패를 확인한다. 육안 가독성과 자동 검사 항목은 구분한다.

### T2 — CHINA 제작 및 구도 탐색

문자를 단순 입체 형상으로 추가한다. 실제 지지·관통·도시 가림을 확인하고, S2 중간의 대표 공개 구도 후보를 최대 두 방향으로 비교한다. 선박의 같은 시점·같은 도시를 사용한다.

후보별로 카메라/타깃 값, 문자 배치, 보이는 특징과 한계를 기록한다. 범위 내 후보 선택은 구현자가 근거를 남기고 진행하며 불필요한 중간 승인을 반복 요청하지 않는다.

### T3 — S2 연속 경로 구현

선택 구도를 지나는 경로와 시선 흐름을 구성한다. 위치가 부드러워도 타깃 전환 때문에 화면이 휘돌면 실패다. 도시 공개의 시간 배분을 조정하되 선박·크레인·전체 타이밍은 바꾸지 않는다.

경계 유지가 불가능하면 7장의 승인 대기 절차로 전환한다. 근거 없는 좌표 미세 조정만 반복하거나 건물 축소로 문제를 숨기지 않는다.

### T4 — 보존·회귀·가시성 검사

원본 438개 오브젝트는 실제 수량을 다시 확인한 뒤 보호 목록으로 삼는다. 카메라/타깃의 허용 구간 변화와 새 문자만 예외다. 기존 도시·선박·장비·미국 구간의 형상·재질·변환·Action·가시성은 보존한다.

STEP 1의 preservation.py는 전 구간 카메라 불변과 기존 추가 목록을 검사한다. 이를 그대로 새 작업의 통과 조건으로 쓰거나 전체 카메라 검사를 제거하지 않는다. 기존 스크립트를 보존한 채 이번 작업용 검사/어댑터를 만든다.

검사는 최소 다음으로 분리한다.
- 비카메라 원본 데이터·평가 상태의 보존.
- 카메라/타깃의 허용 구간 밖 보존, 경계 연속성, 실제 변경 프레임.
- 새 문자·기초의 정확한 목록, 고정 위치·형상·표시 상태.
- 기존 프록시의 고정성·개구부·기초 지지 및 관련 행동 회귀.
- 새 경로의 도시·문자·선박·크레인·지형 관통/근접과 가림.

표본 검사 간격과 오차 허용은 기존 검사·실제 수치 오차를 근거로 기록한다. 경계·근접 구간은 최소 기존 수준의 0.25f 표본을 우선 적용하고 필요 시 세분한다. 표본 통과를 연속시간 무충돌 증명으로 과장하지 않는다.

### T5 — 실제 영상 검토

동일한 Workbench 설정, 960×540, 원래 12fps로 S2 전후와 연결 구간 f84..480을 출력한다. 구간은 실제 원본 확인 후 대응한다. 12fps 프레임을 24fps로 재생해 2배속 검토본으로 대체하지 않는다.

기존 `cn-city-proxy-v001/scripts/render.py`는 `--frames`, `--output`, `--width`, `--diagnostic`를 지원하며 `start:end`의 end는 제외한다. f84..480 포함 출력은 `84:481`이다. 본편 성공 판정은 CAM_MASTER 출력으로 하며 진단 카메라는 형상 검토에만 쓴다.

정상 재생, 느린 재생, 중간 정지/왕복 탐색을 각각 확인한다. CHINA와 랜드마크가 함께 읽히는 구간의 시작·중간·끝을 실제 프레임 번호로 제시한다. 스크럽만 하고 정상 재생 완료라고 하지 않는다.

문자가 추가됐으므로 보호된 S1/S3 카메라에서도 픽셀 차이는 생길 수 있다. 과거의 f267 이후 픽셀 동일성을 새 필수 조건으로 강제하지 않는다. 대신 데이터/동작 보존과 원치 않는 가림·그림자·프레임 침범을 검사한다. S3 이후에도 새 문자가 보이는 구간이 있으면 보고한다.

### T6 — 재개방·재현·보고

결과를 새 Blender 프로세스에서 열고 대표 프레임을 다시 렌더한다. 같은 원본+설정+스크립트로 별도 경로에 재현해 객체 구조·평가 상태·대표 렌더를 비교한다. 동일 환경의 RGB 비교와 구조 비교를 사용하되 .blend 바이너리 해시만으로 동등성을 판단하지 않는다.

diff 자기 검토 후 최종 결과 해시에 연결된 AC 보고서를 작성한다. 과거 STEP 1의 35개 성공이나 다른 후보의 로그를 새 결과 검증으로 재사용하지 않는다.

명령은 실제 경로와 지원 인자를 확인해 사용한다. 일반 형식은 다음과 같다.
`<BLENDER> --background <BLEND> --python-exit-code 1 --python <SCRIPT> -- <실제 지원 인자>`
Windows 설치 경로·F: 드라이브·새 스크립트 인자를 추측해 실행하지 않는다. 사용한 명령·환경·종료 코드·로그를 기록한다. 무관한 웹 lint/빌드·배포는 이번 검증이 아니다.

## 10. 수용 기준

### AC-1 — CHINA 존재·형태·정적 세계 배치
정확한 다섯 글자, 붉은 전면·금색 테두리·입체 두께가 확인된다. 도시 뒤에 지지된 같은 오브젝트이며 카메라 추종·문자 애니메이션·표시 토글이 없다.
검증: 문자열/생성 설정, 정면·사선 형상, 전 구간 변환·가시성·부모/제약 검사, 폰트 없이 재개방 가능한 표시 형상.

### AC-2 — 공동 공개 구간
S2의 정상 재생에서 CHINA 다섯 글자, 방송탑 특징, 상부 개구부 타워의 특징, 고층군·낮은 수변군, 항만·선박이 함께 읽히는 연속 구간이 있다. 네 타워 전체를 항상 보여 줄 필요는 없지만 글자만으로 도시 공개를 대체하지 않는다.
검증: reveal_window와 시간, 시작/중간/끝의 본편 렌더, 전체 정상 재생. 문자·특징부의 화면 이탈 및 실제 가림을 함께 확인한다. 자동 투영/가시 표본은 육안 검토의 보조자료다.

### AC-3 — 물류 중심의 연속 연출
컨테이너 근경에서 점진적 공개 후 같은 선박의 후방 추적으로 이어진다. 도시·문자만을 위한 정지 컷·급회전·왕복·선박 이탈이 없다. 읽는 시간이 부족한 순간 노출은 실패다.
검증: 본편 영상과 카메라/타깃 속도·각속도, 시선 및 프레이밍의 연속 검토.

### AC-4 — S1→S2→S3 접합
기본안은 기존 경계 및 S2 외 카메라를 보존하고 자연스럽게 이어진다. 필요한 접합 변경이 승인 대기이거나 미접합 상태면 미충족이다.
검증: f84..480 연결 재생, 경계 앞뒤/서브프레임의 위치·회전·렌즈·시선·속도 비교, 실제 승인 범위와의 대조.

### AC-5 — 기존 세계와 행동 보존
도시·항구·선박·컨테이너·항로·지구·미국 구간·시간축은 유지된다. 새 카메라/문자가 기존 물류 행동을 가리거나 관통하지 않는다.
검증: 보호 대상 데이터·전 구간 평가 비교, 새 충돌·가림 검사, 기존 행동 회귀. 영상의 픽셀 불변과 동작 보존을 혼동하지 않는다.

### AC-6 — 안전한 재현
원본 및 기존 무관한 변경은 보존되고, 별도 결과본·설정·소스로 재현된다. 저장·재개방 후 문자와 카메라가 같고 중복 적용/경로 덮어쓰기를 방지한다.
검증: 입력/출력 해시, 보호 실패 테스트, 새 프로세스 재출력, 재현 구조·평가·렌더 비교.

### AC-7 — 증거와 상태의 일치
모든 결과는 제출 .blend 버전/해시에 연결된다. AC별 통과·실패·미검증, 비교 후보·승인 상태·남은 한계가 명시된다.
검증: 보고서, 실제 파일·명령·로그·영상 대조. 자동 검사 성공을 최종 미술 승인으로 쓰지 않는다.

## 11. 중단 조건·결과 보고·공통 경계

**관련 변경을 멈추고 보고할 조건:**
- 원본/필수 참조 또는 Blender 저장·렌더 환경을 확인하지 못함.
- S1/S3 경계·카메라, 기존 도시·선박/항로, 전체 시간축 변경이 필요함.
- 렌즈/센서/클립 변경, 새 유료 서비스·자산·설치·권한 확대가 필요함.
- 허용 범위만으로 목표와 자연스러운 접합을 함께 충족하지 못함.

범위 내 카메라/문자 세부 조정은 이유를 기록하고 진행한다. 핵심 요구를 임의로 낮추지 않는다. 막힌 경우 이미 만든 결과와 실패 증거를 보존하고, 최소 변경 대안을 인계한다.

**결과 보고:**
판정은 수용 가능 / 재작업 필요 / 증거 부족으로 판정 보류 중 하나다. 필수 AC 실패·미검증 또는 필요한 승인 대기가 있으면 완료로 판정하지 않는다.

원본·결과 버전/해시, 실제 모델·추론 설정, 변경 파일/diff, 문자 배치·폰트 근거, 카메라/타깃/렌즈 변경 구간, 공개 구간, AC별 증거, 명령·환경·성공/실패·기존/신규 실패, 재생·재개방·재현 결과, 미실행 검증과 이유, 설계 이탈·후속 요구를 보고한다. 민감정보는 로그에서 제거한다.

스킬 사용 여부·독립 리뷰 여부·직접 재생과 제출 증거 검토를 구분한다. 기술적 수용과 사용자 미술 승인, 운영 공개 승인은 별개다.

**필수 경계:**
- 테스트 삭제·비활성화·규칙 완화로 통과를 꾸미지 않는다. 새 승인 범위에 따른 검사 변경은 명시적 허용 목록과 회귀 검사로 관리하고 기존 검사를 보존한다.
- 비밀키·실제 개인정보를 코드·로그·샘플에 넣지 않는다.
- 기존 무관한 변경과 미저장 GUI 작업을 보존한다.
- 승인 없는 운영 데이터 변경·운영 배포·유료 호출·강제 푸시·무관한 변경 덮어쓰기를 금지한다.
