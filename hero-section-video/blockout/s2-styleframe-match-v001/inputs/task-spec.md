## 1. 목적·결정 변경·완료 정의

최우선 시각 기준은 사용자가 선택한 s2-styleframe-001.png다.
이것을 단순한 분위기 참고가 아니라 구성·조형·배치·색면·공간 관계의 목표로 사용한다.
기존 Blender는 수정할 대상이며, 기존 프록시 배치를 보존하려고 스타일프레임을 바꾸지 않는다.

이전 지시서의 다음 제외·완화 지시는 이번 작업에서 폐기한다.
- 흰색 해안/기단을 제거하거나 낮추라는 지시.
- 장식적인 물결을 줄이거나 일반 잔물결로 바꾸라는 지시.
- 선체 측면의 대형 PNPLINE 표기를 제거하라는 지시.
- CHINA 양옆의 장식 구름을 제외하라는 지시.
- 내부 수로·교량·도시 구획을 임의 축소/생략해도 된다는 지시.

위 요소는 모두 목표 이미지에 보이는 디자인으로 보존·재현한다.
“더 자연스럽게”, “현실적으로”, “간단하게”라는 구현자 판단은 디자인 변경 허가가 아니다.
공개 시 오인 가능성 등에 대한 의견은 보고서의 별도 공개 검토 항목으로 남기되,
이 내부 previz 작업에서 디자인을 삭제하는 근거로 사용하지 않는다.

완료란:
① 실제 CAM_MASTER의 기준 프레임에서 목표 이미지의 주요 구성·디자인이 대응하고,
② 같은 편집 가능한 3D 장면이 S2 전후와 S3에서 연속적으로 성립하며,
③ 기존 선적·출항·항해·하역의 동작 제약을 훼손하지 않고,
④ 원본·재현 코드·검증 증거가 보존된 상태다.

단일 이미지로 숨겨진 면·정확한 실제 치수·수심까지 확인할 수는 없다.
보이는 부분은 이미지에 맞추고, 보이지 않는 부분만 최소한으로 설계해 가정으로 기록한다.
확인되지 않은 구조를 “원본과 정확히 복원했다”고 주장하지 않는다.

## 3. 변경 권한과 보호 경계

허용 — 별도 결과본에서 실제 오브젝트 목록으로 구체화:
- 중국 도시의 건물군 위치·크기·조형·밀도, 수변과 내부 수로·교량.
- 중국 지역의 흰색 해안/기단, 조경·정자·소규모 소품.
- CHINA의 조형·글자 간격·정적 배치, 양옆 장식 구름.
- 중국 항만의 시각 구조와 청색·백색 크레인 디자인.
- 동일 선박의 외형·선교·갑판·컨테이너 외관, 선체와 화물의 브랜드 표현.
- 목표에 필요한 재질·표면 패턴·지역 수면 표현·비교용 조명.

“허용”은 스타일프레임과 맞추기 위한 변경이지 자유 재디자인 권한이 아니다.
기존 도시/항만 형상을 유지한 채 색만 바꾸고 완료 처리하지 않는다.

기본 보호:
- CAM_MASTER와 시선 타깃의 전체 경로·회전·렌즈·sensor/shift/clip.
- 선박/화물/작동 장비의 동작 루트·경로·타이밍·인계 이벤트.
- FPS, 구간 마커·경계, 총길이, 원테이크 구조.
- 지구의 기본 중심·반지름·지역 좌표 프레임·원거리 항로.
- 미국 도시·창고·차량·S4 이후 작업 과정의 비관련 데이터.

선박 외형을 바꾸면 같은 선박이 등장하는 S1~S4에서도 그 외형이 유지되어야 한다.
이 일관된 시각 변경은 범위 내다. 그러나 항로·접안/하역 위치·동작 변경은 별도 승인 대상이다.
“다른 구간 보존”을 이유로 S2에만 다른 배를 출현시키지 않는다.

시각 메시와 동작 기준점/리그를 분리한다.
새 선체·갑판·크레인이 기존 컨테이너 지지면·스프레더·케이블·선적 위치와
실제로 연결되는지 검사한다. 보이지 않는 원본 메시와만 접촉하는 가짜 검증은 금지한다.

카메라를 먼저 바꾸지 말고 기존 f156 카메라에서 공간을 맞춘다.
잠긴 카메라·동작 아래에서 목표 디자인을 성립시키지 못하면 증거와 대안을 제출한다.
그 충돌을 이미지 삭제/변형이나 숨은 카메라 수정으로 해소하지 않는다.
카메라·렌즈·항로·시간축의 새 변경은 사용자 승인 전 통합하지 않는다.

## 4. 반드시 반영할 디자인 명세

아래 ID별로 참조 영역, 대응 오브젝트, 구현 상태를 reference-map.json에 기록한다.
정확한 도시명/시설명이나 실측 크기를 추정하지 말고 이미지의 시각적 역할로 관리한다.

D01 — 전체 구성
후면의 CHINA와 밀집 고층군, 그 앞을 감싸는 어두운 곡선형 내부 수면,
전면의 밝은 역사풍 건축·정원·저층 지붕군, 오른쪽 항만,
전경 오른쪽에 놓인 선박, 주변 바다의 층위를 유지한다.
기존 프록시의 직선형 건물 나열을 목표와 같다고 간주하지 않는다.

D02 — CHINA
붉은 전면·금색 가장자리·두께·둥근 모서리, 다섯 글자의 상대 크기와 간격,
수직 건축과의 앞뒤 겹침을 재현한다. 반드시 ASCII 대문자 CHINA다.
기존 글자 프록시가 목표와 다르면 수정한다. 이전 Bfont 모양을 절대 기준으로 삼지 않는다.

D03 — 장식 구름
왼쪽의 큰 흰색 나선형 조형물과 A 오른쪽의 작은 조형물을 보존한다.
이는 장면 안의 입체 장식이다. 삭제하거나 대기 안개로 바꾸지 않는다.
공중에 떠 보이는 장식이라는 이유로 기둥·받침을 임의 추가하지 않는다.

D04 — 고층 도시군
구체형 방송탑, 상부 개구부 타워, 단계형 첨탑, 가장 높은 완만한 타워와
그 주변 청회색·은회색 고층군의 실루엣·높낮이·전후 위치를 맞춘다.
눈에 띄는 랜드마크를 일반 상자로 대체하거나 복제하지 않는다.
중요한 입면 분할·유리/금속 색면·층단은 해당 표시 크기에서 읽히도록 구현한다.

D05 — 내부 수면과 교량
고층 도시 전면을 둘러싸는 어두운 수면의 윤곽·폭·곡률, 밝은 수변 경계,
왼쪽의 아치형 교량과 양안 관계를 반영한다.
수로를 단순 검은 바닥으로 대체하지 않는다. 그림에 없는 외부 연결구·운하를 임의 추가하지 않는다.
가려진 연결과 수심은 최소 가정으로 기록한다.

D06 — 전면 수변 건축·정원
왼쪽과 전면의 크림색 석조 건물, 돔, 아치·반복 창호,
검은 기와·붉은 기둥의 정자, 작은 정원/수목, 중앙 오른쪽의 밀집 지붕군을 반영한다.
돔·지붕·처마·입면 리듬은 보존하고, 보이지 않는 실내까지 제작하지 않는다.
화면에서 읽히는 소형 차량·조경 등도 별도 대응 목록으로 관리한다.

D07 — 우측 항만
참조에 보이는 청색·백색 크레인 구조의 규모·방향·지지부,
부두와 선박의 관계, 주변 저층 건축과 소형 차량을 반영한다.
다른 콘셉트에서 가져온 다수의 대형 크레인으로 채우지 않는다.
기존 S1 인양 동작이 새 장비 구조에서 성립하는지 반드시 확인한다.

D08 — 선박·화물·브랜드
전경의 청색 선체·붉은 수선부·흰 갑판/선교, 왼쪽 선수와 오른쪽 선미/선교의
화면 관계, 청색·백색 컨테이너의 적재 실루엣과 상대 색면을 맞춘다.
선체의 큰 흰 PNPLINE 표기와 컨테이너의 작은 표기를 모두 유지한다.
주인공 컨테이너의 개체 정체성·인계 기준점은 유지한다.
적재 구조를 목표에 맞추는 데 그 기능 기준의 변경이 필요하면 승인 대상으로 분리한다.

문자는 PNPLINE으로 정확하게 구현하고 자동 생성 텍스처의 오탈자를 복사하지 않는다.
공식 자산을 사용할 수 있으면 원본 비율·사용권을 확인한다.
공식 자산이 없으면 검토용 문자 형상으로 표시하고 최종 브랜드 검수 미완료를 기록한다.
위치·크기·색면을 없애거나 “소유 오인 방지”를 이유로 로고를 삭제하지 않는다.

D09 — 흰색 해안/기단
왼쪽 전경의 높게 솟은 흰색 경사부, 앞쪽과 오른쪽의 밝은 곡면·접힌 듯한
윤곽과 수면 접촉을 보존한다. 일반적인 낮은 콘크리트 방파제로 바꾸지 않는다.
그 실제 재료는 한 장으로 확정할 수 없으므로 “참조형 흰색 해안/기단”으로 관리한다.

D10 — 주변 바다·물결·빛
짙은 청색/청록 수면, 굵고 유선형인 밝은 파동선·반사 패턴,
해안 주변의 큰 물결 인상과 내부 수면의 상대적으로 잔잔한 대비를 유지한다.
일반 잔물결로 단순화하거나 장식적인 패턴을 삭제하지 않는다.
선택 이미지의 주간광·따뜻한 하이라이트·재질 대비를 따른다.
정확한 광원 위치·물리 수치는 미확인이므로 렌더 비교로 조정하고 가정으로 기록한다.

## 5. 실제 3D 구성 방법과 상세화 범위

- 기준 프레임의 화면상 외곽선·겹침·색면을 먼저 맞추고, 그다음 식별 디테일을 올린다.
- 모듈/인스턴스/재질 패턴을 사용할 수 있으나 군집의 폭·밀도·실루엣을 희생하지 않는다.
- 주요 외곽·개구부·교량·돔·구름·해안 단면은 실제 입체 형상으로 표현한다.
- 반복 창호·작은 입면 분할은 재질/모듈로 구현해도 된다. 전체 하이폴리 제작은 필수가 아니다.
- 단계가 previz라는 이유로 눈에 보이는 핵심 디자인을 생략하지 않는다.
- 숨은 후면·내부는 카메라가 드러내는 범위까지 최소 구조로 만들고 추론 영역을 구분한다.

수면은 기존 구형 세계에 접속해야 한다.
하나의 연속된 수면/일관된 지역 표면 체계를 우선하며, 겹치는 물판의 틈·z-fighting을 만들지 않는다.
흰 해안과 큰 물결의 인상은 유지하면서 실제 접속을 설계한다.
수면 노멀·곡면·셰이더 등은 선택할 수 있지만 실루엣에 영향을 주는 큰 형태를 가짜 평면으로 숨기지 않는다.
파도 모양의 실제 높이가 항로·선체 접촉과 충돌하면 임의로 낮추지 말고 충돌과 대안을 보고한다.

정지 프레임이 물결·구름의 시간적 움직임을 정의하지는 않는다.
첫 구현은 고정 공간에 안정적으로 부착된 패턴/형상을 우선하고,
새 물결 애니메이션이나 구름 이동을 기본 요구로 확대하지 않는다.
프레임마다 건물을 이동·축소하거나 f216에서 도시를 끄는 방식은 금지한다.
카메라에 붙인 도시 이미지, 빌보드, 장면 전체의 단일 이미지 투영으로 완료를 꾸미지 않는다.

기본색만 있는 진단 렌더와 재질·광원을 반영한 비교 렌더를 분리한다.
Workbench는 형상 진단용으로 활용하고, 디자인 확인용에는 실제 환경에서 가능한 기본 렌더 엔진을 선택한다.
새 유료 렌더러·외부 생성 API는 필요하지 않다. 선택 엔진·조명·색 관리와 한계를 기록한다.
기존 미국 재질/공유 메시를 수정하지 않도록 데이터 공유를 조사하고 필요한 복사본을 사용한다.

## 6. 구도 일치 검증 — “정확히 반영”의 판정 방법

기준 f156, 실제 CAM_MASTER로 비교한다. 다른 조감도에서만 닮았으면 실패다.
참조 이미지의 크기는 2048×1156이고 기존 추출은 1920×1080이므로 비율이 완전히 같지는 않다.
원본 이미지는 그대로 보존하고 비교용 복사본에만 등비 리사이즈+필요한 여백을 적용한다.
늘이기·회전·자르기·원근 워핑으로 비교 결과를 맞추지 않는다.

reference-map.json에 원본에서 직접 측정한 정규화 화면 좌표와 다음 대응을 기록한다.
- CHINA 각 글자의 주요 외곽과 두 구름의 외곽.
- 대표 타워 꼭대기, 방송탑 구체 중심, 개구부와 주요 가림 관계.
- 내부 수면 윤곽, 교량 양끝, 전면 건축군의 경계.
- 크레인 상단/다리, 선박 선수·선미·수선·적재 외곽, 로고 면.
- 흰 해안의 꺾임과 넓은 수면 패턴 영역.

좌표·화면 경계상자·실루엣·겹침 순서는 보조 측정이다.
자동 유사도 점수 하나나 임의의 “95% 일치”로 통과시키지 않는다.
숫자 허용치를 쓰려면 기준 측정 불확실성과 실제 출력 크기를 근거로 작업 전에 기록하며,
실패 후 결과에 맞게 넓히지 않는다.

최종 비교는 참조 / 변경 전 / 변경 후를 같은 표시 크기로 나란히 제시하고,
필요한 반투명 겹침·차이 지도는 별도 검토 자료로 남긴다.
디자인 변경이 아닌 렌더 노이즈·조명 차이와, 배치·형태 불일치를 구분한다.
정확한 픽셀 복제나 이미지에 없는 정답 3D 복원은 주장하지 않는다.

T2 — 큰 공간과 조형 정합
내부 수면·교량·해안 → 건물군 → CHINA·구름 → 항만·선박 순으로 큰 형태를 맞춘다.

선박과 작동 크레인을 보강할 때 기능 기준점과 실제 지지 표면을 함께 점검한다.
동일한 참조에 맞추는 미세 조정은 계속 진행하되 디자인 대체안의 자동 채택은 금지한다.

T3 — 식별 디테일·재질
돔·아치·기와·입면 리듬·트러스·적재 주름·정원·구름의 나선·정확한 문자 등
목표 디자인을 구분하는 요소를 추가한다. 재질·광원 비교 렌더에서 색면과 수면 표현을 맞춘다.
D01~D10의 남은 차이를 명시한다. “후반 생성 도구가 고칠 것”이라며 누락을 통과시키지 않는다.

T4 — 같은 공간의 연속성·회귀
필수 스틸 후보: f96/124/144/156/170/180/216/278/330/450/456.
실제 마커를 확인하고 S1 선적 및 S4 하역/인계의 관찰 프레임도 추가한다.
S1→S2→S3→S4를 원래 속도로 연속 확인한다.
기록상 f0..648이지만 실제 저장본의 마커가 최종 기준이다.
Workbench 검토 영상과 f156 디자인 렌더의 용도를 구분한다.

선박 외형·화물 외관 변경이 S5 이후에도 이어지면 해당 인계·도크 장면까지 검증한다.
나머지 비관련 구간은 데이터/동작 보존을 검사하고 공유 데이터 영향이 있으면 검토 범위를 확장한다.
정상 재생과 느린 재생·정지/왕복 탐색을 구분해 기록한다.
전 타임라인 평가값과 경계/근접 구간 서브프레임을 조사하며,
표본 검사를 연속시간 전체의 무충돌 증명으로 보고하지 않는다.

T5 — 재현·최종 검토·인계
새 Blender 프로세스로 저장본을 재개방한다.
같은 원본+설정+스크립트에서 별도 경로로 재현해 구조·배치·대표 렌더를 비교한다.
카메라·동작·문자·재질의 상태가 저장 후에도 유지되는지 확인한다.
최종 파일 해시에 연결된 AC별 보고와 diff 자기 검토를 수행한다.
가능하면 단일 읽기 전용 독립 검토자를 사용하되 실제 검토 범위를 밝힌다.

## 8. 기존 검사·실행 명령의 적용 원칙

기존 s2-city-reveal-china-v001/scripts/verify.py는 과거 입력에 대해
비카메라 객체를 보호하고 f97..215 내부 카메라 변경을 예외로 둔 검사다.
이번에는 반대로 디자인 메시 변경을 허용하고 기존 카메라 전체를 보호하므로 그대로 재사용할 수 없다.
과거 검사와 보고서는 보존하고, 이번 기준본과 allowed-changes.json을 사용하는 새 어댑터/검사를 작성한다.

검사를 다음으로 분리한다.
A. 원본 파일과 비관련 데이터의 불변.
B. 카메라/타깃/렌즈·시간축·동작 루트/인계 이벤트의 불변.
C. 허용된 디자인 객체의 변경과 신규 객체 소유/대체 관계.
D. 새 외형의 실제 접촉·관통·가림과 참조 디자인 정합.

이전 프록시의 객체 수·위치·평면 기초를 그대로 고정하는 검사는 이번 명세와 충돌할 수 있다.
변경 사유와 대응하는 새 테스트를 명시하되, 연결·접촉·원본 보호의 의미를 없애지 않는다.
기존 보호 검사 실패를 숨기거나 전부 skip해서 통과시키지 않는다.

기존 render_source.py는 자신의 폴더에 scene-metadata.json을 쓰며 이전 Workbench 렌더러를 호출한다.
읽기 전용 추출기라고 가정해 그대로 실행하지 말고, 새 폴더 전용 출력으로 안전하게 구성한다.
확인한 원본 스크립트의 상대 경로와 사용 인자를 조사한 뒤 실제 명령을 확정한다.

Blender 명령 형식 예시 — 그대로 실행할 확정 명령이 아님:
<BLENDER> --background <WORKING_BLEND> --python-exit-code 1 --python <TASK_SCRIPT> -- <실제 지원 인자>

기존 Windows/F: 설치 경로를 현재 환경에 있다고 가정하지 않는다.
사용 명령·Blender/렌더 엔진 버전·종료 코드·로그·프레임 범위를 보고한다.
12fps를 24fps로 올려 속도를 바꾸는 검토는 금지한다.
필요한 린트/스크립트 검사가 실제로 있으면 사용하고, 없는 웹 빌드 명령을 만들지 않는다.

## 9. 수용 기준

AC-1 — 참조 잠금
목표 이미지 해시가 유지되고 D01~D10이 대응표에 빠짐없이 연결된다.
흰 해안·물결·구름·대형 선체 로고를 임의 삭제/완화하지 않았다.
검증: 입력 해시, 대응표, 최종 f156 비교. 디자인 변경이 있다면 승인 기록 필요.

AC-2 — 구성과 공간 정합
CAM_MASTER f156에서 주요 화면 위치·크기·실루엣·가림 순서,
내부 수로/교량·도시 구획·항만/선박·기단이 참조와 대응한다.
다른 시점만 닮았거나 “비슷한 중국 도시”에 머물면 실패다.
검증: 정규화 대응점, 외곽 비교, 3열 비교와 실제 렌더의 시각 검토.

AC-3 — 디자인과 표면 정합
참조의 건축군·구름·CHINA·크레인·선체·화물·해안·수면의
특징적인 조형과 색면, 표시 크기에서 필요한 디테일이 구현됐다.
CHINA 및 PNPLINE 표기가 정확하고, 허가 없이 없어진 핵심 요소가 없다.
검증: D별 근접/전체 렌더, 문자 데이터와 시각 판정, 남은 차이 목록.

AC-4 — 실제 연속 공간
단일 이미지 투영/카메라 추종/프레임별 형상 교체 없이 같은 장면이 성립한다.
수로·교량·기단·수면 접속이 다른 관찰 시점에서도 이어지고 S2→S3에 틈·튀는 전환이 없다.
검증: 연속 영상, 보조 사선/탑뷰, 고정 환경·가시성/메시 검사.

AC-5 — 기능과 회귀
선적·인양·출항·수면 접촉·항해·미국 하역이 새 형상에서도 성립한다.
카메라/루트 동작·시간축과 비관련 미국 장면을 보호하며 새 충돌이 없다.
검증: 원본 대비 평가값·기존 행동 검사+새 형상 검사·관련 구간 재생.
데이터가 같아도 새 메시가 관통하면 실패다.

AC-6 — 안전·재현·증거
원본과 무관한 변경을 보존하고 결과본을 재개방/재현할 수 있다.
모든 로그·이미지·영상·AC 판정이 최종 결과 해시에 연결된다.
검증: 입력/출력 보호, 재생성 구조·평가·대표 렌더 비교, 실행 기록.

AC-7 — 미결·승인 구분
이미지에서 확인되지 않는 구조와 구현자의 가정을 명시한다.
디자인 또는 핵심 동작 변경 승인이 남으면 전체 완료로 판정하지 않는다.
검증: 가정/충돌/승인 목록과 사용자 시각 검토에 필요한 자료.

## 10. 중단 조건과 충돌 처리

다음 경우 관련 변경을 중단하고 이미 만든 결과를 보존한다.
- 기준 이미지·Blender 원본의 정체나 해시를 확인할 수 없다.
- 목표 디자인을 맞추려면 보호된 카메라·항로·접안·인계·시간축 변경이 필요하다.
- 정지 이미지의 투시/겹침이 하나의 일관된 공간에서 양립하지 않는다고 의심된다.
- 필수 디자인 요소를 삭제·축소·재배치해야만 동작이 성립한다.
- 범위 밖 미국 공간 재설계, 새 유료 서비스/자산·설치·권한 확대가 필요하다.

충돌 보고에는 참조 영역/프레임, 실제 렌더·공간 증거, 원인,
디자인 보존안과 최소 변경안, 재검증 범위를 포함한다.
소수 후보 실패만으로 “불가능”이라고 단정하지 않는다.

승인 전에는 스타일프레임을 수정하거나 최종 Blender에 타협안을 몰래 통합하지 않는다.
승인 후 디자인 변경이 생기면 스타일프레임과 Blender를 같은 변경 ID로 함께 갱신하고,
양쪽 정합성 확인 전까지 “기준 룩 확정”으로 보고하지 않는다.
기존 참조와 결과는 이력으로 보존한다.

## 11. 모델·추론 노력·스킬

권장 실행 모델: GPT-6 Astra / gpt-6-astra
권장 추론 노력: High
작업 방식: 단일 작성 에이전트, 필요 시 최종 읽기 전용 검토 1회.

모델/추론 수준은 추천이지 정확한 3D 복원이나 실행 도구의 보장이 아니다.
실제 Codex의 모델 선택기·권한·지원 설정을 확인한다. 미확인 런타임은 unknown으로 기록한다.
공간 대응·동작 충돌 판단은 High, 정해진 반복 렌더·파일 정리는 필요 시 Medium.
High에서 해결되지 않는 원인 조사에만 지원되는 Extra High(xhigh)를 제한적으로 검토한다.
Max나 병렬 다중 작성자를 기본값으로 쓰지 않는다.

추천 스킬 — Codex 환경에서 설치·설명·사용 지침을 재확인:
- superpowers:executing-plans: T1~T5를 순차 수행하고 판단/진행 기록 유지.
- superpowers:test-driven-development: 파일 보호·구성·기능/회귀 검사에 RED→GREEN 적용.
- superpowers:systematic-debugging: 형태 정합, 투시, 접촉·공유 데이터의 오류 원인 분리.
- superpowers:verification-before-completion: 최종 파일의 새 렌더/재생/재개방 증거 후 판정.
- creative-production:produce: 원본 보존과 정확한 콘텐츠 원칙을 시각 검토에 한정 적용.
  새 이미지 생성·스타일 변경·외부 보드 게시 권한으로 해석하지 않는다.

Blender 전용 스킬/MCP 가용성은 이 인계서에서 확인하지 않았다.
기본 수단은 실제 설치된 Blender/bpy와 기존 도구다. 없는 스킬을 사용했다고 보고하지 않는다.
이미 사용자가 선택한 디자인에 대해 brainstorming 전체를 다시 시작하거나 반복 승인을 요구하지 않는다.
하나의 .blend를 여러 에이전트가 동시에 수정하지 않는다.

## 12. 최종 보고와 공통 경계

판정: 수용 가능 / 재작업 필요 / 증거 부족으로 판정 보류.
필수 AC 실패·미검증·핵심 변경 승인 대기가 남으면 전체 완료를 선언하지 않는다.

보고 내용:
- 기준 브랜치/HEAD, 이미지·원본·결과 해시, 실제 환경·모델/추론 설정.
- D01~D10 반영 결과, 허용 변경 목록·수정 파일·diff 또는 결과 커밋.
- AC별 상태·실제 렌더/영상 증거, 명령·종료 코드·기존/신규 실패.
- 숨은 구조의 가정, 미실행 검증·이유, 남은 차이·위험·승인 필요 사항.
- 초반/종료 스타일프레임 제작에 사용할 동일 결과본의 f96/f216 후보 렌더.
  이 두 렌더는 후속 입력이며 새 스타일프레임 생성 완료가 아니다.

사용자가 디자인을 선택한 사실과 Codex의 기술 검증, 최종 3D 미술 수용, 운영 공개 승인을 구분한다.

필수 경계:
테스트 삭제·비활성화·규칙 완화로 통과를 꾸미지 않는다.
비밀키·실제 개인정보를 코드·로그·샘플에 넣지 않는다.
기존 무관한 변경과 미저장 GUI 작업을 보존한다.
승인 없는 운영 데이터 변경·운영 배포·유료 호출·강제 푸시·무관한 변경 덮어쓰기를 금지한다.
별도 요청 없는 커밋·push·PR·이슈/Notion 수정·외부 업로드를 하지 않는다.
이전 결과가 push되어 있다는 사실은 이번 push 허가가 아니다.
라이브러리/플러그인 추가는 이유·영향을 보고한다. 폰트 파일을 인계물에 포함하지 않는다.
상징적 스타일프레임을 실제 시설·선박 보유·운영 규모의 증거로 사용하지 않는다.

이제 T1부터 수행하라. 목표는 스타일프레임을 고치는 것이 아니라,
그 디자인이 같은 세계의 편집 가능한 3D 공간으로 성립하도록 Blender를 수정하는 것이다.
