반대로 선택된 경계까지 자유롭게 바꿀 수 있다고 해석하지 않는다.
실제 잠금 범위가 겹치면 변경 전에 충돌을 보고한다.

고정: 건물·도크·마당·부두·지구·도로의 실제 배치, 차량/컨테이너 비례,

프록시 차이 대응표를 먼저 만든다:
- ①: 트레일러 축 간격 1.0, 전 구간 바퀴 접지 보정, 운전석/차대 겹침 수정 기록.

  문짝 높이 1.24, 받침판 폭 1.32·중심 z=1.88 보정 기록.
이 수치는 소스의 시험 설정이며 실차 기준이 아니다. 실제 형상에서 재확인한다.

기본 선택은 최신 ①의 형상·축 간격·받침과 도크 배치를 유지하는 것이다.
테스트의 경로와 행동을 이식한 뒤 그 형상에서 접촉·문 가동을 재검증한다.
테스트의 메시·scale·geometry 변경은 일괄 이식하지 않는다.
추가 형상 변경 없이는 문·도크 접속이 성립하지 않으면 작은 수정안과 영향을 보고한다.
S5에서만 문이 작아지거나 바퀴 간격이 바뀌는 애니메이션으로 해결하지 않는다.

## 6. 이식 설계 — 객체·좌표·시간을 분리해 대응한다

### 6.1 객체와 지지 관계

source-map을 실제 Scene 구성에 맞춰 작성한다.
최소 대상: 견인부, 트레일러, 연결점, 컨테이너, 문/힌지,
바퀴, 내부 신규 화물·잔여 화물, 도크 접속 기준, 카메라·주시점.
이름의 S5T__ 접두사만 제거해 대응했다고 끝내지 않는다.

기존 asset_id/개체 ID와 Action·parent·driver·constraint·NLA 의존성을 조사한다.
새 작업본의 변경할 Action/가변 데이터만 격리하고 원본·비교 Scene에 영향이 없게 한다.
전체 메시 재제작·전체 계층 재부모화·전 Action 삭제는 금지한다.

특히 컨테이너 안의 화물을 누락하지 않는다.
본체 경로를 바꿔도 기존 월드 키 때문에 화물이 옛 위치에 남지 않아야 한다.
S5에는 컨테이너와 화물의 상대 위치가 유지되고,
S6에는 기존 첫 입고 화물만 같은 연결부에서 운반 장비로 인계되어야 한다.
신규 입고 화물과 이미 보관 중인 화물의 구분을 유지한다.

### 6.2 좌표·회전 변환

US_FRAME와 테스트 지역 프레임, 실제 도크 평면·진입축·F/R 축을 확인한다.
평가된 최종 변환을 비교해 공통 지역 좌표에서 대응시킨다.
부모 변환과 parent inverse, 회전 모드, constraint/driver/NLA의 영향을 포함한다.
동작 제공 Scene의 올바른 프레임·의존성 그래프에서 평가한다.

기존 본편의 계층/표현을 우선 유지한 채 결과를 베이크하거나
기존 생성 로직의 필요한 부분을 이식한다. 방식은 실제 구조에 맞춰 선택한다.
평가된 결과를 키로 저장한 뒤 같은 효과가 constraint로 다시 더해지는
이중 변환이 생기지 않도록 검사한다.
원점 이동·비균등 스케일·임의 180도 회전으로 좌표 불일치를 감추지 않는다.

### 6.3 시간 대응

먼저 사건 단위의 source_frame → destination_frame 표를 만든다.
조사된 테스트 사건: A648, B746, C810, 문 고정842, 후진849–890, 종료900.
이들은 동작 제공 파일의 시간이지 최종 본편 프레임이 아니다.

F_lock의 실제 상태 → 기존 도로 이동 → 테스트 접근 상태 H
→ 선회 → 정렬 → 정지·문 개방 → 후진 → S5 종료 → 기존 S6 연결로 구성한다.
기존 도로 이동이 이미 H까지 성립하면 재사용한다.
차량이 이미 이동한 구간을 다시 재생하거나 테스트 시작 위치로 되돌리지 않는다.

시간 대응은 단조 증가해야 하고, 차량·컨테이너·문·화물·바퀴가 같은 사건표를 사용한다.
H 접합은 위치만 아니라 방향·속도·각속도·견인부/트레일러 각도까지 확인한다.
보호 구간 뒤에서 필요한 완만한 접합만 조정하고 선택된 선회의 성격은 유지한다.

기본 fps와 S6/S7 시각을 우선 유지하되, 무리한 압축으로 맞추지 않는다.
선택된 동작의 속도감이나 필수 정지/문 개방 시간이 훼손되면 다음을 보고한다:
- 기존 길이를 유지하는 안의 단점.
- S5에 필요한 추가 시간과 S6 이후 이동량 Δ.
- 영향을 받는 Action/NLA/driver/마커/화물/카메라/이벤트/내보내기 범위.
총 길이·S6/S7 시간 이동은 승인 후에만 적용한다.
승인 시 후속 구간의 상대 타이밍을 보존해 함께 이동하고, 채널 일부만 이동하지 않는다.
시간 이동 전후 같은 사건 상태를 비교하여 회귀를 검증한다.

## 7. 차량 동작·접지·인계 구현

부두–도로에서는 같은 측면 추적에 맞춰 전진하며 목적지가 가까워지게 한다.
별도 관광 구간·복잡한 교차로·불필요한 추가 선회를 만들지 않는다.
마당에서는 사용자가 선택한 전진 선회로 후면을 목표 도크에 정렬한다.
B는 실제 선회 중 자세이며 같은 자리에 방향만 바뀐 상태가 아니다.

C: 운전석은 마당, 컨테이너 후면은 도크를 향하고 차량은 정지한다.
정지한 동안 두 후면 문이 열려 측면에 고정된다.
후진은 문 고정 완료 후 시작한다.
D: 같은 방향·진입축을 유지해 짧게 후진하고 도크에서 정지한다.
도면의 ‘위쪽’이 아닌 실제 도크와의 상대 관계로 판정한다.

견인부/트레일러 연결점, 바퀴와 노면, 컨테이너와 받침,
후면과 도크 바닥의 관계를 프레임·서브프레임에서 확인한다.
정밀 차량 동역학은 요구하지 않지만 옆 미끄러짐·제자리 회전·몸체 변형은 허용하지 않는다.

최신 ①의 바퀴 로컬 Z 보정 키는 옛 경로/시각에 의존할 수 있다.
경로·시간을 바꾸면 그 구간의 노면에 맞춰 보정을 재계산하고,
바퀴 회전은 실제 이동거리와 전진/후진 부호에 맞춰 갱신한다.
견인부/트레일러 키만 바꾸고 접지·조향·화물 키를 그대로 두지 않는다.
반대로 테스트의 바퀴 Action으로 최신 접지 보정을 통째로 덮어쓰지 않는다.

원문상 S5 끝은 하역 전이다. S6의 첫 입고 행동을 S5로 앞당기지 않는다.
문이 열린 뒤의 지지·충돌 여유와 D 이후 잔여 화물의 위치도 함께 확인한다.

## 8. 본편 카메라와 S6 연결

본편의 기존 카메라 하나를 계속 사용한다.
테스트 사선 카메라는 관찰 의도의 참고이며 그 Action을 그대로 교체하지 않는다.
진단 탑뷰 카메라는 별도 출력용이지 본편 카메라 전환 지점이 아니다.

카메라 흐름:
①의 선택된 출발 시점 → 같은 측면 위쪽 도로 추적
→ 차량·마당·도크를 함께 관찰 → 후면/도크 → 열린 측면의 입고 바닥.
차량 성능을 강조하는 로우앵글·추가 줌아웃·차량 한 바퀴 선회는 만들지 않는다.
차량이 선회해 보이는 면이 달라지는 것과 카메라가 반대편으로 넘어가는 것은 구분한다.

S5 종료에서 차량은 정지해도 카메라는 열린 측면을 따라 계속 이동한다.
테스트의 종료 정지 키를 그대로 사용해 S6 시작에서 다시 출발시키지 않는다.
차량과 창고를 별개의 화면으로 끊지 말고 후면–도크–입고 바닥의 연결을 남긴다.
후면 내부와 도크를 동시에 정면으로 보여 주기 위해 차량/건물을 돌리지 않는다.

S6 수정 범위는 첫 입고 행동을 이어받기 위한 카메라 접합에 한정한다.
시작 전에 F_rejoin을 정한다: 기존 S6 카메라로 자연스럽게 돌아오는 이른 관찰점.
첫 화물의 도크 통과가 보이도록 하고, 그 이후 보관·피킹 구간까지 새로 연출하지 않는다.
F_rejoin에서 위치·회전·렌즈뿐 아니라 이동·회전 속도도 이어지게 한다.
그 이후는 원본 상태 또는 승인된 시간 이동 후의 동일 상태를 유지한다.

S6의 기존 화물/운반 장비 동작은 재사용한다.
시간 이동이나 필수 접속 보정 이상의 새 작업·새 장비·새 인물을 추가하지 않는다.
F_rejoin까지 연결이 불가능하거나 S6 물체 동작/도크 형상을 바꿔야 하면
변경 이유와 최소 영향 범위를 보고하고 승인 전에는 해당 변경을 보류한다.
급회전·렌즈 점프·모션블러·기둥 가림·암전으로 접합 실패를 숨기지 않는다.

## 9. 실행 단계와 중간 통과 조건

T0. 입력·선택·보호 구간 확정
- ① 현행 결과와 선택 기록, 동작 제공 파일, 지침·환경·해시를 확인한다.
- 원본 프리뷰/상태를 재현하고 F_lock·H·S6 접속 후보·자산 차이표를 기록한다.
- 현재 파일 대상 기존 테스트를 안전한 새 로그 경로에서 실행한다.
통과: 기준 파일과 보호 범위가 명확하고 중대한 미승인 충돌이 없다.

T1. 이식 계약·시간/객체 대응
- 통제된 작은 테스트에서 좌표/부모/회전 변환의 동등성을 확인한다.
- 사건 대응표, 화물 지지 관계, 최신 바퀴 보정 처리 방식을 정한다.
- 새로운 접합/동일성/선후관계 검사는 잘못된 입력에서 실패하는 것을 먼저 확인한다.
통과: 숫자 키를 복사하지 않고 동일한 의미의 자세와 사건을 전달할 수 있다.

T2. 차량 경로 잠정 통합
- 기준 출발/도로를 유지하며 H를 연결하고 선택된 선회·문·후진을 이식한다.
- 접지·바퀴 간섭·연결점·컨테이너/화물·도크 접속을 재검증한다.
- 제공 동작과 결과를 정규화한 사건 시점에서 비교한다.
통과: S4 상태를 잃지 않고 같은 차량이 출발지에서 도크까지 이어진다.

T3. 본편 카메라·S6 초입 연결
- ① 카메라에서 S5 전체를 거쳐 F_rejoin까지 연속 경로를 구성한다.
- 실제 렌더로 목적지 가시성, 차량 비중, 연결부·첫 입고 행동을 확인한다.
통과: 차량뿐 아니라 시선의 이동도 끊기지 않는다.

T4. 저장·재개방·전체 회귀
- 새 .blend를 별도 프로세스로 열어 동일 상태와 재생을 확인한다.
- 전 구간 보호 상태와 S5/S6 접합을 다시 검사한다.
- 변경 구간을 포함한 1배속 연속 프리뷰를 실제 확인한다.
통과: 같은 저장본으로 검증 수치·영상·상태 캡처가 재현된다.

T5. ③을 위한 관찰 프레임 후보 제출
- 최종 통합본에서 S5-01/02/03/03A/04/05 후보를 추출한다.
- 프레임 번호·시각·카메라·행동·파일 해시를 대응시킨다.
통과: 서로 다른 버전의 캡처나 자유 생성 이미지가 아닌 동일 본편의 실제 순간이다.
사용자의 콘티 최종 선택·선화 재작성은 ③으로 남긴다.

범위 내 작은 구현 조정마다 재승인을 반복 요청하지 않는다.
단, 입력 선택·형상 변경·전체 리타이밍·보호 경계 변경의 게이트는 건너뛰지 않는다.

## 10. 수용 기준과 증거

AC-1 입력·선택 추적
① 결과·구도 선택·동작 제공 버전·실제 HEAD·도구 버전이 명확하다.
→ 파일 해시, 출처/선택 기록, 현행 README/report와 실제 상태 비교.

AC-2 원본과 ① 보호
원본 두 파일이 불변이고 F_lock까지의 선택된 내용과 기존 S1–S4가 유지된다.
→ 파일 해시, 객체/메시/Action 서명, 평가된 프레임·서브프레임 상태, 비교 스틸.
키 추가나 핸들 변경이 이전 구간의 보간을 바꾸는지도 확인한다.

AC-3 동일 개체·최신 자산 보존
본편 트럭/컨테이너가 그대로 이어지고 중복·교체·축척 변형이 없다.
①의 접지·축 간격·운전석 개선을 잃지 않으며 프록시 차이 처리 근거가 있다.
→ source-map, 자산 차이표, wheel-fix 회귀 및 화물 상대 변환 검사.

AC-4 출발–접근–선회의 연결
같은 장소·자세·속도로 H에 이어지고 실제 전진 선회로 C에 도달한다.
→ 경로/속도/각속도/연결점 데이터와 탑뷰·사선 연속 영상.
두 끝점이 같다는 것만으로 통과하지 않는다.

AC-5 행동 순서와 후진
정렬·정지 → 문 개방·고정 → 직선 후진 → 정지 순서가 지켜진다.
후진 속도의 방향은 차량 전방과 반대이며 후면은 도크를 향한다.
→ 사건 시각표, 속도·축·문 상태 검사, C/D 스틸·영상.

AC-6 접지·접속·화물
차체/문이 시설을 관통하지 않고 바퀴·지지면·후면/도크 관계가 성립한다.
S5 동안 화물은 같은 컨테이너 안에 남고 S6의 기존 인계와 연결된다.
→ 접지/간섭/지지 검사와 접속부 렌더. 허용 접촉과 관통을 구분한다.

AC-7 연속 본편 카메라
같은 카메라가 차량·도로·목적지·입고 연결부를 순서대로 보여 준다.
순간이동·컷·렌즈 점프 없이 차량 정지 후에도 원문의 시선 이동이 이어진다.
→ 위치/회전/렌즈·속도 검사와 가림·프레이밍 수동 검토.

AC-8 S6 연결·후속 보존
첫 입고 행동을 같은 공간에서 이어받고 F_rejoin 이후 기존 내용이 유지된다.
리타이밍은 승인된 경우에만 전체 영향 채널에 일관되게 적용된다.
→ S5/S6 경계 상태, 시간 이동 대응표, S6/S7 회귀·비교 영상.

AC-9 재현·비파괴
같은 입력/config로 재생성 가능하며 원본 덮어쓰기·중복 객체 증가가 없다.
새 프로세스에서 외부 미저장 상태나 임시 Python 핸들러 없이 재생된다.
→ 재개방 검사, 재실행 비교, 실제 실행 명령·종료 코드.

AC-10 제출 버전 일치
.blend, 검증 JSON, 영상, 관찰 프레임, plan/상태표가 같은 결과 버전에 대응한다.
→ 최종 hashes와 frame-manifest. 모든 필수 AC의 증거 위치가 연결된다.

검사는 저장된 키 숫자만이 아니라 평가된 최종 변환을 포함한다.
부동소수점 오차·충돌 근사·샘플 간격은 실행 전에 config에 근거와 함께 정한다.
변경 구간의 모든 정수 프레임과 접합·문·접촉 주변 서브프레임을 확인한다.
①의 기존 접지 검사는 후속 주행을 1/16프레임으로 검사한 기록이 있다.
통합 때문에 해당 검사 범위를 줄이거나 임계값을 완화해 통과시키지 않는다.

카메라 중심점/AABB 검사만으로 near plane·시야 가림·정밀 연속 충돌을 검증했다고 하지 않는다.
검사한 체적·대상·제외 접촉쌍·샘플 범위·미검증 사항을 보고한다.
기존 테스트의 버전명·고정 시각이 달라지면 의미를 보존한 어댑터/사건 대응 검사를 추가한다.
관련 assertion을 삭제하지 않고 기존 실패와 신규 회귀를 구분한다.
