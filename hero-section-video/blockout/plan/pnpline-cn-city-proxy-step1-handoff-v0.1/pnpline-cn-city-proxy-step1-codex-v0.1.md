## 1. 목적·완료 조건·승인 경계

기존 통합 Blender 장면의 복사본에 중국 상징 도시·항구의 정적 프록시를 구축한다. 첨부 콘셉트의 주요 실루엣과 건물군을 기존 미니어처 지구의 중국 항구 공간에 재구성하고, 이후 S2 카메라 재설계에 사용할 편집 가능한 장면을 제공한다.

사용자가 지정한 최종 완료 조건:
“S2에서 선박이 중국 항구를 출항하는 동안 중국을 상징하는 미니어처 도시가 충분히 드러나고, 카메라가 그 공간을 떠나 S3의 구형 지구 항해로 끊김 없이 이어지는가?”

이번 실행 범위는 프록시 제작·정적 배치 조정과 이 조건을 판정하는 데 필요한 검증까지다. 기존 본편 카메라·시선 타깃·렌즈·선박 항로·타이밍은 변경하지 않는다. STEP 3 카메라 재설계, 스타일프레임 생성, Higgsfield 생성은 실행하지 않는다.

완료 조건을 낮추지 않는다. 프록시가 만들어졌어도 현재 카메라에서 도시가 충분히 읽히지 않으면 전체 판정은 “재작업 필요 — 카메라 재설계 선행”이다. 제작된 프록시와 실패 증거는 그대로 인계한다. 실행·영상 확인이 불가능하면 “증거 부족으로 판정 보류”다. 카메라를 몰래 바꾸거나 비정상적으로 큰 건물을 배치해 성공으로 만들지 않는다.

범위 내에서는 정적 배치를 합리적으로 수정하며 계속 진행한다. 이미 정해진 사항을 반복해서 승인받지 않는다. 단, 카메라·접안 구조·항로 등 보호 대상의 변경이 필요하면 해당 변경을 중단하고 근거와 최소 대안을 보고한다.

## 3. 추천 모델·추론 노력·스킬

권장 작성 모델: GPT-6 Astra / gpt-6-astra.
기본 추론 노력: High. 기존 장면 조사, 지역 좌표·지구 접속, 가시성/보존 검증 판단에 사용한다.
배치가 정해진 뒤 반복 모듈 생성·파일 정리에는 Medium을 사용할 수 있다.
Extra High(xhigh)는 가림·좌표·보존 실패의 원인을 High로 해결하지 못한 조사 구간에만 제한적으로 검토한다. 처음부터 Max/Ultra 또는 다중 에이전트 병렬 편집을 쓰지 않는다.
비용 우선 대안: 실제 사용 가능한 경우 GPT-6.1 Sol / High. 이 선택은 제작 권고이지 모델 간 품질 보장이나 벤치마크 결론이 아니다.

시작 전 Codex의 실제 모델 선택기와 지원 추론 설정을 확인한다. 프롬프트에 모델명을 쓰는 것만으로 런타임 모델이 변경된다고 가정하지 않는다. 모델·설정이 확인되지 않으면 unknown으로 기록한다. 모델 선택이 Blender 실행 권한·설치·파일 접근을 대신하지 않는다.

Codex 환경에서 가용성과 사용 지침을 다시 확인할 스킬:
- superpowers:executing-plans — 아래 T1~T5를 순차 수행하고 진행·판단을 기록.
- superpowers:test-driven-development — 생성 스크립트의 입력 보호, 재실행 안정성, 보존·회귀 검사를 먼저 작성하고 실패→수정→통과 확인.
- superpowers:systematic-debugging — 가림, 지역 좌표 오류, 공유 데이터 오염, 회귀 실패의 원인을 구분.
- superpowers:verification-before-completion — 최종 저장본 재개방·새 렌더·실제 재생·AC 증거 확인 후 판정.

미술적 가독성을 자동 테스트만으로 통과시키지 않는다. 스킬이 없어도 동일한 절차를 수동 수행하고 미사용을 밝힌다. 이 인계서 작성 환경에서는 Blender 전용 스킬의 가용성을 확인하지 못했으므로 임의의 스킬명을 만들지 않는다. 기본 수단은 실행 환경의 Blender Python(bpy)와 기존 검사·렌더 도구다.

한 .blend를 여러 에이전트가 동시에 수정하지 않는다. 필요하면 최종 결과에 읽기 전용 독립 검토 1회를 사용한다. 스킬의 자동 커밋·push·설치·정리 규칙보다 본 지시서의 승인 경계를 우선한다.

## 4. 구현할 프록시와 제외 범위

이미지 전체를 하나의 메시 또는 카메라용 평면 이미지로 붙이지 않는다. 다음 형상군을 별도 선택·이동·크기 조정할 수 있게 만든다. 이름은 실제 건축물의 정확한 식별을 요구하지 않는 작업용 이름이다.

- CN_LM_SPHERE_TOWER: 구체와 가는 축·첨탑이 있는 방송탑. 구체·줄기·기단의 비례가 구분되어야 한다.
- CN_LM_TAPERED_TOWER: 가장 높은, 완만하게 좁아지는 타워. 큰 외곽선 위주이며 창문·정밀 비틀림은 생략.
- CN_LM_OPEN_TOP_TOWER: 상부가 사다리꼴로 뚫린 타워. 특징적인 개구부를 단순 형상으로 표현.
- CN_LM_STEPPED_TOWER: 층단과 뾰족한 상부가 있는 고층 타워. 몇 개의 단계형 매스로 표현.
- CN_HIGHRISE_GROUP: 서로 다른 높이의 일반 고층군. 재사용 가능한 소수의 기본 모듈로 구성.
- CN_WATERFRONT_GROUP: 수변의 밝은 중층 건축군과 탑·돔의 큰 덩어리.
- CN_LOWRISE_GROUP: 어두운 경사지붕의 저층 건물군, 작은 전통 지붕 정자의 실루엣.
- CN_SITE_CONNECTOR: 도시 지면·수변 경계·필요한 지형 연결부. 기존 바다·항로를 유지.

수량·치수·좌표는 이미지에서 실측했다고 주장하지 않는다. 장면 내 선박·컨테이너·지구와의 비례를 검토해 가정으로 기록한다. 네 대표 타워를 모두 같은 프레임에 보여 줄 의무는 없지만, 모든 타워를 단순한 동일 직육면체로 대체하지 않는다.

항구 처리:
- 기존 부두·크레인·야드·선박을 우선 재사용한다.
- 도시와 항구가 이어지는 정적 배경만 최소 보강한다.
- 이미지의 크레인 개수에 맞추려고 기존 작동 크레인을 복제하지 않는다.
- 선박·스프레더·작동 크레인의 모양과 작업 위치, 적재 관계는 보존한다.

이번에 만들지 않을 것:
거대한 CHINA 문자, 장식 구름, 사각 전시 받침대, 별도 평면 수면, 새 국기·문자·로고, 선체 대형 PNPLINE 표기, 미국 도시, 사람·차량 군중, 창문 개별 모델, 실내, 난간·배관·볼트, PBR 텍스처, 유체 시뮬레이션, 최종 조명·스타일프레임.

재질은 형태군과 깊이를 구분하는 단순 무광 색면이면 충분하다. 브랜드색이 필요한 신규 물류 면은 기존 토큰을 참고하되, 전체 장면의 재질·조명·색 관리를 바꾸지 않는다. 새 재질은 새 데이터로 만들고 원본과 공유된 재질을 수정하지 않는다. 이 결과는 상징적 프록시이며 실제 시설·규모·자산 소유의 증거가 아니다.

## 5. 지구·공간 설계와 보호 대상

5.1 세계와의 접속
과거 생성 코드에는 구형 EARTH_CONTINUOUS_OCEAN, CN_FRAME, CN_LAND_TERRACE가 있으며, 육지는 평면 작업대와 구면에 연결되는 경사 해안으로 구성되어 있다. 실제 통합 .blend에서 이름·변환·형상을 재확인한다.

“지구 위에 구현”을 “모든 건물과 부두 메시를 구면으로 강제 변형”으로 해석하지 않는다. 기존 작업대와 접안 높이는 보존하고 도시의 기초·해안이 같은 세계에 붙어 보이게 한다. 추가 부지가 필요하면 중국 측에 한정된 신규 정적 지형으로 연결한다. 구 반지름·중심·바다 메시를 바꾸거나 별도 수면 타일을 얹지 않는다.

부모 변환, 지역 up, 지형 지지면을 확인한 뒤 배치한다. 구면에 직접 놓는 부분과 기존 평면 작업대 위에 놓는 부분을 구분한다. 월드 Z를 모든 위치의 위쪽으로 가정하지 않는다. 지지면이 다른 건물은 기초로 접속하되 건물 자체를 휘지 않는다.

5.2 배치
기존 선적 위치와 출항 수로를 기준으로 항만 뒤·측면의 도시 허용 영역을 찾는다. 고층군 한 덩어리를 후면에 몰아넣기보다 주요 실루엣 사이에 간격을 두고 저층 수변군을 보이는 방향으로 분산한다. 초승달형 수변은 후보일 뿐 강제 도면이 아니다.

콘셉트의 내부 강·수로·완결된 사각 배치를 복제할 필요는 없다. 그러나 해안선과 항만 관계는 읽혀야 한다. 도시를 카메라 앞 바다에 띄우거나, 중요한 건물을 비정상적으로 키우거나, 선박이 지나갈 공간을 막아서 해결하지 않는다.

프레임별로 도시를 이동·회전·확대·숨김 처리하지 않는다. 랜드마크와 건물군은 S1~S7 전체에서 고정된 같은 환경이다. S3에서 자연스러운 원근·가림으로 화면을 떠날 수 있지만, 구간 경계에서 오브젝트를 꺼서 전환하지 않는다.

5.3 변경 허용 목록
허용: 신규 중국 도시 프록시·신규 보조 지형·새 단순 재질·검토 전용 가이드, 신규 프록시의 정적 배치 수정.
기존 CN_CITY_* 등 단순 중국 배경을 대체해야 하면 실제 이름을 확인해 명시적 목록으로 관리한다. 원본 복사본에만 정적인 표시/렌더 숨김을 적용하고 대체 관계를 기록한다. 원본 오브젝트·데이터를 삭제하지 않는다. 이름 접두사만으로 무차별 숨김 처리하지 않는다.

보호: 모든 본편 카메라와 타깃의 평가 변환·렌즈·sensor/shift/clip, 전체 타임라인·FPS·경계 마커, 지구·지역 루트 변환·바다, 선박 경로·자세·규모·적재 관계, 작동 크레인과 접안 구조, 미국 지형·도시·차량·창고·S4~S7 동작.
기존 도시의 정적 숨김 외에는 원본 메시·변환·재질을 변경하지 않는다. 보호된 지형/부두를 수정해야만 배치가 성립하면 해당 변경을 멈추고 대안을 제출한다.

진단용 탑뷰·사선 카메라는 별도 검토 출력에서만 사용한다. 본편의 활성 카메라·타임라인 카메라 마커를 바꾸거나, 진단용 조감도를 S2 성공 증거로 제출하지 않는다.

## 6. 작업 구조·안전한 재현

새 출력 폴더 제안:
hero-section-video/blockout/cn-city-proxy-v001/
동일 경로에 기존 작업이 있으면 덮어쓰지 말고 다음 버전을 사용한다.

필수 산출물 역할:
- inputs/base.blend: 작업 전 원본 보존본.
- inputs/task-spec.md, inputs/reference.png, inputs/manifest.json: 명세·이미지·원본 경로/해시·버전.
- master-cn-city-proxy-v001.blend: 기존 전체 장면을 유지한 결과본.
- proxy-config.json: 지역 좌표 기준, 각 형태군 치수·정적 배치·재사용 모듈·대체 목록.
- scripts/: 입력 보호·프록시 적용·보존/가시성 검사·렌더를 재현하는 코드.
- tests/: 새 프록시와 허용 변경을 검증하는 회귀 검사.
- review/: 전후 대표 프레임·진단뷰·가시성/보존 결과·명령 로그.
- preview/: 본편 카메라의 보강 전후 S2 및 연결 영상.
- report.md, progress.md, hashes.json: 판정·작업 기록·최종 파일 증거.

세부 함수·파일 분할은 실제 레포에 맞춰 조정하되 역할과 검증 항목은 유지한다. 새 컬렉션/오브젝트에는 충돌하지 않는 이름과 소유 태그를 부여한다. 기본 형상은 재사용하되 기존 장면의 공유 메시·재질을 오염시키지 않는다. 기존 asset_id 규칙을 확인하고 instance_id는 개체별로 유일하게 유지한다.

원본·출력 경로가 같으면 적용 스크립트는 실패해야 한다. 허용 폴더 밖 쓰기와 기존 결과의 무통보 덮어쓰기도 막는다. 재실행은 같은 원본+설정에서 같은 구조·배치를 재현하거나, 이미 적용됐다고 명확하게 거부해야 한다. 중복 도시를 계속 생성하면 실패다.

기존 Scene 이름·master_version은 호환성이 필요하면 유지하고 새 cn_proxy_version 등 별도 메타데이터로 이번 변경을 식별한다. 파일명만 바꾸고 결과 버전을 기록하지 않는 일도 피한다. 저장된 프록시는 생성 스크립트나 외부 핸들러 없이 재개방·렌더 가능해야 한다.

## 7. 실행 순서

T1 — 기준 재현과 실패 기록
1) 필수 입력·원본·환경을 확인하고 보존 복사한다. 결과 폴더와 변경 목록을 기록한다.
2) 저장된 CAM_MASTER로 f96/124/148/180/216과 S3 f278/330/450/456을 재현한다.
3) 기존 도시의 부재·가림·화면 이탈을 구분해 기록한다. 없는 랜드마크가 기존 카메라에서 읽힌다고 추측하지 않는다.
4) 기존 행동 테스트를 기준 원본에 실행해 기존 실패를 먼저 남긴다.
5) 새 프록시·보호 대상 검사를 작성한다. 원본에서 프록시 부재 검사가 실패하고 보존 기준은 성립하는지 확인한다.
산출물: 입력 기록, 기준 렌더, 기준 테스트 로그, 보호/대체 목록.

T2 — 프록시 최소 구현
1) 새 컬렉션에 주요 타워와 고층·수변 중층·저층 군집을 구현한다.
2) 기존 중국 항구와 지형에 배치하고 필요한 신규 기초·해안 접속만 추가한다.
3) 전체 공간을 탑뷰/사선 진단뷰로 확인하고 본편 대표 프레임도 렌더한다.
4) 새 형상 식별·정적 상태·지지·재실행 검사를 수행한다.
산출물: 편집 가능한 통합 복사본, 설정, 프록시 목록과 이미지 대응표.

T3 — 기존 카메라에서 정적 배치 조정
1) 동일한 카메라·렌더 설정으로 보강 전후를 비교한다.
2) 선박/크레인 가림, 랜드마크 상호 겹침, 도시가 시야에서 나가는 시점을 확인한다.
3) 도시 허용 영역 안에서만 새 프록시의 위치·방향·높낮이·군집 간격을 조정한다. 한 번에 무엇을 바꿨는지 기록한다.
4) 기능 구조와 콘셉트 비례를 해치지 않는 배치만 유지한다. 도시 면적을 무한 확장하거나 건물을 계속 높이지 않는다.
5) 합리적인 정적 배치로 해결되지 않는 원인이 확인되면 반복 상세화 대신 AC-1 실패 증거와 후속 카메라 요구를 작성한다.
산출물: 선택 배치, 실제 가시 구간/잔여 가림, 실패 시 최소 후속 요구.

T4 — 연속성·회귀·실제 재생
1) S2 f96..216과 연결 구간 f84..480을 원래 12fps로 전후 출력한다. 실제 파일에서 범위/FPS가 다르면 먼저 대응을 확인한다.
2) 전체 S3 항해가 도시 추가로 가려지거나 다른 세계로 보이지 않는지 연속 재생으로 확인한다.
3) 전 타임라인의 카메라·타깃·렌즈·보호된 동작을 기준본과 비교한다. 새 프록시와 카메라·선박·작업 장비의 충돌도 검사한다.
4) 정상 재생과 느린 재생/왕복 탐색을 구분해 실시한다. 타임라인 스크럽만 하고 정상 재생 완료라고 하지 않는다.
5) 경계·근접 위험 구간은 기존 검사 수준을 참고해 서브프레임도 표본 확인한다. 샘플 충돌 검사를 연속 충돌의 수학적 증명처럼 보고하지 않는다.
산출물: 전후 영상, 실제 재생 기록, 보존/충돌/회귀 결과.

T5 — 재개방·재현·자기 검토·인계
1) 저장본을 새 Blender 프로세스에서 열어 대표 프레임을 다시 출력한다.
2) 보존 원본+설정+스크립트에서 새 경로로 재현한다. 결과 메시·배치·재질·보호 상태와 대표 렌더를 비교한다.
3) 동일 환경에서의 재현 결과와 입력/결과 해시를 남긴다. .blend 바이너리 해시 차이만으로 시각 재현 실패/성공을 단정하지 않는다.
4) diff와 허용 목록을 대조하고 모든 AC를 판정한다. 과거 성공 로그를 새 결과의 증거로 재사용하지 않는다.
산출물: 최종 결과본·재현 방법·AC 보고서·남은 위험.

## 8. 실제 검증 도구 사용 시 주의

레포에서 확인한 tests/master_regression.py는 카메라 연속성, 고정 환경, 선박 접촉, 화물 인계 등 행동을 검사한다. 현재 원본과 결과본에 필요한 검사를 실행하되 미적 가시성을 보장한다고 해석하지 않는다. 다른 테스트는 실제 파일과 전제조건을 먼저 확인한다.

기존 s5-integration-v001/scripts/check_preservation.py는 S5 통합 작업 전용이다. 후보 오브젝트 이름이 기준본에도 존재한다고 가정하고 S5의 과거 승인 예외를 포함한다. 새 도시가 추가된 비교에 그대로 호출하면 적절하지 않다.
이번 보존 검사는 다음으로 분리한다.
- 원본에 있던 오브젝트의 보호 상태 비교.
- 명시적으로 허용한 원본 중국 배경의 정적 숨김 비교.
- 신규 오브젝트의 허용 목록·고정 상태·프록시 소유 태그 검사.
새 오브젝트를 비교에서 누락하거나 기존 S5 예외를 새 카메라 변경 허가로 사용하지 않는다. 기존 스크립트는 보존하고 작업 전용 검사/어댑터를 추가한다.

기존 scripts/render_review.py는 --frames를 지원하지만 --top은 US_FRAME 기준이다. 중국 탑뷰에 그대로 사용하지 않는다. 본편 출력은 CAM_MASTER, 중국 진단뷰는 실제 CN 지역 좌표 기준으로 별도 처리한다. 해당 스크립트의 start:end는 end 제외이므로 f84..480을 포함하려면 84:481이다.

기존 도구 확인 후 사용할 명령 형식:
<BLENDER> --background <BLEND> --python-exit-code 1 --python <검증 또는 렌더 스크립트> -- <실제 지원 인자>
위는 명령 템플릿이다. 기존 Windows 설치 경로나 F: 경로를 현재 환경에서 확인 없이 그대로 사용하지 않는다. 정확한 실행 명령·버전·종료 코드·로그 경로를 최종 보고한다.

영상 검토 기본안은 기존과 같은 960×540/12fps/Workbench다. 세부 실루엣을 판단하기 어렵다면 추가 고해상도 스틸을 만들되 저해상도 영상에서 읽힌다고 대신 주장하지 않는다. 12fps 프레임을 24fps로 빠르게 재생해 통과시키지 않는다. 무관한 웹 lint/빌드·배포 검사는 이번 검증이 아니다.

## 9. 수용 기준

AC-1 — 사용자가 지정한 도시 공개·항해 연결
조건: 기존 CAM_MASTER의 S2 출항 중 연속된 구간에서, 특징부가 구분되는 대표 랜드마크와 일반 고층군·낮은 수변군이 항만·선박과 함께 읽힌다. 탑 꼭대기만 보이거나 한 프레임만 번쩍 보이는 수준은 부족하다. 이후 같은 도시가 원근과 가림으로 멀어지면서 S3의 같은 선박·곡면 바다로 이어진다.
검증: 실제 가시 구간의 시작/끝 프레임과 재생 시간을 기록하고 시작·중간·끝 스틸 및 정상 속도 연결 영상을 제시한다. 도시 인지를 CHINA 글자·검토 라벨·진단용 다른 카메라에 의존하지 않는다. 화면 점유율과 가시 표본은 보조자료이며 임의의 “95% 가시성” 같은 자동 합격 기준은 만들지 않는다.
판정: 이 조건이 실패하거나 핵심 가독성 증거가 부족하면 전체 완료 불가. 기술적 통과와 사용자 시각 수용은 구분한다.

AC-2 — 콘셉트 대응과 편집 가능성
조건: 이미지의 주요 타워 형상, 높낮이, 수변 중층·저층 지붕군이 구분된다. 전부 획일적인 상자, 이미지 평면, 단일 불가분 메시가 아니다. 세부 창문·장식 제작은 불필요하다.
검증: 이미지의 어떤 부분을 어떤 프록시로 옮겼는지 대응표와 사선/탑뷰. 주요 그룹의 개별 편집 및 설정 변경 재현.

AC-3 — 같은 구형 세계의 정적 환경
조건: 도시 지지면과 해안이 기존 중국 항구·바다에 연결된다. 바다 이중면, 떠 있는 전시판, 눈에 띄는 지형 틈·관통, 프레임별 생성/소멸·변형이 없다. 원본 지구 반지름·항로·접안 관계는 유지된다.
검증: 지형 접속 확대뷰, S2→S3 영상, 새 환경의 전 타임라인 변환·가시성/애니메이션 데이터 검사.

AC-4 — 카메라·기존 행동 보존
조건: 카메라·타깃·렌즈·마커·FPS·선박·화물·작업 장비·미국 구간의 보호 상태가 기준본과 동일하다. 허용된 정적 배경 숨김과 신규 프록시만 차이가 난다.
검증: 전체 타임라인 평가값 및 데이터 서명 비교, 허용 목록, 관련 기존 회귀 검사. 수치 오차 허용값은 기존 검사와 실제 재현 오차를 근거로 기록한다.

AC-5 — 새로운 가림·충돌 회귀 없음
조건: 새 프록시가 카메라를 관통하거나 선박 수로·선적 행동을 막지 않는다. S3의 구면·항해 가독성을 훼손하지 않는다. 도시를 추가했으므로 원본 영상과 픽셀 차이가 나는 것 자체는 실패가 아니다.
검증: 카메라/선박/장비와 새 형상의 충돌 표본, 위험 구간의 실제 렌더·재생, 가림 원인 기록. 투영 경계상자를 실제 보이는 면적과 혼동하지 않는다.

AC-6 — 안전한 저장·재현
조건: 원본 해시 유지, 별도 결과본, 재개방 가능, 보호 대상 불변, 같은 원본과 설정에서 재현 가능, 재실행 시 중복 생성 없음.
검증: 경로 충돌 거부, 적용 전후 해시, 새 프로세스 재출력, 재생성 비교, 생성 목록 검사.

AC-7 — 증거와 상태 보고
조건: 모든 증거가 제출 결과본의 버전/해시에 연결된다. AC별 통과·실패·미검증과 이유가 있고, 과거 검사 결과를 이번 검사로 표시하지 않는다.
검증: report.md, 명령 로그, 입력/결과 해시, 실제 영상/스틸 파일의 대조.

## 10. 중단·보고·금지 사항

해당 변경을 중단하고 보고할 경우:
- 실제 원본·필수 참조 또는 저장/렌더 환경을 확인하지 못함.
- 카메라·타깃·렌즈·S2 경계·S3 경로·전체 타이밍 변경이 필요함.
- 기존 작동 부두/크레인·선박 형상·지구 반지름·미국 배치를 바꿔야 함.
- 승인 없는 설치·유료 모델/자산·권한 확대·파괴적 변경이 필요함.

AC-1 미달 시 제공할 후속 자료:
현재 프록시 결과본, 실패 프레임/연속 구간, 가리는 오브젝트, 시야 밖/가림/비례 문제 구분, 합리적으로 시도한 정적 배치와 결과, STEP 3에서 검토할 최소 카메라 요구. 실제 카메라 변경은 실행하지 않는다. 실패를 “도시를 구현했으므로 완료”로 바꾸지 않는다.

최종 보고 형식:
1) 판정: 수용 가능 / 재작업 필요 / 증거 부족으로 판정 보류.
2) 원본·결과 브랜치/HEAD·파일 경로·해시와 실제 실행 환경.
3) 추가/대체/숨김 목록, 콘셉트 대응, 허용 범위 이탈 여부.
4) AC-1~7 상태·증거·가시 구간·미검증 항목.
5) 명령·성공/실패·기존/신규 실패 구분, 재개방·재현·재생 결과.
6) 변경 파일/diff, 결과 .blend·영상·스틸·설정·스크립트·로그.
7) 다음 카메라 재설계에 필요한 사항. 스타일프레임·Higgsfield·운영 공개는 미수행이라고 구분.

필수 경계:
- 테스트 삭제·비활성화·규칙 완화로 통과를 꾸미지 않는다.
- 비밀키·실제 개인정보를 코드·로그·샘플에 넣지 않는다.
- 기존 무관한 변경과 미저장 GUI 작업을 보존한다.
- 승인 없는 운영 데이터 변경·운영 배포·유료 호출·강제 푸시·무관한 변경 덮어쓰기를 금지한다.
- 별도 요청 없는 커밋·push·PR·이슈/노션 수정·외부 업로드를 하지 않는다.
- 라이브러리 추가는 이유·영향을 보고한다. 스킬 지침이 이 경계를 우회하지 못한다.
- 자동 검사 성공, 프록시 제작 완료, 미술적 수용, 운영 공개 승인을 서로 구분한다.

이제 기존 통합 원본과 참조 이미지를 확인하고 T1부터 진행하라. 상세 모델링이나 카메라 재설계로 범위를 넓히지 말고, 실제 출력으로 최종 완료 조건을 판정하라.
