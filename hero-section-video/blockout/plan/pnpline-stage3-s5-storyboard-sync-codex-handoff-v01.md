## 4. 현재 후보의 역할 오류부터 바로잡는다

기존 frame-manifest의 후보는 다음과 같다.

이 번호를 최종 콘티의 정답으로 고정하지 않는다.

확인된 문서상 불일치:
- 기존 S5-03 f766의 event는 ‘선택된 전진 선회’다. 원래 역할은 ‘입고 마당 접근’이다.
- 기존 S5-03A f810의 event는 ‘정렬·정지’다. 원래 역할은 ‘선회·정렬 중’이다.
- scripts/package_evidence.py에도 이 매핑이 하드코딩되어 있다.

이는 후보 라벨과 요구 역할의 불일치다. 차량 동작 전체가 잘못됐다는 의미는 아니다.
f810을 ‘선회 중’으로 이름만 바꾸거나, 이미 정지한 차 옆에 화살표를 넣어 통과시키지 않는다.
먼저 실제 영상·평가 상태에서 접근 프레임과 선회 중 프레임을 다시 선택한다. f766은 S5-03A의 검토 후보로 고려할 수 있지만 재생·상태 확인 없이 확정하지 않는다.
정렬 직후·문 개방 전 f810은 보조 진단 스틸로 남길 수 있다. 이를 위해 필수 콘티 수를 자동으로 늘리지 않는다.

최종 역할 계약:
- S5-01 / 부두 출발: S4 종료에서 이어진 같은 차량이 출발하는 초기 상태. 도로·목적지와 출발지 관계가 보인다.
- S5-02 / 연결 도로 추적: 부두가 멀어지고 도로가 주된 주변 공간이 되며 같은 물류센터가 가까워진다.
- S5-03 / 입고 마당 접근: 마당·도크·방향을 정렬할 공간이 읽힌다. 본격 선회 중인 다음 관찰점과 구분한다. 문은 닫혀 있다.
- S5-03A / 마당 선회·정렬 중: 실제 전진 선회 중이며 견인부·트레일러의 자세와 위치 변화가 읽힌다. 최종 정렬 전이고 문은 닫혀 있다.
- S5-04 / 후면 정렬·문 개방: 차량은 정렬·정지, 후면은 도크를 향하고 문은 측면에 고정. 아직 후진 전이며 도크까지 빈 간격이 남는다.
- S5-05 / 도크 도착·창고로 시선 연결: 같은 차량은 접안·정지, 문은 열린 상태, 화물은 아직 내부. 카메라가 기존 개방면을 따라 입고 바닥으로 이어진다.

프레임 ID는 정지 관찰점이지 컷이나 새 카메라를 뜻하지 않는다. 같은 CAM_MASTER에서 시간 순서가 이어져야 한다.
화살표와 메모를 가려도 03/03A/04의 상태가 구분되는지 본다. 속도·감속은 주변 프레임/영상과 상태 데이터로 확인하며 스틸 한 장만으로 입증했다고 하지 않는다.
필수 역할에 맞는 실제 프레임이 없으면 ‘재선정으로 해결 불가’로 보고한다. 새로운 자세를 이미지에 그려 넣지 않는다.

## 5. 권장 제작 방식 — 구조와 표현을 분리한다

단계 A: 실제 본편 프레임 + 정확한 메모로 구조 검토용 콘티 초안을 만든다.
단계 B: 선택된 동일 프레임을 기준으로 흑백 러프 선화 표현을 정리한다.
단계 C: 최종 저장본과 표현본을 대조하고, 사용자 선택을 받은 뒤 최종 묶음으로 확정한다.

자동 이미지 생성으로 모든 장면을 새로 상상하는 방식은 기본 경로가 아니다.
권장 기본안은 동일한 3D 상태·카메라에서 로컬 선화 렌더/윤곽 정리 후 콘티 레이아웃을 적용하는 방식이다. 가용한 Blender Freestyle 등은 설치된 버전·렌더 엔진의 지원을 확인하고 최소 샘플로 검토한다. 기존 생성 보드와 손그림 느낌이 완전히 같다고 보장하지 않는다.

선화 렌더/이미지 가공은 별도 임시 프로세스·작업 파일에서 한다. 본편의 재질·World·렌더 설정을 바꾸어 저장하지 않는다. 생성한 선화 Scene이나 진단 카메라를 최종 본편에 추가할 필요는 없다.
단순 회색 변환 이미지를 선화가 완성됐다고 보고하지 않는다. 화이트 배경, 읽히는 가는 윤곽, 제한된 명암/해칭, 기존의 테두리·하단 메모 영역이라는 시각 기준을 검토한다.

로컬 표현만으로 원하는 손그림 수준이 나오지 않으면 다음을 인계한다:
실제 무주석 프레임, 선화 기준 이미지, 고정 구조 설명, 프레임 ID/해시, 한 장별 표현 수정 지시.
사용자가 ChatGPT 이미지 생성으로 정리한 결과는 다시 받아 구조 대조 후 편입한다. Codex에 동일 이미지 도구가 있다고 가정하거나 무단 외부 호출을 하지 않는다. 표현본이 없으면 ‘프레임 초안 완료 / 선화 정리 대기’로 구분한다.

표현에서 금지:
차량/컨테이너 길이 변경, 운전석·후면 교환, 문 위치 변경, 창고·도로 재배치,
좌우 반전, 카메라 변경, 원근 워프, 구조를 지우는 가림/안개,
로고를 보이게 하려고 면·표시 위치를 옮기는 처리, 여러 순간을 한 장에 합치는 처리.
선화의 존재하지 않는 디테일을 새 자산의 승인 디자인으로 해석하지 않는다.

본편 영상 영역의 종횡비와 프레이밍을 보존한다. 하단 메모는 영상 밖 여백에 추가한다.
개별 장면을 예쁘게 보이게 하려고 임의로 크롭·줌인하지 않는다. 축소·여백·표시용 오프셋은 대응표에 기록한다.
필요 화살표는 실제 동작에 근거한 별도 주석으로만 추가하고 무주석 원본을 보존한다. 화살표가 없어도 주요 구조가 읽혀야 한다.

## 6. 실행 순서와 검토 게이트

### T0 — 입력·출처·기존 검증 확인

입력 .blend/② 결과/표현 참고 이미지의 해시, 실제 HEAD, 환경과 선택 상태를 기록한다.
Blender 버전·실행 경로·fps/fps_base·본편 카메라·렌더 영역·S5/S6 마커를 직접 확인한다.
기존 검증을 새 로그 경로에서 재현하고, 과거 통과 기록과 현재 실행 결과를 구분한다.
②의 필수 행동/연속성 실패가 재현되면 ③의 장식 작업으로 덮지 말고 해당 결함을 먼저 보고한다.

### T1 — 프레임 재선정과 구조 초안

기존 후보가 의미에 맞으면 재사용한다. 03/03A는 실제 상태를 다시 조사한다.
한 ID에 우선 후보 1개를 고른다. 선택의 차이가 중요한 경우에만 대안 1개를 추가한다.
번호를 바꾸기 위해 마스터를 수정하지 않는다. 선택 프레임은 엄격한 시간 순서와 위 역할 계약을 만족해야 한다.
같은 카메라의 원본 PNG, 하단 메모가 있는 초안, 전체 흐름의 연락판, 프레임 선택 이유를 제출한다.
별도 진단용 탑뷰는 대조 자료로만 두며 본편 콘티로 섞지 않는다.
여기서 사용자에게 프레임 선택·필요 수정·표현 방향을 묶어서 검토받는다. 기록된 선택은 다시 묻지 않는다.

### T2 — 표현 정리·원본 구조 대조

선택된 프레임에 흑백 러프 콘티 표현을 적용한다. 기준 스타일이 제공되어 있으면 먼저 확인한다.
무주석 원본 / 선화본 / 최종 주석본을 분리하고 출처 관계를 기록한다.
같은 영상 영역으로 정렬한 나란히 보기 또는 오버레이로 다음을 대조한다:
운전석·트레일러 연결·컨테이너 후면·문 상태·차륜 접지·도로 경계·도크 개구부·창고 개방면·입고 바닥.
픽셀 전체 일치 검사는 그림체 차이를 오류로 만들므로 구조 비교와 분리한다. 반대로 이미지 해시가 존재한다는 것만으로 구조 일치를 주장하지 않는다.
표현 단계에서 생긴 차이는 콘티만 수정한다. 정상적인 마스터를 생성 이미지에 맞춰 바꾸지 않는다.

### T3 — 필요한 경우에만 마스터 미세 조정

문제 처리 우선순위:
1. 잘못 고른 시점: 다른 실제 프레임으로 재선정.
2. 잘못된 메모/편집/선화: 콘티·주석만 수정.
3. 실제 본편의 가림·프레이밍 결함: 허용 범위에서 카메라/주시점/렌즈 미세 조정.
4. 차량·도크·동선·시간·핵심 행동 결함: ②의 제한적 재작업으로 분리하고 승인 전 변경 보류.

각 수정은 문제 ID, 기준 프레임과 영상 증거, 이유, 객체/채널/구간, 예상 회귀 범위를 먼저 기록한다.
③에서는 실제 연출상 결함을 고치기 위한 제한적인 카메라 수정만 허용한다. 단순 취향 변경은 사용자 선택 없이는 실행하지 않는다.
현재 ②의 F_lock=720, F_rejoin=948을 재확인하고 f720까지와 f948 이후의 본편 상태를 보호한다. 사이의 수정도 양끝 위치·회전·렌즈와 이동의 연속성을 유지한다.
720/948 바깥으로 수정이 필요하면 임의로 범위를 늘리지 않는다.
차량 동선, 정렬·문 개방·후진 시각, 전체 fps/길이, 지형·창고·도크·차체 비례는 기본 불변이다.
②의 경첩/문 하단/받침판·바퀴 간격/접지 보정 등 기존 승인 형상과 기능을 옛 콘티에 맞춰 되돌리지 않는다.
한 프레임만 좋은 위치로 바꾸지 말고 주변 프레임·서브프레임의 실제 이동과 가림을 다시 검사한다.

수정할 이유가 없으면 새 마스터를 편집·재저장하지 않는다. 최종 묶음에 원본의 바이트 동일 복사본을 두거나 해시로 같은 파일을 명시한다. 이름만 변경한 것을 새로운 동작 버전이라고 말하지 않는다.

### T4 — 최종 저장본에서 재추출·재검증

수정이 있으면 새 버전으로 저장하고 별도 프로세스에서 재개방한다.
최종 기준 파일을 고정한 뒤 최종 PNG·선화·콘티·연속 영상·대응표를 생성한다.
중간 .blend를 열어 둔 GUI에서 캡처한 화면을 최종 파일의 증거로 사용하지 않는다.
변경이 없는 결과를 재사용할 때는 원래 출처와 동등성 검증을 남긴다. 해시 칸만 새 값으로 바꾸지 않는다.
가장 단순한 권장안은 여섯 장과 경계 프리뷰를 최종 저장본에서 다시 출력하는 것이다.
마스터가 바뀌면 영향받은 프레임 선택·선화·주석·plan·영상·선택 기록을 재검토 대상으로 표시한다.
최종 승인 이후 같은 이름으로 파일을 덮어쓰지 않는다.

### T5 — 사용자 최종 확인·종료

기술 검사 통과와 사용자의 최종 콘티 승인을 분리한다.
검토 요청에는 전체 연락판, 개별 콘티, 원본 대조, 연속 프리뷰, 변경/유지 요약을 함께 제시한다.
승인 기록은 실제 사용자 응답의 출처·시각·선택 대상 버전/프레임으로 남긴다. 도구 실행 시각을 승인 시각으로 쓰지 않는다.
사용자가 승인하면 그 정확한 묶음을 고정한다. 답변이 아직 없으면 ‘최종 동기화 후보 / 사용자 승인 대기’로 제출한다.

## 7. 렌더 시점 출처와 프레임 대응표 — 이번 단계의 필수 구현

현재 package_evidence.py는 현재 .blend의 해시를 읽고 기존 main-frames PNG를 복사해 후보를 만든다. 부분 재실행 시 과거 PNG에 현재 해시가 붙는 것을 충분히 차단하는 구조는 아니다. 현재 산출물이 잘못됐다고 단정하지 말고, 이번 동기화 도구에서 이 위험을 막는다.

기존 코드를 단순 재실행해 역할이 잘못된 후보를 다시 만들지 않는다.
프레임 선택은 새 데이터 파일에서 관리하고, 같은 선택 데이터를 추출·편집·검증에서 사용한다.
렌더를 시작할 때 실제 읽은 .blend SHA-256, Scene, Camera, 프레임 범위, fps/fps_base,
렌더 설정·스크립트/설정 해시를 생성한 실행 ID와 함께 기록한다.
출력마다 실제 프레임·원본 PNG 해시를 묶고, 후처리는 그 기록을 입력으로 받아야 한다.
원본 출처가 없거나 현재 기준과 맞지 않는 파일은 거부하거나 ‘과거 자료’로 격리한다.
새 출력 폴더/실행 ID를 사용해 중간 실패 시 이전 PNG가 섞이지 않게 한다.

storyboard-manifest.json에 포함할 최소 항목:
- storyboard_id, 역할·행동 설명, candidate/selected/approved 상태.
- 기준 .blend 경로·SHA-256·실제 Scene/Camera, 실제 레포 HEAD.
- master_frame와 subframe, fps/fps_base, 영상 시작 프레임, 시각 기준.
- master_time_seconds와 preview_time_seconds. 프레임 0 기준인지 명시한다.
- 평가된 카메라 world 행렬·렌즈·shift, 차량/컨테이너/도크 상태 요약 또는 상태 파일 참조.
- 이미지 해상도·픽셀 종횡비·영상 영역·허용된 축소/여백 정보.
- raw_frame 경로/해시, render_record 경로/해시, 표현 처리 방식/설정.
- line_art·최종 패널 경로/해시와 각각의 부모 raw_frame 해시.
- 사용자 선택/승인 출처, 기존 보드의 keep/replace/retire 판단과 이유.

시각 계산은 저장된 fps/fps_base와 프레임 기준에서 계산한다. 기존 (frame-624)/12를 모든 결과에 하드코딩하지 않는다.
같은 파일명이라도 master hash·프레임·Camera가 다르면 다른 버전으로 취급한다.
자기 자신의 해시를 내부에 넣어 계산을 반복하지 않는다. 최종 hashes 목록은 자기 자신을 제외하고 외부 파일에서 관리한다.
스크립트·설정·참조가 다른 파일에 의존하면 경로와 해시를 기록하되 범용 의존성 관리 시스템을 새로 만들지 않는다.

## 8. 테스트·회귀 범위

새 도구에서 우선 확인할 실패 사례:
- S5-03A에 정렬·정지 프레임이 배정됨: 사건 상태 검사에서 거부.
- 원본/Camera/프레임 출처가 없는 PNG 또는 현재 기준과 해시 불일치: 거부.
- 최종 패널이 다른 원본 프레임을 가리키거나 파일이 누락됨: 거부.
- ID 중복, 시간 순서 역전, fps/preview 시작점 오류: 거부.
- 선택 후 입력 파일 또는 표현 파일 변경: 해당 선택을 재검토 상태로 표시.
- 동일 출력 폴더에 과거 파일이 남은 불완전 렌더: 현재 묶음으로 패키징 금지.

정지/이동/문/접안 상태는 메모 문자열을 읽어 판정하지 않는다. 실제 평가된 객체 상태와 주변 시간 샘플로 확인한다.
숫자 허용 오차는 현행 config와 검증 의미를 확인해 사용하고, 실패 후 느슨하게 바꾸지 않는다.

마스터 무수정:
입력/최종 파일의 바이트 동일성, 기존 검사 재현, 대표 상태·선화 구조·출처 일치를 확인한다.
새로운 정밀 물리 검증을 했다고 말하지 않는다.

카메라 수정:
기존 통합/마스터/바퀴 회귀를 유지하고, 변경구간과 접합부의 위치·회전·렌즈·주시점·속도·가림·충돌을 추가 검사한다.
카메라 광선/대표점의 화면 내 위치만으로 실제 가독성을 통과시키지 않는다. 렌더와 연속 재생을 함께 확인한다.
기존 객체·Action·Mesh·환경과 보호 구간을 비교하고, 변경한 카메라 가이드 등 허용된 차이만 명시한다.
본편에 선화 Scene/보조 카메라를 저장해 기존 단일 Scene·카메라 검사를 깨뜨리지 않는다.

검사 명령은 ② README와 실제 코드를 먼저 읽는다. 기존 스크립트에는 실행 위치·로그·sibling 모듈 의존성이 있으므로 새 어댑터/출력 폴더에서 실행한다. 원래 증거를 덮어쓰지 않는다.
render_review.py는 임시 World/Workbench 설정과 16:9 출력값을 적용하므로 현재 본편 비율/카메라와 비교하고 해당 설정을 렌더 기록에 남긴다. 그 임시 설정을 본편 파일에 저장하지 않는다.
② 통합 생성기·① 수정기를 재실행해 ③의 표현본을 만들지 않는다.

## 9. 수용 기준

AC-1 기준·승인 구분:
② 실제 입력/해시/선택 상태, 작업 HEAD와 환경이 기록된다. 과거 보고서의 통과와 이번 실행·승인을 구분한다.
검증: 입력 조사·해시·선택 기록·재현 결과.

AC-2 역할과 시간 순서:
01→02→03→03A→04→05가 실제 서로 다른 필요한 상태를 설명한다. 03A는 최종 정렬 전 선회 중이고 04는 문 고정 후 후진 전이다.
검증: 프레임 선택표·평가 상태·원본 스틸·주변 연속 프리뷰.

AC-3 구조 일치:
모든 콘티가 해당 원본의 차량·문·도크·도로·카메라 투영을 유지한다. 손그림 표현 때문에 새 공간/동작이 생기지 않는다.
검증: 영상 영역을 맞춘 원본/표현 대조와 핵심 구조별 시각 판정.

AC-4 표현·가독성:
가로형 흑백 러프 콘티, 일관된 테두리·하단 메모·읽히는 윤곽을 갖춘다. 메모·화살표가 주요 물체를 가리지 않는다. 선화 미완료는 별도로 표시한다.
검증: 개별 패널과 전체 연락판의 시각 검토, 사용자 표현 선택.

AC-5 최소 변경·보호:
문제 없으면 마스터 무수정. 수정 시 허용된 카메라 구간만 변경하고 기존 동작/형상/타이밍과 양쪽 경계를 보존한다.
검증: 입력 해시·diff/평가 서명·보호 구간 검사·기존 회귀.

AC-6 원테이크 유지:
S4 후반→S5 전체→S6 첫 입고로 이어지는 카메라·화물 관계가 유지된다. 새 컷·장면 재배치·숨긴 전환이 없다.
검증: 동일 본편 Camera의 원속도 연속 영상과 접합부 상태.

AC-7 최종 출처 동기화:
최종 패널·원본 PNG·선화·영상·manifest가 하나의 최종 마스터에 대응한다. 오래된 렌더의 해시 표기만 바꾸지 않는다.
검증: 렌더 시점 기록·산출물 해시·잘못된 출처 거부 테스트·재추출 결과.

AC-8 재현·제출·확정:
저장본을 새 프로세스에서 다시 열어 결과를 확인할 수 있고 최종 선택 기록이 실제 파일 버전과 연결된다.
검증: 재개방 명령/종료 코드·실제 영상 재생·선택 기록·산출물 목록.
사용자 승인이 아직 없으면 기술 동기화 완료와 별개로 최종 확정은 대기다.

필수 AC 실패/미검증을 완료로 표시하지 않는다. 정적 검사·자동 검사·실제 재생·사용자 연출 승인은 각각 보고한다.

위 경로는 새로 만드는 제안이며 이미 존재한다고 가정하지 않는다. 로컬 관례·gitignore에 맞춰 조정하고 실제 경로를 보고한다.
본문 콘티는 기본 6장이다. 이미 일치하는 기존 보드는 근거를 남겨 유지할 수 있다. 03A 통합/삭제나 전체 ID 개편은 자동 결정하지 않는다.
최종 .blend는 원본 보존 복사본 또는 검증된 수정본이다. 파일 복사만 했다면 그대로 밝힌다.

preview에는 기존 ②의 f624–948을 최소 비교 범위로 고려한다. f948에서 마스터를 수정했다면 그 이후 원본 재접속 확인에 필요한 여유 프레임도 포함한다. 검토 영상 때문에 S6 자체를 재설계하지 않는다.
최종 미디어는 같은 fps·원속도·시간 순서로 출력한다. 탑뷰는 보조 검토 자료다.
PNG/JSON/Markdown/MP4를 기본 산출물로 한다. PDF·PPT·웹사이트·전체 원테이크 재렌더는 이번 필수 범위가 아니다.

실제 재현 명령은 사용 중인 Blender/Python/인코더와 스크립트 인자를 확인한 뒤 README에 기록한다.
새 도구는 입력 .blend, Scene/Camera, 선택 JSON, 출력 폴더를 명시적으로 받고 입력/출력 동일 경로와 출처 불일치를 거부한다. 실패는 nonzero로 반환한다.
인코더/시각 검토 환경이 없으면 PNG 시퀀스와 미실행 사유를 제출하고 연속 검토 완료라고 말하지 않는다.
무관한 npm 빌드로 Blender 검증을 대신하지 않는다.

보고서:
변경 요약·파일 목록·diff/결과 해시, 유지/교체한 보드와 이유,
재선정 프레임·실제 역할, 마스터 수정 여부와 범위,
AC별 상태·증거·실행 명령·성공/실패,
기존/신규 실패·미실행 검증·출처 무효화/재추출 결과,
사용자 선택 상태·남은 위험·다음 작업을 적는다.
사용자에게 폴더 경로만 주지 말고 전체 연락판과 개별 패널·원본 대조·연속 영상을 실제로 열어 볼 수 있게 제공한다.

## 11. 중단 조건·공통 경계

필수 입력/버전/선택이 충돌하거나 실행 환경이 없으면 확인 범위와 미확인 사항을 보고한다.
프레임 재선정으로 해결되지 않는 행동 결함, 보호 구간 변경, 동선/형상/리타이밍 변경은 ②의 재작업으로 분리한다.
선화 정리 결과가 구조를 반복해서 바꾸면 생성 횟수를 늘리지 말고 실제 프레임 기반 방식으로 되돌린다. 원하는 표현 수준에 못 미치면 그 사실을 보고한다.
새 유료 서비스·외부 업로드·권한 변경·파괴적 작업이 필요하면 승인 전 중단한다.

테스트 삭제·비활성화·규칙 완화로 통과를 꾸미지 않는다.
비밀키·실제 개인정보를 코드·로그·샘플에 넣지 않는다.
기존 무관한 변경과 사용자의 저장/미저장 작업을 보존한다.
승인 없는 운영 데이터 변경·운영 배포·유료 호출·강제 push·무관한 변경 덮어쓰기를 금지한다.
라이브러리 추가는 이유·영향을 보고하고 설치·권한 정책을 따른다. gitignore 제외물을 강제로 추적하거나 git clean으로 지우지 않는다.

최종 판정은 단계에 맞춰 구분한다:
‘프레임/콘티 후보 작성 완료 — 사용자 선택 대기’
‘최종 동기화 검사 통과 — 사용자 최종 승인 대기’
‘③ 콘티 확정·동기화 완료 — 실제 승인 기록 있음’
‘재작업 필요 / 증거 부족’

③ 완료는 상세 자산·스타일프레임·최종 렌더·실차 안전성·웹 운영 공개 승인이 아니다.
