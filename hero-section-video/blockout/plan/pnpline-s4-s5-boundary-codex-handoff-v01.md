- F_boundary: S4 종료/S5 시작의 공통 경계.

두 끝 프레임을 독립적으로 맞추지 말고 하나의 연속 타임라인에서 수정한다.
프리뷰에는 변경 구간 양끝 바깥의 원본 동작도 포함해 접합부를 확인한다.
기본 fps·전체 길이·기존 이벤트 시각은 유지한다. 전 구간 리타이밍은 하지 않는다.

기본 수정 대상:
- 기존 본편 카메라의 위치·회전·주시점, 필요한 경우 제한된 렌즈 조정.
- 해당 구간의 카메라 경로 가이드와 검토 메타데이터.

카메라만으로 요구를 충족하면 차량 동작은 수정하지 않는다.
차량 출발의 작은 위치/방향/속도 보완이 불가피하면, 영향 근거와 대상 프레임을 기록하고 최소 범위로 조정한다.
컨테이너·트레일러·견인부·연결점의 상대 관계와 이전 인계 접촉은 함께 보존해야 한다.

큰 하역 위치 이동, 정지 차량의 임의 회전, S4 인양 동작 재설계,
도로/부두/창고 재배치, 차량 길이/축척 변경은 범위 밖이다.
필요하면 해당 수정은 멈추고 카메라 대안·영향·승인 필요 사항을 보고한다.

변경 구간 밖의 기존 키와 평가 결과를 유지한다.
특히 베지어 핸들·보간·constraint 변경으로 구간 밖 결과까지 바뀌지 않는지 검사한다.
기존 후속 카메라로 되돌아가려고 급회전·가속을 넣지 않는다.
최소 구간 내에서 자연스러운 재접속이 불가능하면 범위 확대를 요청하고,
잘린 프리뷰나 숨긴 전환으로 문제를 감추지 않는다.

## 6. 목표 화면과 동작

### S4 종료의 공통 화면

- 주인공은 차량과 그 위의 PNPLINE 컨테이너다. 차량을 반드시 화면 정중앙에 놓을 필요는 없다.
- 컨테이너 바닥과 차량 받침이 정상적으로 맞닿고 차량과 함께 고정되어 있다.
- 인양 장치는 컨테이너와 분리되어 있으며 차량 출발 공간을 침범하지 않는다.
- 선박은 같은 부두에 정박하고, 선박·부두 사이의 수면 경계가 구분된다.
- 선박/하역 구역은 화물이 온 장소로 배경에 남는다. 선박 전체를 담기 위해 차량을 작은 점으로 만들지 않는다.
- 차량의 진행 방향 앞에서 실제 빈 진입로가 기존 도로로 이어진다.
- 같은 물류센터가 그 도로의 목적지로 식별된다.
- 차량의 전면/후면·긴 측면·컨테이너 상단이 필요한 만큼 읽힌다.
- 목적지를 보여 주려고 건물을 옮기거나 비현실적인 초광각·거대한 줌아웃을 쓰지 않는다.

가시성은 대표점의 화면 내 위치만으로 합격시키지 않는다.
도로 연결과 건물 실루엣이 다른 물체에 가려지지 않고 실제 화면에서 식별되는지 본다.
화살표나 자막은 보조 설명일 뿐, 실제 통로와 목적지 노출을 대신할 수 없다.

### S5 시작·추적 합류

- 위 공통 상태에서 같은 차량이 천천히 앞으로 출발한다.
- 카메라는 기존 위치/주시 방향에서 같은 관찰 측면 위쪽의 추적으로 이어진다.
- 전후 프레임의 상태가 연속되어야 한다. 프레임이 달라져도 차량을 완전히 고정하라는 뜻은 아니다.
- 출발 시 차량이 가속하므로 속도 변화 자체는 허용하되 순간적인 속도/회전 도약은 피한다.
- 항구는 뒤로 멀어지고 도로와 목적지가 앞쪽에 남는다.
- 컨테이너 후면 문은 닫힌 상태를 유지한다. 선박은 재출항하지 않는다.
- 이번 프리뷰는 부두 출발 초반까지만 다룬다. 입고 마당 선회·도크 접안은 하지 않는다.

   원본을 새 Blender 프로세스에서 읽고, S4 후반~S5 초반의 기준 스틸/저해상도 프리뷰를 확보한다.
   현재 가시성·동작·구간 경계 오류를 프레임과 함께 기록한다.
   입력 해시, Scene/오브젝트/부모/Action/환경/카메라 상태를 기준 서명으로 보존한다.

2) 최소 수정
   카메라만으로 목표 경계 구도를 먼저 찾고, 그 구도가 S4 후반과 S5 출발로 연속되는지 확인한다.
   전환 구간 전체를 조정한다. 마지막 한 프레임에만 새로운 위치/회전을 넣지 않는다.
   기본 후보 1개를 제출한다. 뚜렷한 구도 상충이 있을 때만 대안 1개를 추가하며 선택은 사용자에게 남긴다.
   단순 탐색·제한된 범위 조정마다 승인을 반복 요청하지 않는다. 중단 조건에 해당할 때만 질문한다.

3) 자동 검사
   경계 상태, 접촉/분리, 출발 경로, 카메라 연속성, 범위 밖 보존을 검사한다.
   새 검사부터 통제된 실패 입력/기준 상태로 RED를 확인한다. 원본 파일을 훼손해 실패 사례를 만들지 않는다.
   관련 기존 회귀 검사를 실행하고 기존 실패와 신규 실패를 분리한다.
   구버전 전용 이름/버전 assertion이 v005에 맞지 않으면 불일치를 보고하고, 실제 v005에 맞는 의미 보존 검사를 추가한다.
   버전 불일치를 이유로 기존 안전/연속성 검사까지 일괄 무시하지 않는다.

4) 저장본 시각 검토
   작업본을 저장한 뒤 별도의 새 프로세스로 다시 열어 상태·검사를 재확인한다.
   동일한 파일에서 연속 카메라 프리뷰를 출력하고 1배속으로 직접 검토한다.
   확대·편집된 스틸만으로 연속성 합격을 선언하지 않는다.
   최종 정지 프레임뿐 아니라 안착/분리 후반, 공통 경계, 출발 중, 변경 구간 앞뒤를 캡처한다.

5) 인계
   공통 경계와 다음 단계가 이어받을 출발 초반 상태를 boundary-contract.json에 기록한다.
   .blend 해시, 프레임, fps, Scene/Camera/차량 ID, world/지역 좌표와 축,
   카메라 위치·회전·렌즈·주시점·속도, 차량 위치·방향·속도,
   컨테이너 상대 변환·지지 상태·문 상태, 인양 분리 상태, 선박 정박 상태를 포함한다.
   이 상태는 추후 S5 전체 통합의 입력이다. 테스트 파일의 같은 번호 프레임으로 교체하지 않는다.

## 8. 수용 기준과 검증 방법

AC-1 원본·범위 보존
원본 SHA-256이 불변이고, 새 작업본에서 허용 대상/구간 밖 기존 동작·환경이 유지된다.
→ 파일 해시 + 수정 전후 데이터/평가 상태 서명 + 기존 회귀 검사.
공유 데이터 변경, S1~S3·S4 전반·후속 S5/S6/S7의 신규 차이를 함께 확인한다.

AC-2 S4 종료 정보
차량/컨테이너, 배경 선박/하역 구역, 빈 진입로, 도로와 같은 물류센터가 같은 화면에서 읽힌다.
→ 경계 프레임 스틸 + 전후 영상의 시각 판정. 대표점 투영만으로 완료하지 않는다.

AC-3 인계 상태
컨테이너는 같은 차량에 안정적으로 실려 있고 인양 장치는 분리, 문은 닫힘, 선박은 정박한다.
→ 지지 상대 행렬·접촉/간격·문/선박 상태 + 렌더 검토.

AC-4 경계 연속성
S4 후반→S5 초반이 하나의 카메라·동일 차량으로 이어지고 순간이동·반전·컷·급격한 렌즈 변화가 없다.
→ 위치/회전/렌즈/주시점·속도/각속도 비교 + 1배속 영상.
카메라의 q와 -q 표현 차이를 물리적인 180도 회전으로 잘못 판정하지 않는다.

AC-5 실제 출발 가능성
차량 앞의 통로가 열려 있고, 견인부뿐 아니라 트레일러 전체가 시설과 충돌하지 않으며 접지/연결이 유지된다.
→ 바운딩 볼륨 등 명시한 충돌 근사 + 실제 동작 검토.
카메라도 기둥·선박·차량 등을 관통하지 않는다. 진단용 탑뷰는 필요할 때만 별도 출력한다.

AC-6 재개방·재현
같은 기준/config에서 수정이 재현되고, 저장본을 재개방한 결과가 검증 출력과 대응한다.
→ 새 프로세스 검사, 키/상태·대표 스틸 비교, 명령·종료 코드·환경 기록.
숨은 핸들러나 미저장 GUI 상태에 의존하지 않는다.

AC-7 다음 단계 전달
공통 경계·출발 초반 인계 상태와 미해결 사항이 기록되어 있다.
→ boundary-contract.json + report의 프레임 대응.
S5 테스트 이식, 최종 콘티 제작, 사용자 구도 승인은 완료 범위에서 제외한다.

수치 허용 오차는 마스터 스케일·fps·기존 검사와 근거를 확인해 실행 전 config에 기록한다.
관련 구간의 모든 정수 프레임을 검사하고, 경계/접촉/키 변화 근처는 서브프레임도 확인한다.
초기 0.25프레임 샘플 간격은 검토 제안이며 정밀 연속 충돌 보장을 뜻하지 않는다.
검사 방법·범위·누락을 명시하고, 실패 후 임계값을 느슨하게 만들어 통과시키지 않는다.

## 9. 제출물·재현 명령·보고

필수 제출:
- master-s4-s5-boundary-v001.blend: 원본의 다른 구간을 보존한 수정 작업본.
- S4 후반~S5 출발 초반의 단일 카메라 저해상도 MP4.
  인코더가 없으면 PNG 시퀀스와 재생 미검증 이유를 제출하고 영상 검토 완료로 표시하지 않는다.
- 같은 범위의 수정 전 프리뷰, 수정 전후 경계 스틸, 출발 초반 스틸.
- 재실행 가능한 최소 수정/검증/출력 스크립트와 config.
- baseline/after 보존 비교, validation 결과, boundary-contract.json.
- README.md, report.md, hashes.json 및 민감정보를 제거한 로그.

사선 프리뷰는 동일한 해상도·fps로 전후 비교한다.
기존 12fps/768×432는 저해상도 비교의 후보이며 실제 입력·출력 설정을 확인한다.
출력 영상에 새 컷이나 누락 프레임을 넣어 문제를 숨기지 않는다.
정지 캡처에 한해 Scene/프레임/기준 파일 식별용 메모를 표시해도 된다.

명령은 기존 README와 실제 설치 환경에서 확인한 것만 실행한다.
새 스크립트는 input/output/config/Scene을 명시적으로 받고,
입력과 출력이 같으면 거부하며 실패는 nonzero로 반환한다.
Blender/Python/인코더 절대 경로를 과거 사용자 경로로 하드코딩하지 않는다.
README에는 실제 실행한 생성·검증·재개방·렌더·인코딩 명령과 종료 코드를 남긴다.
웹사이트를 수정하지 않으므로 무관한 npm 빌드로 검증을 대신하지 않는다.

report에 포함:
- 실제 기준 HEAD/입력·결과 해시, 변경 파일 목록과 diff 또는 결과 커밋(만든 경우만).
- 변경한 객체·채널·프레임 범위와 변경 이유.
- AC별 상태·측정값·화면/영상 증거.
- 원본 대비 유지한 것과 의도적으로 달라진 것.
- 기존 실패/신규 실패, 미실행 검증과 이유.
- 원문/스토리보드/실제 공간의 상충과 남은 위험.
- 사용자에게 선택받을 대표 경계 프레임과 후보 영상.

## 10. 중단·완료 경계

다음이면 관련 작업을 중단하고 근거와 최소 대안을 보고한다.
- 필수 입력/Blender 실행/이미지 확인에 접근할 수 없거나 입력 버전이 충돌한다.
- 요구 구도를 위해 하역 동작·건물·도로·전체 스케일 또는 다른 구간을 크게 바꿔야 한다.
- 범위 안에서 기존 동작으로의 자연스러운 접합을 만들 수 없다.
- 원본이나 보호 구간이 변경됐거나 공유 데이터의 영향 범위를 알 수 없다.
- 새 유료 도구·외부 업로드·보안/권한 변경이 필요하다.

테스트 삭제·비활성화·규칙 완화로 통과를 꾸미지 않는다.
비밀키·실제 개인정보를 코드·로그·샘플에 넣지 않는다.
기존 무관한 변경을 보존한다.
승인 없는 운영 데이터 변경·운영 배포·유료 호출·강제 push·무관한 변경 덮어쓰기는 금지한다.
라이브러리 추가는 이유·영향을 보고하고 설치 권한/승인 정책을 따른다.
문제가 없는 범위 내 작은 조정은 이유를 기록하고 진행한다.

최종 판정:
‘① 단계 검토 후보 수용 가능 / 사용자 구도 선택 대기’
‘재작업 필요’
‘증거 부족으로 판정 보류’

필수 AC가 실패·미검증이면 수용 가능으로 표시하지 않는다.
① 단계 통과는 S5 전체 통합·최종 스토리보드·운영 공개 승인이 아니다.
