## 0. 목적·승인 경계·기준

이 지시서를 실행 요청으로 전달받으면, PNPLINE 원테이크 영상의 S1~S7을 하나의 고정된 미니어처 공간에서 연결하는 Blender 블록아웃을 제작하고 검증하라.

목표는 애셋의 외관 완성이나 최종 애니메이션 제작이 아니다. 단순한 형태와 최소 이동으로 다음을 확인하는 것이다.
“같은 컨테이너가 같은 선박에서 같은 입고 차량으로 인계되고, 같은 물류센터로 이동하며, 카메라는 관통·순간이동 없이 창고 작업과 별도 출고 차량의 배송 흐름까지 이어지는가?”

### 1.3 보조 입력과 조회 실패 처리

- 러프 스토리보드는 실제 이미지 파일·구간 ID·버전·선택 상태가 제공된 것만 참고한다. 이번 지시서는 텍스트와 애셋 목록 기반이며 개별 러프 이미지와의 시각적 일치를 검증한 문서가 아니다.
- 러프 이미지가 없어도 텍스트 기반 Master 후보 제작은 가능하다. 해당 구도는 “텍스트 기반 후보 / 보드 대조 미실시”로 기록한다. 없는 이미지를 보았다고 하지 않는다.
- 노션을 읽을 수 없으면 사용자가 제공한 N0~N7의 완전한 Markdown/텍스트 내보내기로 대조한다. 원문과 내보내기 모두 없거나 중요한 본문이 누락되면 제작을 중단하고 부족한 입력을 보고한다. 애셋 목록만으로 빈 연출을 만들어 채우지 않는다.
- ChatGPT의 프로젝트 소스·첨부 파일·연결 권한이 Codex에 자동 공유된다고 가정하지 않는다.
- 원문·목록·선택된 보드 사이의 충돌은 위치와 영향을 기록한다. 원문이 명시한 연속성에 맞지 않는 그림을 그대로 복제하지 않되, 승인된 행동을 임의로 바꾸지도 않는다.

### 1.4 레포·실행 환경 확인

먼저 현재 HEAD, 작업 트리의 기존 변경, 출력 경로와 적용되는 AGENTS.md를 확인한다.
작성 시 CONTEXT.md와 #61 본문·승인 댓글을 조회했다. 기준 커밋의 루트 AGENTS.md 조회는 404였으며, 하위 경로와 Codex 로컬 지침은 별도 확인 대상이다.

관련 문서 조사 후보:
- docs/wayfinder/pnpline-cn-map.md 및 해당 media/design tickets/
- docs/wayfinder/design-system-v1.md
- output/design-concept-v1/의 README와 토큰
- 이번 작업 경로에 적용되는 AGENTS.md와 기존 Blender 제작 규칙

후보 경로의 존재를 가정하지 않는다. 필요한 규칙·관련 승인 이력만 읽고 웹사이트 전체 조사로 확대하지 않는다.
Blender 버전, 사용 가능한 실행/제어 수단, 파일 저장, 프리뷰 출력·열람 가능성을 작은 시험으로 확인한다. bpy 스크립트 또는 이미 연결된 도구 중 가능한 최소 경로를 사용한다. 새 플러그인·브리지·유료 서비스 설치는 전제하지 않는다.

Blender 실행·저장·프리뷰 확인을 할 수 없으면 그 사실과 필요한 환경을 보고한다. 스크립트 작성만으로 블록아웃 제작·검증을 완료했다고 하지 않는다.

## 4. 공통 세계와 배치 규칙

다음은 N1~N7 및 A의 공간·동일성 조건을 구현하기 위한 Master 구조다.

1. 하나의 공통 세계 좌표계와 기준 단위를 사용한다. 첫 버전은 하나의 .blend 내 주 씬을 기준으로 하되 환경·애셋·경로·검토 보조물을 분리 관리한다. 하나의 메시로 합치라는 뜻이 아니다.
2. 중국/미국 지역의 로컬 기준축은 허용하되 모두 같은 세계 좌표로 환산되어야 한다. 곡면 위 지역마다 위쪽 방향이 달라지는 관계를 명시한다.
3. 지구·육지·부두·도로·건물은 재생 중 위치·크기·형태가 바뀌지 않는다. 처음부터 같은 세계에 존재하며 카메라 이동으로 발견된다.
4. 구형 세계의 반지름, 국가 간 배치, 거리와 상대 비례는 실제 지리 축척이 아니라 시험용 구성이다. 초기값·이유·변경 이력을 기록한다. 원문에 없는 미터값을 운영 사실처럼 쓰지 않는다.
5. 수정 버전 사이에서 반지름·배치·프록시 비례를 조정하는 것은 가능하다. 한 번의 재생 안에서 스케일을 바꾸거나, 다른 항구 세트로 바꾸거나, 지구를 돌려 목적지를 대신 이동시키는 것은 금지한다.
6. 선박은 해당 수면의 접선 방향으로 놓이고 경로에 따라 자세가 바뀌어야 한다. 선체를 휘거나 수면을 갑자기 평평하게 만들어 문제를 숨기지 않는다.
7. 선박 중심점만 확인하지 말고 선수·중앙·선미의 수면 관계를 함께 본다. 반지름과 선박 길이 조합 때문에 부유·과도한 파묻힘이 보이면 배치/비례 시험 단계로 돌아간다.
8. 중국 항구에는 선박의 한쪽 부두, 반대쪽 바다 카메라 공간, 선수 앞 출항 수로를 확보한다. 정확한 좌/우현 선택은 시험 배치로 기록하고 뒤 구간에서도 일관되게 유지한다.
9. 미국은 “접안부 → 하역 위치 → 연결 도로 → 입고 마당·도크 → 열린 창고 측면 → 출고 마당 → 공통 도로·분기”가 연결되어야 한다. S4에서 보인 물류센터가 S5~S7의 같은 건물이어야 한다.
10. 창고 관찰 순서는 “입고 대기 → 보관·피킹 → 포장 → 출고 대기 → 출고 차량”이다. 실제 작업 전체를 일직선 공정으로 단정하지 말고, 깊이와 작업 통로를 가진 배치에서 카메라가 이 순서로 관찰하게 한다.
11. 벽·지붕의 개방 부분은 처음부터 유지한다. 카메라가 접근할 때 숨기거나 투명화하지 않는다. 도시 건물은 배경으로 두고 주요 물류 흐름과 시야를 막지 않게 한다.

## 5. S1~S7 카메라·상태 연결 요구

아래는 원문에서 Master에 필요한 조건을 추린 것이다. 구간 번호는 컷 번호가 아니다.

### S1 — 컨테이너 선적 [N1, A-01·A-02·P-01]
시작: 중국 부두에 선박이 정박한다. A-01은 스프레더에 매달려 있으며, 카메라는 바다 쪽 사선에서 긴 측면·끝면과 아래 적재 위치를 함께 본다.
행동: 수평 하강 → 감속·안착 → 스프레더 분리·상승. 컨테이너를 임의 회전·확대하지 않는다.
카메라: 하강을 따라가다가 안착을 계기로 후퇴를 시작한다. 선박 전체·도시 전경 공개는 다음 구간에 남긴다.
종료/인계: A-01은 같은 적재 위치에 있고 선박은 정박 중이다. 인양 장치는 올라가며 카메라는 후퇴 중이다. S2가 이 상태를 이어받는다.

### S2 — 중국 항구와 출항 [N2, E-03·E-04]
행동: 인양 장비가 출항을 방해하지 않는 상태로 물러난 뒤 선박이 부두와 간격을 확보하고 수로로 전진한다.
카메라: 후퇴에 상승을 더해 적재열 → 선박 → 부두·크레인 → 야드·도로 → 도시를 드러낸다. 같은 바다 쪽 측면에서 선미 방향으로 넓게 이동한 뒤 후방 사선 추적으로 연결한다.
금지: 와이드 화면에서 후방 화면으로 카메라 재설정, 선박 관통, 도시를 계속 보이게 하려는 지형 재배치.
종료/인계: 같은 선박·컨테이너가 전진하고 카메라는 높은 후방 사선에 있다. 곡률은 예고되지만 지구 공개는 S3에서 이어진다. 계류줄은 필수가 아니며 표현한다면 출항 전에 해제되어야 한다.

### S3 — 미니어처 지구 항해 [N3, E-01·E-02]
카메라: 후방 추적을 유지하며 거리를 넓혀 구형 외곽/곡률을 읽히게 한다. 배가 점으로 작아지도록 물러나지 않는다.
행동: 같은 선박이 곡면 위를 이동한다. 지구는 고정되고 선박의 형상·크기·적재 위치도 유지된다.
접근: 선박 앞 목적지인 미국 해안을 먼저 보여 준다. 이후 같은 선측에서 후방 사선 → 측면 → 선수 옆 → 전방 사선으로 앞질러 간다.
종료/인계: 카메라는 배를 바라보면서 항구 쪽으로 계속 이동한다. 선박은 아직 접근 중이며 접안·하역하지 않는다. 전방 사선에서는 배 뒤로 지나온 바다가 보이고 미국 항구가 시야 밖에 있을 수도 있다. 이를 오류로 보고 항구를 옮기지 않는다.

### S4 — 미국 입항과 하역 [N4, E-05~E-08·P-02]
카메라: S3의 전방 사선에서 부두 쪽으로 비스듬히 물러나며 상승한다. 접안 방향 → 크레인·접안부 → 야드 → 연결 도로 → 물류센터 → 도시를 드러낸다.
행동: 선박 감속·접안·정지 후 A-01을 들어 올려 대기 중인 A-03에 내려놓고 인양 장치를 분리한다.
시선 인계: 선박+컨테이너 → 컨테이너+하역 위치 → 컨테이너+입고 차량이 잠시 같은 화면에 읽히도록 한다.
종료/인계: A-01은 A-03 위에 고정되고 차량은 연결 도로 방향으로 출발 준비 상태다. 카메라는 부두 측면 사선에 있으며 선박은 뒤쪽 부두에 남는다. 본격적인 차량 주행은 S5다.

### S5 — 물류센터로 이동 [N5, A-03·E-07~E-09]
행동: 부두 출발 → 완만한 도로 주행 → 마당 접근·감속 → 방향 정렬 → 정지·후면 문 개방 및 측면 고정 → 짧은 후진 → 도크 정지.
카메라: 차량의 같은 측면 위쪽에서 동행한다. 마당에서는 차량의 후진을 따라 왕복하지 않고 바깥쪽 경로를 따라 도크와 창고 개방면으로 이어진다.
핵심 검증: 최종 정렬 시 컨테이너 후면이 목표 도크를 향한다. 후면축과 도크 진입축이 맞아 그 자세에서 짧게 후진하면 도착해야 한다. 화살표만 도크를 향하고 차량은 다른 방향을 보는 상태는 실패다.
종료/인계: A-03과 A-01은 도크에 정지한다. 후면은 열려 있고 내부 화물은 남아 있다. 차량·열린 후면·입고 구역이 함께 보이며 카메라는 개방면 쪽으로 이동 중이다. 컨테이너를 차량에서 내리지 않는다.

### S6 — 물류센터 처리 [N6, W-01~W-10·CH-01·A-04]
관찰: 열린 컨테이너와 도크 연결 → 새 화물의 입고 대기 → 별도 화물의 보관 → 피킹 → 이미 진행 중인 포장 → 출고 대기·상차.
동일성: 새로 입고한 팔레트는 입고 위치에 남는다. 그 팔레트나 방금 피킹한 상품이 즉시 모든 작업을 마치는 연출로 바꾸지 않는다.
카메라: 처음부터 열린 측면 바깥의 여유 공간을 따라 진행한다. 랙·기둥을 관통하지 않고, 마지막에는 출고 마당 쪽으로 경로를 넓힌다.
Master 수준: 작업 위치·점유 부피·접근/이송 통로와 시선 인계를 검증한다. 필요한 팔레트·운반 수단의 단순 이동은 포함하되 손동작·봉함의 완성은 요구하지 않는다. 미구현 세부 행동은 마커/주석으로 표시하고, 박스가 저절로 완성되는 가짜 동작으로 대체하지 않는다.
종료/인계: A-04는 일부 상품과 마지막 상차를 받은 출발 준비 상태, 문 닫힘, 작업자·카트는 경로 밖이다. A-04는 S6 끝까지 정지한다. A-01·A-03은 입고 측에 남고 보조 출고 차량도 미리 대기한다.

### S7 — 미국 각지 배송 [N7, A-04·A-05·E-10~E-12]
행동: 주요 출고 차량 출발 → 마당·공통 도로 진입 → 보조 차량 시간차 출발 → 서로 다른 분기 경로로 이동.
카메라: 주요 차량의 바깥 측면 위쪽에서 시작해, 출발을 확인한 뒤 도로 바깥쪽으로 멀어지며 상승한다. 중심을 차량 → 차량과 분기 → 물류센터와 배송 흐름으로 넓힌다.
종료: 물류센터와 도로·차량의 관계가 읽히는 높은 사선 구도. 차량이 점이 되거나 다시 지구 전체까지 물러나지 않는다. 차량들이 동시에 정지할 필요는 없으며 마지막 정지 프레임도 의미가 읽혀야 한다.
금지: 차량의 복제·순간 생성, 입고 차량의 출고 차량 변신, 실제 배송망 지도·고객 문 앞 장면·중국으로 돌아가는 루프.

## 6. 최소 동작과 기록 방식 [이번 작업 설계]

- 처음부터 S1~S7을 가로지르는 전체 러프 경로를 만든다. S1을 정교하게 완성한 뒤 S2를 시작하는 방식으로 진행하지 않는다.
- 본편용 카메라는 하나의 연속 타임라인에서 평가한다. 검토용 탑뷰·사선 카메라는 별도 허용하지만 본편에서 카메라 컷으로 연결하지 않는다.
- 카메라 위치뿐 아니라 시선 목표·회전·롤·렌즈/화각의 연결도 확인한다. 구간마다 독립적인 시작/정지 보간을 적용해 경계에서 불필요하게 멈추지 않게 한다.
- FPS·구간 프레임 수·렌즈·화면 비율·검토 해상도는 시험 설정으로 선택하고 기록한다. 원문에 없는 최종 초수를 확정하거나 기존 5~8초 생성 클립 규칙을 가져오지 않는다.
- 공간 검토용 경로와 본편의 이동 경로를 구분한다. 가이드 선과 ID 라벨은 검토 화면에서만 사용한다.
- A-01의 지지 대상이 크레인→선박→미국 크레인→차량으로 바뀔 때, 실제 평가 위치·회전이 튀지 않는지 확인한다. 숨김/복제 전환으로 인계를 꾸미지 않는다.
- A-03은 운전석·트레일러의 연결점을 유지하며 방향을 바꾸게 한다. 전체 차량을 한 점에서 돌리거나 옆으로 미끄러뜨려 마당 공간이 충분하다고 판정하지 않는다.
- S5는 진입·선회 중·정렬 완료·문 개방·접안 상태를 같은 배치에서 비교한다. 차량의 점유 궤적, 문이 움직일 공간, 카메라 경로가 충돌하지 않는지 확인한다. 실제 차량의 정밀 동역학·안전 인증 검증과는 구분한다.

구간 경계는 B12, B23, B34, B45, B56, B67로 관리한다. 한 경계에는 하나의 공통 상태를 사용하며 양쪽 구간에 독립적인 복사 상태를 두지 않는다.
최종 .blend의 평가 상태에서 다음을 추출한다.
- 경계 ID, 프레임·시간, 카메라 world 위치·방향·시선 목표·렌즈/화각.
- 경계 직전·직후 이동 방향과 속도/회전 변화.
- 관련 애셋 instance_id, world 변환, 지지/연결 대상, 문 상태, 이동/정지 상태.
- 다음 구간의 관찰 대상, 해당 프리뷰/스틸 파일.

추출 데이터는 “의도한 값”을 수동으로 적는 것이 아니라 실제 씬 상태와 일치해야 한다.

## 7. 제작 순서와 단계별 검증

M0 — 입력·환경·기준 기록
필수 원문과 목록, 레포 기준, 기존 변경, 실행 환경을 확인한다. 충돌·미결·이번 시험값을 기록하고 저장/프리뷰 최소 시험을 한다.
검증: 입력 누락과 환경 실패가 없는지, 기존 사용자 파일이 보존되는지 확인한다.

M1 — 세계 배치와 전체 경로 초벌
지구·양국 환경·미국 물류 연결을 단순 형태로 배치한다. 핵심 프록시와 S1~S7 관찰 지점을 함께 두고 첫 연속 카메라 프리뷰를 만든다.
검증: 전체가 한 세계인지, 서로 다른 세트의 정지 화면을 연결한 결과가 아닌지 확인한다. 이 단계에서 실패한 경로를 발견해도 숨기지 않는다.

M2 — 두 핵심 공간 문제 검증
(1) S2→S3→S4: 곡률과 선박 크기, 접촉, 같은 선측 추월, 미국 해안 발견과 접안부 접근.
(2) S4→S5→S6: 하역 차량 위치, 도로 연결, 트럭 선회·후진, 문·도크·개방면, 카메라 통과 공간.
검증: 같은 Master 배치에서 동작 프리뷰와 탑뷰/측면을 비교한다. 수정한 반지름·도로·창고 배치가 앞뒤 구간에 미치는 영향을 재검토한다.

M3 — 전체 운송·시선 인계 연결
선적·하역의 단순 인계, 창고의 작업 구역 관찰, 별도 출고 차량과 분산 경로를 전체 타임라인에 연결한다. 상세 작업 연기는 추가하지 않는다.
검증: 화물과 차량의 동일성, 경계 상태, 각 인계에서 이전/다음 대상의 가독성을 확인한다.

M4 — 최소 수정·회귀 검증·인계
전체를 다시 재생하고 경계·추월·문 개방·후진·창고 출구를 집중 확인한다. 최종 .blend에서 상태 기록과 화면 증거를 다시 생성한다. 파일을 닫았다가 재개방해 재현성을 확인한다.
검증: 아래 AC별 근거와 미검증 사항을 제출한다. 상세 구간 제작으로 자동 진행하지 않는다.

## 8. 검증 방법과 수용 기준

공통 검증 방법:
- 명령·스크립트는 실제 환경에서 존재와 버전을 확인한 뒤 실행한다. 기존 테스트 체계가 없으면 그 사실을 보고하고 이번 씬용 최소 검증 수단을 마련한다.
- 생성/검증 스크립트를 작성하면 경로 누락·동일 ID 오류·경계 단절 같은 실패를 먼저 탐지하는 검사부터 만들고 최소 구현 후 재검사한다.
- 전 프레임의 카메라/핵심 이동체 상태를 확인하고, 인계·선회·후진·근접 구간은 필요에 따라 서브프레임이나 점유 궤적 검사로 보강한다.
- 위치 샘플·바운딩 박스 검사를 정밀 연속 충돌 검증이나 실제 물류 설비 안전 검증이라고 과장하지 않는다. 검사 해상도·허용 오차·방법의 한계를 기록한다.
- 수면에 잠기는 선체 부분, 바퀴와 도로, 적재 접촉 등 의도된 접촉과 불필요한 관통을 구분한다. 넓은 예외 처리로 오류를 숨기지 않는다.
- 실제 프리뷰 재생을 보고 구도·시선·급회전·프레이밍을 검토한다. 상태표만으로 가독성을 통과시키거나 정지 스틸만으로 연속성을 통과시키지 않는다.

AC-1 — 입력 추적
조건: N0~N7, A, 실제 참고 보드의 출처·버전·조회 범위가 기록되고 누락/충돌/가정이 구분된다.
검증: 입력 기록과 원문 대조. 본문 누락이 있으면 필수 입력 미충족이다.

AC-2 — 고정된 통합 세계
조건: 지구·양국 항구·도로·물류센터·분기 도로가 같은 좌표계에 존재하며 재생 중 세트 교체·형태/스케일 변경이 없다.
검증: 세계 사선뷰, 환경 변환/형상 상태 검사, 전체 프리뷰.

AC-3 — 최소 애셋과 동일성
조건: 목록의 각 ID가 프록시·영역·가이드·보류 중 하나로 대응된다. A-01·A-02·A-03은 동일 개체이고 A-04·A-05는 출고 개체로 구분된다. 이동 부품과 반복 요소가 수정 가능하다.
검증: 애셋 대응표, 씬 구조, 타임라인상의 개체/지지 상태 검사.

AC-4 — 연속 카메라와 여섯 경계
조건: S1~S7이 한 본편 카메라로 이어지고 B12~B67에 위치·방향·화각의 순간 변경, 비의도적 정지, 카메라 컷이 없다.
검증: 경계 전후 상태 데이터와 연속 재생. 경계 스틸만으로 통과 처리하지 않는다.

AC-5 — 곡면 항해와 추월
조건: 같은 선박이 형상·크기를 유지하며 수면을 따라 이동하고, 목적지 확인 후 같은 선측을 지나 전방 사선으로 카메라가 이동한다. 배가 점처럼 사라지거나 화면이 급격히 뒤집히지 않는다.
검증: S2~S4 프리뷰, 선수·중앙·선미와 수면 관계, 카메라/선박 경로의 사선뷰.

AC-6 — 선적·하역 인계의 공간 성립
조건: 스프레더·컨테이너·적재면·차량 위치가 맞고, 인계에서 화물이 뜨거나 순간이동하지 않는다. S4에서 다음 도로와 물류센터를 목적지로 읽을 수 있다.
검증: S1/S4 러프 동작, 지지 대상 전환 전후 상태, 인계 관찰 프레임. 상세 장치 작동 검증은 별도로 남긴다.

AC-7 — 차량·도크·카메라 연결
조건: 같은 A-03이 마당에서 정렬하고, 후면이 도크를 향한 상태에서 문을 열어 고정한 뒤 짧게 후진한다. 도크·개방면 위치를 바꾸지 않고 카메라도 관통 없이 S6로 이어진다.
검증: 같은 프레임의 탑뷰·본편뷰, 차량 점유 궤적/연결점/후면축, 문 공간, 도크 바닥 연결, S5→S6 프리뷰.

AC-8 — 창고의 관찰 순서와 화물 구분
조건: 입고·보관·피킹·포장·출고 구역이 연속적으로 관찰되고 통로가 확보된다. 입고 팔레트와 후속 작업 화물이 구분되고 상세 미구현 행동이 표시된다.
검증: 창고 배치도와 S6 프리뷰, 개체 상태·보강 목록. 미구현 손동작·포장을 완료라고 보고하지 않는다.

AC-9 — 출고·분산·종료
조건: 주요 출고 차량은 S6 끝까지 정지하고 S7에서 출발한다. 보조 차량은 미리 배치된 위치에서 움직인다. 마지막에 물류센터와 분산 흐름이 읽히며 중국 복귀 루프가 없다.
검증: S6→S7 프리뷰, 차량별 대기·출발·경로 기록, 마지막 프레임.

AC-10 — 재현 가능한 인계와 범위 준수
조건: 최종 .blend를 재개방해 같은 프리뷰와 경계 상태를 확인할 수 있고, 산출물·데이터·보고서가 같은 버전을 가리킨다. 금지된 외부 변경·생성·공개가 없다.
검증: 재개방/재출력, 파일 목록과 해시, 실행 로그·diff 자기 검토. 필수 AC 실패·미검증이면 완료 판정하지 않는다.

## 9. 산출물 [경로·파일명은 신규 작업용 제안]

기존 파일과 충돌하지 않는 로컬 작업 폴더를 정하고 최종 경로를 보고한다. 아래 구성은 제안이며 현재 레포에 존재한다고 가정하지 않는다.

blockout-master-v001/
  master-v001.blend
  manifest.json
  boundary-states.csv
  report.md
  preview/master-v001.mp4
  review/
  scripts/                 # 스크립트 방식을 사용한 경우

필수 내용:
- master-v001.blend: 편집 가능한 환경·애셋·경로·단일 본편 카메라·S1~S7 마커.
- manifest.json: 입력 출처/버전, 레포 기준, 실행 환경, 단위·지구 반지름·비례·배치·FPS·렌즈·화면 설정, 애셋 ID와 씬 개체 대응, 임시 선택·보류 항목.
- boundary-states.csv: 최종 씬에서 추출한 B12~B67 상태와 직전·직후 검사 정보. 복잡한 상태는 같은 의미의 JSON으로 바꿔도 되며 이유와 위치를 기록한다.
- 연속 프리뷰: S1~S7 전체를 잇는 검토 영상. MP4를 만들 수 없으면 실제 재생 가능한 동등 형식과 이유를 제시한다. 스틸 모음으로 대체하지 않는다.
- review/: 전체 세계 사선 배치, 중국 출항 배치, 미국 항구~출고 배치, S5 마당 탑뷰/측면, 주요 관찰 프레임과 여섯 경계 전후. 모두 같은 Master에서 출력하고 구간·프레임·버전을 식별할 수 있게 한다.
- report.md: AC별 판정·증거, 시험값과 변경 이유, 입력 충돌, 실패/미검증, 후속 구간 작업의 시작 조건.
- 사용한 생성/검증 스크립트와 재실행 방법. 직접 편집했다면 그 사실과 편집 범위를 기록하고 .blend와 스크립트 중 어느 것이 최종 원본인지 명확히 한다.

가이드가 없는 본편 프리뷰와 ID·경로를 확인할 검토 화면을 구분한다. 강한 심도·모션블러·안개·화려한 재질로 오류를 가리지 않는다.
모바일은 실제 사용 비율이 제공된 경우 대표 구도 위험만 점검한다. 미제공이면 미검증으로 남기고 중앙 크롭만으로 모바일 적합 판정을 내리지 않는다.
중국어 카피·CTA는 영상에 굽지 않는다. 최종 구도의 여유 영역은 후보로 표시하며 실제 웹 레이아웃 대조는 별도 검증이다.

## 10. 중단 조건·보존·보안

- 필수 원문/목록 누락, 접근 실패, 핵심 연출 충돌은 해당 제작을 멈추고 근거·영향·대안을 보고한다.
- 현재의 고정 세계·선박 비례·카메라 조건이 양립하지 않으면 실패 화면과 시험값을 제출한다. 숨긴 컷, 순간이동, 스케일 애니메이션을 몰래 도입하지 않는다.
- 지구 반지름·배치·렌즈·시험 타이밍처럼 이번 범위의 잠정값 조정은 이유를 남기고 진행한다. 단계 삭제, 핵심 행동 변경, 별도 세계/실시간 3D로의 전환은 승인 없이 하지 않는다.
- 테스트 삭제·비활성화·규칙 완화로 통과를 꾸미지 않는다.
- 비밀키·실제 개인정보를 코드·로그·샘플에 넣지 않는다.
- 기존 무관한 변경을 보존한다. 사용자 .blend를 초기화하거나 전체 씬을 삭제·덮어쓰지 않는다. 재실행은 새 출력이나 이번 작업이 소유한 범위에 한정한다.
- 승인 없는 운영 데이터 변경·운영 배포·유료 호출·강제 푸시·무관한 변경 덮어쓰기를 금지한다.
- 이 작업의 기본 종료는 로컬 산출물과 보고다. 커밋·push·PR 생성/병합·노션/이슈 수정은 별도 요청 없이는 실행하지 않는다.
- 라이브러리 추가는 이유·영향을 보고한다. 권한 확대·설치·외부 전송·비용이 발생하는 변경은 먼저 승인을 받는다.

## 11. 결과 보고와 다음 구간 인계

보고 순서:
1. 판정: 수용 가능 / 재작업 필요 / 증거 부족으로 판정 보류. 필수 AC가 남으면 완료라고 하지 않는다.
2. 기준 브랜치·HEAD, 결과 diff 또는 파일 해시, 실제 저장 경로, 변경/생성 파일.
3. AC별 상태와 해당 영상 구간·스틸·검사 로그. 실행한 검증과 제출 증거만 확인한 검증을 구분한다.
4. 실제 실행 명령·환경·성공/실패, 기존 실패와 신규 실패, 미실행 검증과 이유.
5. 원문/승인안 차이, 설계 이탈, 시험값 변경, 남은 위험·미결·후속 작업.

후속 S1~S7 작업에는 이 Master 버전, 공통 배치·애셋 ID, 해당 구간의 진입/종료 경계 상태를 입력으로 넘긴다. 구간별로 세계와 공유 애셋을 다시 만들지 않는다. 경계나 공유 배치를 바꾸면 영향받는 다른 구간과 전체 카메라를 재검증한다.

## 12. 스킬 사용

Codex 환경의 실제 카탈로그와 지침을 먼저 확인한다.
- 계획 실행과 단계별 확인: executing-plans 계열이 있으면 활용한다.
- 생성/검증 스크립트: test-driven-development를 적용 가능한 범위에 사용한다.
- 동작/검사 실패: systematic-debugging을 사용해 원인과 재현을 먼저 기록한다.
- 최종 보고: verification-before-completion에 따라 실제 실행 증거를 확인한다.
- Blender 제어·프리뷰 관련 스킬은 설명과 가용성을 확인한 것만 사용한다. 설치된 것으로 추정하지 않는다.

스킬은 이 지시서의 원문 조건·수용 기준·보안·승인 경계를 대체하지 않는다. 공유 Master .blend를 여러 작업자가 동시에 수정하도록 분산하지 않는다.

이제 입력·환경·기준을 확인하고, 허용된 로컬 범위 안에서 M0~M4를 수행하라. 중단 조건을 만났다면 진행한 범위와 필요한 결정을 근거와 함께 보고하라.
