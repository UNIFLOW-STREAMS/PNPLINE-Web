# PNPLINE 미국 미니어처 도시 — Codex 구현 프롬프트 v0.2

작성 기준: 2026-10-29. 별도 후보 파일에서 구현·검증한다. 운영 공개나 현재 마스터 교체 작업이 아니다.

## 1. 목적과 승인 범위

레포: https://github.com/UNIFLOW-STREAMS/PNPLINE-Web

첨부된 미국 미니어처 도시 콘셉트를 현재 채택된 Blender 장면의 미국 지역에 구현하라. 단순한 랜드마크 프록시가 아니라, 콘셉트의 도시 구획·랜드마크·높낮이·밀도·항만·도로·물류시설과 USA/별 장식이 함께 읽히는 편집 가능한 3D 공간이 목표다.

사용자가 명시한 디자인 변경은 자유의 여신상을 콘셉트보다 더 크게 만들고 선박 진입 때 잘 보이도록 배치하는 것이다. 나머지 디자인을 임의로 단순화·재디자인하지 않는다.

다음 두 조건은 동시에 충족해야 한다.
- 콘셉트의 구성·디자인·상대 배치·밀도를 최대한 충실하게 반영한다.
- 현재 채택된 카메라·항로·하역·차량·창고 동작과 연속된 구형 세계를 보존한다.

충돌하면 어느 한쪽을 몰래 바꾸지 않는다. 범위 안의 배치 대안을 검토하고, 핵심 변경이 필요한 부분만 근거와 함께 보고한다. 이미 결정된 작업을 다시 브레인스토밍하거나 매 단계 반복 승인받지 않는다.

## 4. 디자인 구현 명세

공통 원칙: 참조 조감도의 화면 좌표를 현재 카메라에 억지로 복사하지 않는다. 도시의 전후·좌우 구획과 랜드마크 관계를 읽어 기존 미국 지역의 좌표계 안에 배치한다. 개별 건물보다 구역 전체를 정렬·회전·등비 조정하는 방법을 우선하되 US_FRAME과 기능 동선은 바꾸지 않는다.

D01 — USA 입체 문자
- U–S–A를 각각 선택/편집 가능한 실제 입체 형상으로 만든다.
- 짙은 네이비 전면, 밝은 은색/백색 외곽과 측면, 두께·베벨·곡선 비례를 참고 이미지에 맞춘다.
- 후면의 거대한 문자 앞에 스카이라인이 겹치는 관계를 유지한다.
- 평면 자막/빌보드/텍스처 한 장으로 대체하지 않는다.
- 폰트가 정확히 확인되지 않으면 근사와 차이를 기록한다. 기본 폰트 글자만 세워 놓고 디자인 일치로 처리하지 않는다. 필요하면 외곽을 직접 조정한다.
- 표시 형상은 외부 폰트 없이 재개방 가능하게 보존하며 폰트 파일을 재배포하지 않는다.

D02 — 별 장식
- 첨부 이미지에서 읽히는 왼쪽 5개·오른쪽 5개, 총 10개의 오각별을 개별 두께 있는 3D 오브젝트로 구현한다.
- 흰색/밝은 은색, 크기 차이, 높낮이, 문자 양옆에 흩어진 리듬을 유지한다.
- 도시 지역에 고정하고 카메라 추종·애니메이션·표시 토글을 사용하지 않는다.
- 공중 장식에 이미지에 없는 지지 기둥을 만들지 않는다. 별을 생략하거나 별무늬 텍스처로 바꾸지 않는다.

D03 — 자유의 여신상
- 녹청색 로브, 횃불 든 팔과 불꽃, 왕관, 반대팔의 책판, 몸체·기단·작은 섬의 조합을 식별 가능하게 만든다. 단순 사람 캡슐/녹색 기둥으로 대체하지 않는다.
- 콘셉트의 항구 입구 바다 쪽 상징물이라는 관계를 유지하되, 실제 선박 접근 시 잘 보이는 쪽으로 정적 위치·방향을 조정한다.
- 동상 본체를 콘셉트 대비 더 크게 만든다. 기단만 높이거나 카메라 줌으로 커 보이게 하는 것은 불충족이다.
- 콘셉트에 실제 미터 치수가 없으므로 도시의 대표 건물/영역과 정규화한 참조 비율을 먼저 기록한다. 그 비율에 맞춘 기준안과 확대한 선택안의 높이·비율·배율을 비교해 남긴다.
- 초기 확대 배율은 구현 가정으로 설정하고 검토한다. 임의 배율을 사용자가 승인한 값이나 미술 합격 기준으로 쓰지 않는다. 전체 비례를 유지하며 확대한다.
- 선박 통로 밖에서 횃불·왕관·몸체 윤곽이 크레인/USA/고층군에 계속 가려지지 않도록 위치와 배경 간격을 잡는다.
- 조감도에서 크게 보이는 것만으로 통과시키지 않는다. 실제 입항 카메라로 검증한다.

D04 — 고밀도 스카이라인
- 중앙의 높고 층단진 밝은 타워, 오른쪽의 가늘고 높은 첨탑형 유리 타워, 그 사이 밀집 건축군의 높낮이·폭·실루엣을 반영한다.
- 뒤 고층 → 앞 중저층으로 이어지는 높이 변화와 좁은 간격을 유지한다.
- 몇 개의 동일 상자를 넓게 띄운 generic skyline으로 단순화하지 않는다.
- 재사용 모듈/인스턴스는 허용하지만 구획·밀도·외곽선·대표 입면은 구분한다.

D05 — 우측 공공건축·교량·녹지
- 밝은 돔과 좌우 날개가 있는 공공건축, 전면 녹지·계단·도로를 반영한다.
- 오른쪽 아래의 붉은 현수교, 수면, 언덕·수목의 묶음을 유지한다. 다른 다리 디자인으로 임의 치환하지 않는다.
- 현수교를 본선 입항 통로 위에 새로 걸치거나 차량 경로를 바꾸지 않는다. 숨은 구조는 필요한 만큼만 설계해 가정으로 남긴다.

D06 — 전면 도심·도로·물류 구역
- 석조 중저층 블록, 반복 창호·코니스, 도로와 소형 노란 차량, 전면/우측 창고·트럭·컨테이너 야드의 배치 질서를 재현한다.
- 참조에서 보이는 철도/운송 설비 형태도 대응 목록에 포함하되 기존 움직이는 트럭 경로를 가로막지 않는다.
- 창고를 콘셉트처럼 보이게 만들려고 현재 실제 작업 창고와 도크를 폐기하거나 같은 위치에 중복 건물을 세우지 않는다.
- 기존 기능 건물의 외관 보강 또는 기능 동선을 피한 배경 구역 대응을 먼저 검토한다. 중요한 구역 관계가 달라져야 하면 차이와 영향을 보고한다.

D07 — 항만·선박
- 해측 부두, 여러 청색·백색 크레인, 밀집 컨테이너 야드와 창고/도심 연결을 반영한다. 참조의 크레인 군집과 현재 기능 크레인의 대응을 기록한다.
- 실제 하역 크레인/리그를 우선 재사용한다. 외관 메시 변경은 실제 트롤리·케이블·화물 지지점과 양립해야 한다.
- 장식용 크레인은 기능 장비와 구별하고 선박·인양·카메라 통로를 침범하지 않는다.
- 중국에서 온 기존 PNPLINE 선박을 그대로 사용한다. 콘셉트 선박을 별도로 복제하거나 다른 선박 외형으로 교체하지 않는다. 콘셉트는 항만과 선박의 관계 참고다.
- 소형 예인선·차량은 필요할 때 저비용 정적 장식으로 구현하되 본선 통로/동작과 구분한다. 새 군중·운송 애니메이션은 제외한다.

D08 — 지형·수면·재질
- 사각형 콘셉트의 부두와 외곽 구성은 최대한 살리되, 별도의 바다판/공중 전시대로 올려 놓지 않는다. 기존 미국 지역 지형과 같은 구형 바다에 접속한다.
- 모든 건물을 억지로 구면 변형하지 않는다. 기존 기능 작업대의 지지면을 유지하고 신규 기초/해안을 연결한다.
- 이미 수정된 US_LAND_TERRACE의 수중 항로 여유를 보존한다. 새 기단·자유의 여신상 섬이 그 통로를 다시 막아서는 안 된다.
- 네이비 USA·밝은 별·녹청 동상·회색/청회색 유리·크림 석조·붉은 교량·청색 물류 장비를 구분한다.
- 최종 PBR/실내/유체 시뮬레이션까지 확대하지 않는다. 그러나 주요 랜드마크와 문자/별은 실제 카메라에서 디자인이 읽히는 수준까지 만든다.
- 컨셉의 구름 배경·흰 스튜디오 바닥을 미국 지역의 별도 배경으로 넣지 않는다. 장면은 기존 세계와 이어져야 한다.

## 5. 변경·보호 계약

새 컬렉션 예: US_CITY_CONCEPT_V001. 아래를 독립 편집 가능하게 분리한다.
USA_LETTERS / USA_STARS / LIBERTY / SKYLINE / URBAN_BLOCKS /
CIVIC_AND_BRIDGE / HARBOR_DRESSING / SITE_AND_LANDSCAPE

기존 미국 배경 프록시는 목록을 명시해 복사본에서 정적으로 교체/숨김 가능하다. 접두사만 보고 미국 객체 전부를 삭제하거나 숨기지 않는다. 대체 관계와 실제 데이터 변경을 기록한다.

보호 대상:
- 중국 도시·CHINA·구름·수로·해안과 수정된 인양 기구.
- 모든 기존 카메라·타깃·렌즈·Action·시간축·구간 경계.
- 선박 항로·자세·적재·접안, 화물 인계와 작동 장비의 기능 기준점.
- 미국 지역 루트의 위치/방향, 기존 부두 높이·하역 지점·차량/창고 동선.
- 지구 중심·반지름과 기존 연속 수면.

미국 시각 객체는 바꿀 수 있어도 이 보호 대상은 기본적으로 바꾸지 않는다. 전역 조명/색 관리도 임의 교체하지 않는다.

새 미국 객체는 현재 미국 지역 좌표계에 고정한다. 프레임마다 크기·위치·가시성을 바꾸어 가독성을 꾸미지 않는다. 카메라 고정 이미지 평면이나 전체 콘셉트 투영으로 3D 구현을 대신하지 않는다.

미국 기능 구역을 보존하려면 콘셉트 충실도를 크게 포기해야 하거나, 카메라/항로를 바꿔야 자유의 여신상이 보이는 경우에는 관련 수정만 보류한다. 진단용 후보 구도·배치와 최소 변경안을 제출하되 승인 전 본편 카메라를 바꾸지 않는다.

## 6. 실행 순서

T1 — 기준 재현·미국 구역/가시성 지도
- 현재 저장본을 별도 inputs/base.blend로 보존하고 실제 해시·타임라인·기준 환경을 기록한다.
- 현재 씬의 미국 객체·제약·부모·기능 공간과 이미 있는 모델을 조사한다.
- 기존 검사/행동을 재현하고 기존 실패를 분리한다.
- S3 후반 접근부터 S4 접안·하역, S5 창고 이동까지 기준 스틸/영상을 얻는다.
- 참조 D01~D08, 정적 배치 허용 영역, 변경/보호 목록을 reference-map.json 및 allowed-changes.json으로 만든다.

T2 — 큰 배치와 자유의 여신상부터
- USA·별·동상·주요 타워·공공건축·교량·항만/창고 군집의 큰 형태를 배치한다.
- 동상 참조비율 기준안과 확대안을 동일 카메라에서 비교해 위치·크기를 선택한다. 상세 건축 전에 실제 입항 가독성을 먼저 검증한다.
- 기존 선박 통로/하역/도로/도크를 침범하지 않는 배치인지 확인한다.
- 범위 내 정적 조정은 근거를 남기고 진행한다. 문제를 건물 축소·별 생략·카메라 이동으로 숨기지 않는다.

T3 — 모델링과 밀도·디자인 구현
- 구획별 건물군을 채우고 동상 식별 형태, USA 베벨/두께, 별, 대표 입면·돔·교량·항만 구조를 구현한다.
- 신규 메시·재질은 원본과 공유 오염이 없도록 분리한다. 결정적 형상은 실제 3D, 반복 창호 등은 모듈/재질 활용 가능하다.
- 이전 구역의 재생성으로 새 장면이 날아가지 않도록 구역별 소유 태그·설정·안전한 재실행을 제공한다.
- 참조와 다른 부분을 차이 목록에 계속 기록한다. 일반 도시가 됐는데 디테일이 많다는 이유로 완료시키지 않는다.

T4 — 본편 카메라·기능 회귀 검증
- 실제 본편 카메라로 입항→도시 공개→접안→하역→차량/창고 연결을 정상 속도로 렌더하고 직접 확인한다.
- f330/390/421/456/510/532/600/648은 관찰 후보다. 실제 채택 타임라인과 프레이밍을 확인해 필요한 구간을 선택한다. 고정된 정답 프레임으로 간주하지 않는다.
- 동상이 읽히는 실제 연속 구간의 시작/중간/끝, 지속 시간, 가림을 기록한다. 바운딩박스가 프레임 안에 있다는 것만으로 통과시키지 않는다.
- USA와 별은 도시 공개에 적합한 구간에서 함께 인식돼야 한다. 모든 10개 별이 모든 프레임에 보일 필요는 없지만 하나의 진단뷰에서만 보이는 결과도 불충분하다.
- 전체 타임라인의 보호된 핵심 동작 평가값과 관련 경계/근접 구간의 서브프레임을 검사한다. 새로운 미국 형상이 S3 항로와 S4–S7 동작을 가리거나 관통하지 않는지 확인한다.
- 기존 결함이 이번 변경에 의해 악화되지 않았는지 대조한다. 기존 결함을 묶어 전부 수정하지도, 새 결함을 기존이라고 덮지도 않는다.

T5 — 재개방·재현·최종 인계
- 결과를 새 Blender 프로세스에서 열어 대표 렌더를 다시 생성한다.
- 같은 입력과 설정으로 별도 경로에 재현하여 구조·배치·보호 상태·대표 출력을 비교한다.
- diff와 허용 목록, AC별 증거를 대조한다. 가능하면 최종 파일을 읽기 전용으로 독립 검토한다.
- 최초/진입/대표 공개의 3장 렌더를 후속 미국 스타일프레임 입력 후보로 제공하되 스타일프레임 생성 완료라고 하지 않는다.

## 7. 검증 도구 적용 원칙

기존 previz-crane-height-v002/scripts/verify_scope.py는 인양 변경을 대상으로 과거 inputs/base.blend와 전체 객체 동일성을 비교하고 자신의 폴더에 보고서를 쓴다. 새 미국 객체 추가를 허용하는 검사가 아니다.

기존 스크립트는 보존하고 현재 기준본·이번 allowed-changes를 사용하는 새 검사/안전한 어댑터를 작성한다. 기존 검사 삭제/skip으로 통과시키지 않는다. 과거 객체 개수·전체 메시 불변 검사는 변경 사유와 대체 검사로 명시적으로 대응한다.

핵심 검증:
- 원본·비관련 메시/재질/Action 보존.
- 카메라·선박·화물·차량·작동 기구의 기존 평가값 보존.
- USA 3글자·별 10개·동상 식별 형상과 신규 정적 객체 목록.
- 선박 실제 메시·화물·크레인·카메라와 신규 형상의 충돌/가림.
- 동상의 크기 확대와 실제 진입 가시성.
- 경로 충돌·중복 생성·덮어쓰기 거부, 재실행·재개방.

자동 검사는 파일/구조/동작 보존의 근거다. 미술 일치와 가독성은 실제 이미지·정상 재생으로 별도 판정한다.

검토 영상은 현재 원본의 정상 속도, 같은 FPS와 프레임 범위로 비교한다. 원본이 12fps라면 전체 정수 프레임을 12fps로 출력한다. 기존 2/3프레임 샘플 또는 3.5배속 웹 프리뷰를 정상 동작 검증으로 대신하지 않는다.

형상 검토는 Workbench, 디자인 검토는 같은 비교 환경의 기본 재질 렌더를 사용할 수 있다. 두 목적을 구분하고 UI·가이드가 없는 CAM_MASTER 렌더를 제출한다. 진단용 조감도는 보조자료이며 본편 카메라 변경이나 성공 증거의 대체물이 아니다.

실행 형식 예시 — 실제 설치 경로/스크립트/인자 확인 후 확정:
<BLENDER> --background <WORKING_BLEND> --python-exit-code 1 --python <TASK_SCRIPT> -- <실제 지원 인자>

새 스크립트는 실제 파일과 지원 인자를 검증해 문서화한다. F: 경로 또는 Blender 설치 버전이 동일하다고 가정하지 않는다. 무관한 웹 lint/빌드·배포를 끼워 넣지 않는다.

## 8. 수용 기준

AC-1 기준·원본 보존
현재 채택 경로와 실제 파일 해시, 입력 이미지, 로컬/원격 차이를 기록하고 원본·미저장·무관한 변경을 보존한다.
검증: 입력 manifest, 전후 해시, diff, 경로 보호 검사.

AC-2 콘셉트 구성·밀도
D01~D08의 상대 구획·스카이라인·중저층·항만·공공건축·교량·창고가 구현되며 일반적인 상자 도시로 대체되지 않는다. 불가피한 차이는 숨기지 않는다.
검증: 참조 대응표, 유사한 진단 시점과 실제 본편 렌더의 비교, 미반영 항목 목록.

AC-3 USA·별
USA 세 글자의 입체 조형/색/두께와 양옆 별 10개가 편집 가능한 3D로 존재하고 세계에 고정된다. 도시 공개 구간에서 문자와 양측 별 장식이 읽힌다.
검증: 객체/표시형상/정적 상태 검사, 실제 렌더. 글자 PNG/카메라 추종 금지.

AC-4 자유의 여신상 확대·입항 가독성
동상 본체가 정규화한 콘셉트 기준보다 커졌고, 접근 중 횃불·왕관·몸체 윤곽을 연속적으로 인지할 수 있다. 선박/크레인 통로를 막지 않는다.
검증: 기준/확대 배율과 크기 기록, 정상 속도 영상, 가시 구간 시작/중간/끝, 실제 가림/충돌.

AC-5 세계·물류 연속성
같은 구형 바다·현재 미국 위치에 붙어 있고, 이미 확보한 수중 항로 여유를 보존한다. 접안·인양·하역·트럭/창고 동선에 신규 관통·부유·심한 가림이 없다.
검증: 실제 메시 기반 검사와 S3→S4→S5 연결, 영향받는 S6/S7 검토.

AC-6 보호 동작·중국 구간
카메라·항로·이벤트·중국 디자인/인양과 비관련 데이터가 기준본과 일치한다. 새 모델의 등장으로 생기는 픽셀 차이와 기존 데이터 보존은 구분한다.
검증: 데이터 서명·핵심 루트 평가·기준 회귀와 중국 대표 프레임.

AC-7 재현·증거
새 .blend가 재개방되고 재현 가능하며 모든 AC 증거가 제출 결과의 버전/해시에 연결된다.
검증: 재생성 비교, 명령·환경·종료 코드·로그, 결과 manifest.

필수 AC 실패/미검증이 남으면 전체 완료가 아니다. 기술적 완료·사용자 미술 수용·운영 공개는 별개다.

- superpowers:systematic-debugging — 가림·좌표·접촉·회귀 실패 원인 분리.
- superpowers:verification-before-completion — 최종 파일의 새 증거 확인.

위 이름은 모델링 기능 자체를 제공하는 보장이 아니다. 기본 구현은 실제 설치된 Blender/bpy와 검증된 기존 도구다. 필요한 Blender 전용 스킬/MCP가 있으면 설명·권한을 확인한다. 없는 스킬을 사용했다고 보고하지 않는다. 복잡한 조각을 별도 자산으로 대체해야 하면 사용권·비용·형상 변경을 먼저 보고한다.

Higgsfield 플러그인이 설치됐다는 사실은 업로드·AI 생성·유료 호출 허가가 아니다. 이번에는 생성 API나 새 외부 자산 구매를 실행하지 않는다. 같은 .blend를 여러 에이전트가 동시에 수정하지 않는다.

필수 경계:
- 테스트 삭제·비활성화·규칙 완화로 통과를 꾸미지 않는다.
- 비밀키·실제 개인정보를 코드·로그·샘플에 넣지 않는다.
- 기존 무관한 변경과 미저장 GUI 작업을 보존한다.
- 승인 없는 운영 데이터 변경·운영 배포·유료 호출·강제 푸시·무관한 변경 덮어쓰기를 금지한다.
- 별도 요청 없는 커밋·push·PR·외부 업로드·마스터 승격을 하지 않는다.
- 라이브러리/플러그인 추가는 이유·영향을 보고한다. 폰트 파일을 재배포하지 않는다.
- 참조의 글자·국기·시설·선박을 실제 운영/자산 보유의 증빙으로 해석하지 않는다.

이제 T1에서 현재 저장본과 미국 구역을 확인한 뒤, 자유의 여신상의 입항 가독성을 먼저 확보하고 콘셉트 기반 도시 모델링을 진행하라.
