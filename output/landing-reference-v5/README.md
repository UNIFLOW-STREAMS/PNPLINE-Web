# PNPLINE 전체 랜딩 V5

수정된 중문 V4와 레퍼런스 기반 디자인 방향을 적용한 로컬 검토용 구현이다. 히어로, 서비스, 고객 유형, 창고와 시스템, 진행 절차, 비용 설명, FAQ, 견적 문의의 **8개 영역**을 포함한다. 개인정보 페이지는 독립 경로로 제공한다.

## 실행

저장소 루트 `F:/pnpline-landing`에서 실행한다.

```powershell
python output/landing-reference-v5/server.py --port 9672
```

브라우저 주소: [http://127.0.0.1:9672/](http://127.0.0.1:9672/)

개인정보 페이지: [http://127.0.0.1:9672/privacy/](http://127.0.0.1:9672/privacy/)

서버는 `127.0.0.1`에만 바인딩하고 이 폴더의 공개 웹 파일만 제공한다. MP4 시점 탐색을 위해 HTTP byte-range 요청을 지원한다. 파일을 직접 더블클릭하기보다 위 서버를 사용한다. 종료는 서버 터미널에서 `Ctrl+C`다.

## 에셋과 IMAGE 자리표시자

- **로고:** `resources/logo/PNP-LINE.webp`의 공식 원본을 사용한다.
- **폰트:** 기존 `output/landing-immersive-v3/assets/`의 로컬 Noto Sans SC 400·500·600·700과 `Noto-Sans-SC-OFL.txt`를 사용한다.
- **영상:** 같은 V3 폴더의 `hero-scrub.mp4`를 재사용한다. 기존 출처 목록에 기록된 33초 작업 영상의 스크롤용 파생본이며 최종 영상이 아니다. 원본 출처는 `hero-section-video/blockout/pacing-33s-v001/preview/pnpline-33s-30fps-v001.mp4`다.
- **포스터:** 기존 `hero-poster.jpg`를 재사용한다. 같은 작업 영상의 3.5초 프레임이며 영상 첫 프레임과 같다는 의미는 아니다.
- 기존 파일의 상세 출처 기록은 `output/landing-immersive-v3/assets/provenance.json`에 있다.

새 이미지 생성 서비스를 호출하지 않았다. 사용자의 요청에 따라 **네 개의 색상 배경 + IMAGE 글자 SVG**를 로컬에서 만들었다. 난수 시드 `20261101`을 사용하므로 같은 명령으로 동일 색상을 재현한다.

| 자리 | 파일 | 배경색 |
| --- | --- | --- |
| 창고 서비스 설명용 이미지 | `assets/placeholder-warehouse.svg` | `#abaed2` |
| 운송 서비스 설명용 이미지 | `assets/placeholder-freight.svg` | `#a7a5a6` |
| 실제 창고 자료가 들어갈 자리 | `assets/placeholder-evidence.svg` | `#bcc3ca` |
| 실제 시스템 자료가 들어갈 자리 | `assets/placeholder-system.svg` | `#b0b2d9` |

내역은 `assets/placeholder-manifest.json`에 있다. 네 SVG는 실제 시설·장비·시스템·실적을 묘사하지 않으며 alt에서도 자리표시자임을 밝힌다. AI 이미지 생성·유료 생성 호출은 **0건**, 추가 생성 비용은 **$0**이다. 과거 프로젝트 전체 지출이 $0이라는 뜻은 아니다.

기존의 사실적인 생성 창고·항만 삽화, 미확인 시설 사진, 파트너 배지, 가짜 WMS 화면이나 운영 수치를 사용하지 않는다. 실제 자료로 교체할 때는 관계·출처·사용 권한·공개 범위·마스킹을 확인해야 한다.

## 인터랙션과 접근성

- 히어로의 유효 스크롤 구간을 영상 시점에 대응시킨다. 아래로 이동하면 뒤 시점, 위로 이동하면 앞 시점으로 탐색하고 스크롤을 멈추면 프레임을 유지한다. 자동재생·반복 재생은 없다.
- 영상이 로드되기 전이나 끝나기 전에도 서비스·견적으로 즉시 이동할 수 있다. 앵커 이동 뒤에는 목적지에 포커스를 옮기고 모바일 메뉴를 닫는다.
- 헤더 메뉴는 좁은 화면에서 펼침·닫기로 전환한다. Escape와 메뉴 바깥 클릭·포커스 이동으로 닫을 수 있다.
- FAQ는 기본 HTML `details/summary`를 사용한다. 질문을 키보드로 열고 닫을 수 있으며 여러 답변을 함께 열 수 있다.
- 모바일 본문·폼은 1열로 바뀌며 6개 폼 필드 순서를 유지한다. 라벨·도움말·오류를 입력과 연결한다.
- 시스템 `prefers-reduced-motion: reduce` 또는 푸터의 `减少动态效果` 설정에서는 정지 포스터와 일반 문서 흐름을 사용한다. 시스템 모션 감소가 켜져 있으면 페이지 설정으로 이를 해제하지 않는다.
- 미디어 로드·탐색 실패, 낮은 화면 높이 또는 히어로 텍스트가 가용 높이를 넘는 경우에도 정적 배치로 전환해 콘텐츠와 문의 접근을 유지한다.
- 문서가 보이지 않거나 히어로가 화면을 벗어나면 불필요한 프레임 갱신을 멈춘다.

## 문의와 개인정보의 한계

이 구현은 **디자인 미리보기**다. 문의 폼은 서버 엔드포인트, 네트워크 전송, 저장 기능이 없다. 버튼을 눌러도 실제 문의가 접수되지 않으며 `设计预览：信息未发送。`를 표시한다. 빈 값의 운영상 필수 여부는 확정하지 않았고, 입력된 이메일 형식과 동의 여부를 미리보기에서 안내한다.

동의 영역의 개인정보 링크는 새 창으로 열어 원래 폼의 입력을 유지한다. `/privacy/`는 **검토용 안내이며 정식 개인정보 처리방침이 아니다.** 실제 수집·보관·처리 방식에 맞춘 전문과 문의 접수 구현은 운영 공개 전에 별도로 완성해야 한다.

영상은 작업본이고 품질 평가에서 제외한다. 사용자 지정 IMAGE 자리표시자는 의도적인 상태이며 최종 시각 자산이 아니다. 이 README는 기능과 범위를 설명하며, 실제 브라우저 검증 결과는 부모 작업의 QA 기록을 따른다.
