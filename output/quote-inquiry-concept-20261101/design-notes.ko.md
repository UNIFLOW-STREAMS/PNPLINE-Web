# Quote 문의폼 컨셉
2026-11-01

## 판단
기존 Quote의 차콜 배경, 밝은 입력면, 소개문구와 패키지 디테일은 이어간다.
입력항목은 원고V4의6개 항목으로 교체하고 개인정보동의를 추가한다. 새페이지나 두 번째 문의폼을 만들지 않는다.
기존 제품/이메일 입력 의미를 유지하고 물량·목적지를 원고요구에 맞게 재정의한다. 운송방식과 IOR를 추가한다.
회사명·출발지·서비스체크·추가요구 textarea는 이번6항목 폼에 병합하지 않는다. 해당질문이 실제운영에 필요하면 원고의 폼설계 검수에서 확정한다.
TXT 요청서 생성 대신 실제문의 접수 흐름을 목표로 하는 디자인이다. 이번 작업은 컨셉이며 실제서버나 전송기능 구현을 완료한 것이 아니다.

## 원고 근거
docs/pnpline-china-source-content/pnpline-landing-mvp-copy-v4.zh-CN.md 149–166행.
필드6개는 제품 / 운송방식 / 월물량 / 목적지 / IOR / 이메일이다.
동의는 privacy 정책열람과 본문의문의를 위한 정보사용 동의다.
인계문서50행은 필수여부·수집목적·동의문구에 운영검수가 필요하다고 명시한다. 별표를 임의로 확정하지 않았다. 최종개인정보정책과 처리목적은 실제접수에 맞춰야 한다.

## 구성
좌측38%는 브랜드소개와 작은패키지, 우측62%는 단일흐름의 밝은폼.
폼내부는 제품 → 운송 → 물량 → 목적지 → IOR → 이메일 → 동의 → 제출 순서의1열.
물량의 수량과 단위만 하나의 복합필드로 나란히 둔다. 서로다른 질문을2열로 쌓지 않는다.
한 개 폼이며 카드그리드·탭전환으로 필수질문을 숨기지 않는다. 원고의6개항목은 한섹션에서 충분히 배치할 수 있다.

## 필드별 조작
운송방식 FCL/LCL/항공/미정 단일선택. 이미지의 Not sure 강조는 선택상태 예시다. 실제폼은 명시적인 무선택상태에서 시작한다.
월물량은 자유텍스트와 단위선택. 수량값은 숫자 또는 Not sure를 허용한다. CBM/kg/orders를 제안하고 Other unit을 선택하면 같은 복합필드 안에서 단위를 직접 쓸 수 있다.
Not sure이면 단위를 강요하지 않는다. 빈입력·0·음수·최대길이·소수표기 처리규칙은 실제운영 물량정의에 맞춰 구현한다.
목적지의5가지 옵션은 content.json에 모두 기록했다. FBA창고/PNPLINE미국직영창고/최종소비자/미국기업·소매수령처/미정.
IOR Needed/Not needed/Not sure 단일선택. 필요여부 답변이 서비스적격 판정은 아니다.
이메일은 연락용이며 placeholder를 실제값으로 채우지 않는다.
개인정보동의는 초기미선택. 정책은 /privacy/로 연결하고 돌아온 뒤 작성내용을 유지할 수 있도록 구현한다.

## 상태와 서버연동 요구
서버 접수목적지·저장/보관정책·개인정보전문·스팸대응·필수필드정의는 이번컨셉에서 확정하지 않는다.
제출중은 실제 요청동안만 표시하며 중복클릭을 막고 버튼이름과 aria-busy를 갱신한다.
성공은 서버가 실제 접수를 확인한 경우에만 표시한다. 생성TXT나 로컬변수 갱신을 접수완료로 표현하지 않는다.
실패는 오류를 알리고 재시도를 제공한다. 재시도시 중복접수를 방지할 서버정책도 필요하다.
오류시 입력근처 문구와 요약을 제공하고 첫오류 필드로 초점을 옮긴다. 동의누락과 이메일오류를 구분한다.
입력보존/재시도는 구현·테스트한 뒤 안내한다. 임의의 회신시간·확정요율·배송일을 쓰지 않는다.
상태문구 초안은 content.json에 있으며 실제수집에 맞춰 검수한다.
