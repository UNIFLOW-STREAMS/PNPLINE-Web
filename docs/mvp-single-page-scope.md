# PNPLINE 2페이지 MVP 범위와 32개 콘텐츠 처리 기준

결정 ID: `MVP-2PAGE-20261031`  
결정일: 2026-10-31 (Asia/Shanghai)  
상태: 사용자 범위 승인. 콘텐츠·디자인·영상·개인정보 검수 및 실제 구현 완료와는 별개다.  
근거: 사용자가 메인 랜딩 한 페이지와 개인정보 처리방침으로 MVP 축소를 지시했다. 기존 32페이지 전부 또는 핵심 10페이지+개인정보의 출시 요구를 대체한다.

## 1. 공개 범위

- 공개 콘텐츠 페이지는 `/`와 `/privacy/` 두 개다. 대표 주소는 현행 GitHub 결정의 `https://pnpline.cn`이며 www 호스트는 대표 주소로 301 연결한다.
- `/`의 목적은 미국 직영창고를 중심으로 제공 범위·신뢰 근거·비용을 이해시키고 견적 상담을 받는 것이다.
- 개인정보 페이지는 실제 리드 처리와 분석 설정에 맞춰 독립 검수하고, 폼과 푸터에서 접근한다. 복귀 링크는 `/#quote`다.
- `/#services` 등은 같은 문서의 이동 위치다. 별도 페이지·canonical·검색 키워드 랜딩으로 세지 않는다.
- API, robots.txt, sitemap.xml, 자산 URL과 404/오류 응답은 콘텐츠 페이지 수에 포함하지 않는다.
- 32개 원고는 원자료로 보존한다. 2개 경로 유지, 26개 핵심 내용 통합, 뉴스/정책 3개와 파트너 1개 전체 보류다. 통합된 26개의 상세 경로도 MVP에서는 생성하지 않는다.

## 2. 랜딩 구조와 내비게이션

화면 카피 초안은 [통합 랜딩 중국어 원고 V4](pnpline-china-source-content/pnpline-landing-mvp-copy-v4.zh-CN.md), 문장 선택·증빙·폼·공개 검수 조건은 [V4 인계서](pnpline-china-source-content/pnpline-landing-mvp-copy-v4-handoff.md)를 따른다. 범위 승인이 카피 승인이나 실제 사이트 구현을 뜻하지는 않는다.

| 순서 | 앵커 | 내용·현재 콘텐츠 소유 이슈 |
| --- | --- | --- |
| 1 | `/#journey` | 핵심 메시지·CTA와 S1–S7 Scroll World (#22, #42) |
| 2 | `/#services` | 창고·국제운송·통관 지원·업무 범위 (#26, #23, #21) |
| 3 | `/#customers` | Amazon·독립몰/TikTok·B2B 사용 시나리오 (#29) |
| 4 | `/#evidence` | 실제 창고·운영·자격 증빙과 WMS/API 지원 (#31, #34) |
| 5 | `/#process` | 상담→조건 확인→입고 준비→운영 시작 및 준비 정보 (#22) |
| 6 | `/#pricing` | 비용 항목·견적 조건 (#22, #14) |
| 7 | `/#faq` | 핵심 FAQ·서비스 제외 조건 (#22) |
| 8 | `/#quote` | 하나의 견적 폼·연락 채널·개인정보 동의 (#22, #41, #40) |

헤더는 服务→`/#services`, 运营与系统→`/#evidence`, 费用说明→`/#pricing`, 常见问题→`/#faq`, CTA 获取报价→`/#quote`를 기본으로 한다. 로고는 `/`, 개인정보는 푸터·폼의 `/privacy/`로 연결한다. 개인정보 페이지에서도 홈 앵커를 포함한 링크를 사용한다. 이는 제작용 정보 구조이며 중국어 최종 카피는 #33에서 검수한다.

S1–S7은 영상 제작 구간이며 위 웹 섹션 번호와 다르다. 히어로는 스크롤 진행도에 따라 영상의 특정 시점으로 이동하는 방식이다. 스크롤을 멈추면 해당 시점을 유지하며, 설명 영상을 자동으로 끝까지 재생하는 흐름으로 만들지 않는다. 중국 선적·출항→해상 항해→미국 하역·트럭 이동→창고 처리→배송 분기는 시각적 연출로 전달하고, 7개 장면 설명표는 공개 본문에서 제외한다. 항공·반품·FBA 상세 조건은 일반 서비스 설명에서 보완한다. 영상 완료를 강제하지 않고 서비스·견적으로 바로 이동할 수 있게 한다. 33초·30fps 로컬 검토본은 존재하나 최종 미디어 규격·모바일·시킹 검수는 #24/#62/#43에 남는다.

## 3. 통합·보류 기준

1. **통합:** 서비스 선택·제공/제외 범위·견적 준비·신뢰 판단에 필요한 고유 정보만 요약한다. 반복 히어로·회사 소개·CTA·폼은 하나로 합친다. 서비스별 차이는 카드·표·FAQ·펼침 영역으로 유지한다.
2. **검증 조건:** 실제 주소·면적·처리량·요율·배송 기간·자격·통관 책임은 기존 공개 승인과 출처 기준을 따른다. 미국 직영 운영은 기존 사용자 확인을 유지하되 부동산 소유·전 과정 직접 수행으로 확대하지 않는다. 미확정 정보는 고객 화면의 빈 카드나 TBD 대신 숨기거나 승인된 조건부 안내로 처리한다.
3. **상세 보류:** 전문 정책 해설·전체 작업별 요율·API 기술 문서·세부 SOP·플랫폼별 독립 SEO 페이지는 MVP 공개 조건에서 제외한다. 원자료와 출처·검수 상태를 보존한다.
4. **전체 보류:** 뉴스/정책 게시물과 파트너 모집은 초기 탐색·출시 의존성에서 제외한다. 정책 변경 대응에 필요한 일반 주의사항·상담 전 정보만 법무 확인 후 FAQ로 요약할 수 있다. 해설 전문을 그대로 싣지 않는다.
5. **후속 재개:** 실제 고객 문의 또는 우선 검색 의도, 고유한 본문·증빙, 담당자와 최신성 유지 방식이 확보되면 상세 페이지를 별도 승인한다. 뉴스는 작성자/검수자·날짜·출처·갱신 담당자를, 파트너는 모집 대상·조건·응대 담당자를 추가로 확보한다. 자동 P1/P2 출시 약속을 하지 않는다.

## 5. 링크·색인·기술 기준

- 원고의 상세 페이지 링크는 위 표의 홈 앵커 또는 상담으로 바꾼다. 모든 링크를 무조건 견적으로 바꾸지 않는다. 개인정보에는 서비스 영업 CTA 대신 홈·폼 복귀를 제공한다.
- 랜딩의 주요 텍스트·증빙·CTA는 초기 HTML에 포함하고 영상·스크롤·클릭 실행에만 의존해 생성하지 않는다. 미디어 지연 로딩과 본문 접근을 분리한다.
- 두 경로에 고유한 title/description/H1/canonical을 둔다. 실제 화면과 맞는 구조화 데이터만 사용하며 서비스별 가상 URL이나 불필요한 다단계 BreadcrumbList를 생성하지 않는다.
- 검수 빌드는 noindex·접근 제한을 유지한다. 공개 검수 후 공개·색인 가능한 두 경로만 sitemap에 넣고 앵커·보류 경로는 제외한다. 개인정보 문서의 색인 예외가 별도 승인되면 sitemap도 동일하게 조정한다.
- 기존 상세 경로가 이미 공개·색인되었는지 배포 전에 확인한다. 공개 이력이 있으면 실제 대체 콘텐츠별로 리디렉션을 검토하고 기록한다. 미공개 계획 경로는 생성하지 않으며 요청 시 정상 404를 반환한다. 모든 기존 경로를 홈으로 일괄 리디렉션하지 않는다.
- Next.js/TypeScript, 파일 기반 카피·운영 JSON·evidence manifest, 견적 API/이메일/최소 리드 저장의 기존 방향은 유지한다. 경로 축소가 백엔드·동의·보관/삭제·오류 처리·운영 검수를 없애지 않는다.
