# PNPLINE 단일 페이지 섹션 계획

작성일: 2026-11-01 · 상태: [V5 로컬 구현](../output/landing-reference-v5/README.md)에 반영. [브라우저 검증 범위](../output/landing-reference-v5/QA.md) 참고.

시각 기준: [design-taste-frontend 디자인 방향](pnpline-design-direction-2026-11-01.ko.md). 아래 구조는 유지하며, 서비스·비용 제목 배치와 견적 배경은 이 방향에 맞춰 정리했다. 번호는 계획서 식별용이며 공개 화면의 장식 번호를 요구하지 않는다.

기준 원고: [수정된 중문 V4](pnpline-china-source-content/pnpline-landing-mvp-copy-v4.zh-CN.md) 및 [인계 기준](pnpline-china-source-content/pnpline-landing-mvp-copy-v4-handoff.md).
참고 조사: [Mobbin 선정 5개와 실제 사이트 확인 기록](../design-refs/mobbin-2026-11-01/five-site-check/REPORT.ko.md).

이 문서는 전체 페이지의 정보 구조·배치 계획이다. 랜딩 구현, 원고 승인, 실제 서비스 범위 승인 또는 폼 운영 승인을 의미하지 않는다. 기존 중문·한국어 원고와 사이트 코드는 수정하지 않는다.

## 1. 전체 방향과 순서

중국 판매자가 미국 창고와 물류 서비스를 비교하고 문의하는 B2B 랜딩으로 설계한다. 큰 물류 장면으로 시작하되 본문에서는 작업 범위, 운영 확인 사항, 비용 조건을 읽기 쉽게 보여준다.

**히어로 → 서비스 → 고객 유형 → 창고와 시스템 → 진행 절차 → 비용 설명 → FAQ → 견적 문의 → 푸터**

방문자의 질문도 같은 순서로 이어진다.

1. 어떤 회사이며 무엇을 맡길 수 있는가?
2. 내가 필요한 작업을 맡길 수 있는가?
3. 내 판매 방식에는 어떤 조합이 필요한가?
4. 화물과 기록은 어떻게 관리되는가?
5. 문의한 뒤 무엇을 확인하는가?
6. 비용을 비교할 때 무엇을 봐야 하는가?
7. 아직 불확실한 조건은 무엇인가?
8. 어떤 정보를 보내면 상담을 시작할 수 있는가?

레퍼런스의 역할은 구분한다. United Carriers를 전체 정보 위계의 주 참고로, Swap을 분류와 상세 설명의 관계, Aurora를 실물 자료와 문의 폼의 배치, Waabi를 히어로의 장면·텍스트 비율, Zipline을 단계 구분의 보조 참고로 사용한다. 다섯 브랜드의 색·서체를 섞지 않는다. 직접적인 물류 사업 참고는 United Carriers이며, 나머지의 사업 범위·성과를 PNPLINE으로 옮기지 않는다.

## 2. 전체 페이지 구도

아래는 기능 구현 전 배치도다. 각 상자의 높이는 실제 스크롤 길이를 뜻하지 않는다.

```text
데스크톱
┌──────────────────────────────────────────────────────────────┐
│ PNPLINE   服务范围  仓库与系统  费用说明  常见问题   [获取物流报价] │
├──────────────────────────────────────────────────────────────┤
│ 01 히어로 · 전체 폭 영상 / 스크롤 위치에 대응하는 프레임        │
```

모바일에서는 같은 순서를 유지한다. 히어로의 제목·설명·버튼이 첫 화면에서 읽히도록 영상과 텍스트의 안전 영역을 확보한다. 각 본문은 제목 → 설명 → 상세 순의 1열로 바꾼다. 고객 유형 3행과 비용 5행은 가로 스크롤 표 대신 항목명 아래에 설명을 둔다. 진행 절차는 세로 3단, 견적 폼은 6개 필드를 위에서 아래로 배치한다. 별도 모바일용 요약 원고로 조건을 누락하지 않는다.

전체 디자인은 공식 로고와 대표 청록색을 유지하고, 중문 산세리프·밝은 기본 면·옅은 중성 면을 공통 기준으로 삼는다. 견적도 같은 테마로 유지한다. 제목·구분선·열 너비로 위계를 만든다. 모든 영역을 동일 크기 카드 또는 전체 화면 높이로 만들지 않는다. 본문은 내용 길이에 맞춰 높이를 정한다.

## 3. 영역별 계획

### 01. 히어로 · #journey

- **V4 제목:** 美国自营海外仓，衔接出货与订单履约
- **방문자가 이해할 내용:** PNPLINE은 미국 창고를 직접 운영하며 중국 출고, 미국 보관, 주문 출고·배송 요구를 연결한다. 모든 구간의 무조건적 직접 수행을 약속하는 의미로 확장하지 않는다.
- **보존할 내용:** 브랜드, H1, `依托PNPLINE直接运营的美国仓库…` 보조 문장. 두 번째 문단 `从一件代发、FBA补货到批量交付…`는 서비스 도입부로 이동해 내용은 보존하고 첫 화면의 텍스트 양을 줄인다.
- **핵심 행동:** `获取物流报价` → #quote. 보조 행동 `查看服务范围` → #services.
- **참고 화면:** [Waabi 히어로](https://mobbin.com/sites/sections/0345226a-541f-4607-89b7-b6e0923cb872)의 큰 장면·좌측 제목, [United Carriers 실제 히어로](https://unitedcarriers.com/)의 물류 장면과 행동 위계. Waabi의 세리프 서체와 자동재생은 채택하지 않는다.
- **배치:** 전체 폭 영상에 좌측 정렬 H1·설명·버튼. 첫 화면에 두 행동을 노출한다. 중문 제목은 데스크톱 2행을 기준으로 글자 크기·텍스트 폭을 조정하고 영상 주 피사체와 겹치지 않게 한다.
- **동작:** 히어로 구간의 스크롤 진행도 → 영상 시점. 아래로 이동하면 뒤 시점, 위로 이동하면 앞 시점, 정지하면 현재 프레임 유지. 자동재생·루프·재생 버튼·S1~S7 설명표·삭제된 안내 문구를 넣지 않는다. 페이지 내 링크는 긴 히어로 구간을 즉시 건너뛸 수 있어야 하며, 이동 중 모든 프레임을 순서대로 재생하지 않는다. 마지막 구간 후 고정이 풀리고 서비스가 이어진다. 스크롤 길이는 최종 영상의 시점 매핑과 기기 검증 후 정한다.
- **모바일/예외:** 좁은 화면에서도 설명·CTA 접근을 유지한다. 모션 감소 또는 미디어 실패에서는 대표 정지 이미지와 일반 본문으로 이어진다. 영상 품질은 이번 디자인 평가 범위에서 제외한다.

### 02. 서비스 · #services

- **V4 제목:** 按需要的环节，组合您的物流服务
- **방문자가 이해할 내용:** 필요한 구간만 문의할 수 있으며 실제 수탁 범위와 인계 책임은 확인한다.
- **보존할 내용:** 네 서비스의 이름과 조건을 모두 보존한다.
  1. `仓储与订单履约`: 一件代发 / FBA中转补货 / 库存与保管 / 退货与B2B. 단건 출고, 라벨·분할 보충, 보관 방식·기간, 반품 검품·재입고 및 B2B 포장·예약 조건을 구분한다.
  2. `中国出货与美国境内运输`: FCL/LCL/항공의 선택 기준, 출발·도착·물량·시간 요구, 입고 또는 미국 내 운송, 노선·접수·인도 범위 확인을 남긴다.
  3. `IOR与进口清关咨询`: 상품·거래 자료, 신고 문서, 책임, HS·FDA·FCC 관련 적용 요구·지원 범위 확인을 남긴다.
  4. `库存与系统对接`: 재고·입고·주문·출고 정보, 플랫폼·ERP·API의 실제 지원 범위 확인을 남긴다.
- **핵심 행동:** 필요한 서비스 범위를 파악한 뒤 `获取物流报价` → #quote. 서비스별 외부 상세 페이지나 별도 폼은 만들지 않는다.
- **참고 화면:** [United Carriers 서비스](https://mobbin.com/sites/sections/4987af31-2f8f-4b7a-ae54-884e327e7f1f), [Swap 분류·상세 설명](https://mobbin.com/sites/sections/3cc9073e-7451-4821-84ba-7ad0ff92018b).
- **배치:** 상단에 제목·공통 조건, 아래에 서비스명·상세를 가진 4개의 세로 행. 창고·이행 행은 4개 세부 작업을 2×2 텍스트 묶음으로, 나머지는 짧은 문단으로 둔다. 서비스명과 본문을 기본 노출하고 탭 뒤에 필수 설명을 숨기지 않는다. Swap에서는 분류와 상세의 대응 관계만 가져온다.
- **모바일:** 4개 서비스와 각 설명을 순서대로 노출하고 창고 세부 작업도 1열로 바꾼다. 이미지 캐러셀이나 수평 탭 탐색을 필수로 만들지 않는다.

### 03. 고객 유형 · #customers

- **V4 제목:** 从您的销售方式，找到需要的作业
- **방문자가 이해할 내용:** 같은 창고라도 판매 방식·수령인에 따라 필요한 작업이 다르다.
- **보존할 내용:** Amazon FBA/FBM은 두 방식의 구분, Shopify/TikTok Shop은 주문·포장·배송·반품·실제 연동, 공장·무역·B2B는 대량 운송·입고·재고·기업 납품을 설명한다. Walmart 등의 라벨·포장·예약 요구도 보존한다. 플랫폼명이 공식 협력·인증을 의미하지 않는다는 안내를 표 아래에 둔다.
- **핵심 행동:** 본인 상황에 맞는 작업을 대조한다. 필요한 경우 해당 서비스 행으로 페이지 내 이동한다. 채널을 고르는 별도 입력이나 견적 폼의 자동 선택은 추가하지 않는다.
- **참고 화면:** [United Carriers 업종별 행](https://mobbin.com/sites/sections/552c7526-87f8-44ba-af88-ae3bab81ae5d).
- **배치:** 고객 유형 3개를 구분선으로 나눈 넓은 행으로 배치한다. 좌측은 판매 유형, 우측은 우선 확인 사항. 플랫폼 로고 띠나 검증되지 않은 고객 사례로 표현하지 않는다. 서비스 정의는 반복하지 않고 조합과 차이를 쓴다.
- **모바일:** 유형명 아래에 확인 사항을 배치한다. 세 유형을 모두 노출한다.

### 04. 창고와 시스템 · #evidence

- **V4 제목:** 了解直接运营的美国仓库与作业方式
- **방문자가 이해할 내용:** 미국 직영 운영과 함께, 화물 인계·작업·재고·출고 기록을 무엇으로 확인할 수 있는가.
- **보존할 내용:** `仓库与货物交接`에서 입고 검수·보관·피킹·출고의 조건·자료·책임을, `库存与出库管理`에서 정보 항목·가용 기능·권한·갱신 방식·연동 범위 확인을 설명한다.
- **핵심 행동:** 자신의 상품과 기록 조회 요구를 대조한다. 추가 문의는 공통 견적 진입점을 사용하며 로그인·대시보드 체험을 새로 만들지 않는다.
- **참고 화면:** [Aurora 실물 이미지와 본문](https://mobbin.com/sites/sections/ef11fc7c-0c98-48b0-9faf-fbd568330939). 이미지와 근거 설명의 인접 배치만 채택하며 흐린 본문 대비를 따라 하지 않는다.
- **배치:** 옅은 회색 영역 안에 두 묶음. 검증된 자료가 있으면 실제 시설 사진+작업 설명, 개인정보를 제거한 시스템 실화면+확인된 기능 설명을 짝지어 놓는다. 자료가 없으면 두 텍스트 열로 완결하고 이미지 공간 자체를 없앤다.
- **모바일:** 각 묶음의 제목 → 자료가 있다면 이미지 → 해당 설명 순서로 배치한다.
- **중복 정리:** 서비스 영역은 ‘무엇을 문의할 수 있는지’, 이 영역은 ‘인계와 기록을 어떻게 확인하는지’를 맡는다. 면적·처리량·거점·인증·고객 로고·실시간 연동 등 미확인 사실을 추가하지 않는다. 히어로 장면을 실제 창고 증빙으로 쓰지 않는다.

### 05. 진행 절차 · #process

- **V4 제목:** 从一份需求，开始确认执行方案
- **방문자가 이해할 내용:** 문의만으로 실행이 확정되지 않으며, 조건 확인 뒤 견적과 실행 범위를 합의한다.
- **보존할 내용:** `说明需求` → `核对条件` → `确认报价`의 3단계. 상품·운송·예상 물량·목적지·IOR, 미정 항목 표기, 수탁 범위·자료·작업·납품·책임, 과금 단위·포함/추가 비용·실행 조건을 보존한다.
- **핵심 행동:** 문의 전에 아는 정보와 아직 정하지 못한 정보를 구분한다. 이 영역 자체에 별도 버튼은 두지 않는다.
- **참고 화면:** [Zipline 단계 목록](https://mobbin.com/sites/sections/11ec89ac-42c8-4311-b26b-85147d3e1fc3). 단계별 제목·설명의 구분만 참고하며, 지도·드론 배송·자동 전환을 도입하지 않는다. 가로 3단은 PNPLINE의 원고에 맞춘 새 배치다.
- **배치:** 흰 배경의 짧은 가로 3단. 작은 번호, 제목, 원고 설명을 표시한다. 7개 영상 장면이나 실제 운송 추적 타임라인과 혼동하지 않게 한다.
- **모바일:** 세로 3단으로 바꾸고 각 단계를 펼친 상태로 유지한다.

### 06. 비용 설명 · #pricing

- **V4 제목:** 先明确费用包含什么，再比较报价
- **방문자가 이해할 내용:** 같은 물류 서비스라도 상품·물량·운송·보관·작업 조건에 따라 비용이 달라지며 포함 항목을 비교해야 한다.
- **보존할 내용:** 头程运输 / 清关与相关费用 / 仓储 / 仓内操作 / 美国境内配送의 5항목과 조건 전부. 서비스비·세금 구분, 최소 과금, 장기 보관, 특수 포장·추가 작업, 최종 견적서 기준 안내를 남긴다.
- **핵심 행동:** 필요한 비용 항목을 확인한 뒤 `获取物流报价` → #quote.
- **참고 화면:** [United Carriers의 행 기반 정보 위계](https://mobbin.com/sites/sections/552c7526-87f8-44ba-af88-ae3bab81ae5d). 선정 화면에 PNPLINE과 같은 비용 비교표는 없으므로 원고의 2열 표를 직접 설계한다. 이를 레퍼런스의 가격표라고 표현하지 않는다.
- **배치:** 상단 제목·산정 원칙, 아래 전체 폭의 ‘비용 항목 / 확인 조건’ 5행. 표 아래 추가 비용 안내와 CTA. 요금제 카드, 시작가, 자동 계산기, 근거 없는 가격 예시는 넣지 않는다.
- **모바일:** 항목명 아래 조건을 쓰는 5개의 행으로 변환한다. 최소 과금·추가 요금 조건을 접힌 주석에 숨기지 않는다.

### 07. FAQ · #faq

- **V4 제목:** 询价前，先确认这些问题
- **방문자가 이해할 내용:** 자신에게 남은 조건·불확실성에 대한 직접적인 답을 찾을 수 있다.
- **보존할 질문 8개:** 직영 여부 / 一件代发와 FBA 중계 차이 / 한 구간만 상담 가능 여부 / 물량·방식 미정 시 문의 / IOR 필요 여부를 모를 때 / 세금·추가 비용 포함 여부 / 출고·배송 시간 / 재고·주문·연동 확인 방법.
- **핵심 행동:** 필요한 질문을 펼쳐 확인한다. 답변의 상세 기준이 필요할 때 #services, #evidence, #pricing 또는 #quote로 이동한다.
- **참고 화면:** [United Carriers FAQ](https://mobbin.com/sites/sections/cd260370-e196-4f28-b204-7fd65d69d85f).
- **배치:** 좌측 제목, 우측 8개 질문의 접이식 목록. 기본은 첫 질문을 열고 여러 답을 동시에 열 수 있게 한다. 질문은 모두 보이며 각 답에는 직접 답변을 남긴다.
- **중복 정리:** 직영·비용·시스템 질문은 짧은 직접 답변 + 관련 영역 링크로 정리할 수 있다. 전체 본문을 다시 복사하지 않는다. 미정 문의, IOR ‘不清楚’, 배송 시간의 영향 조건 등 문의에 필요한 답은 유지한다. 단건 출고와 FBA의 핵심 차이도 답 자체에서 설명한다. 실제 축약 문구는 중문 원고 검토에서 확정한다.
- **모바일:** 1열 접이식 목록. 키보드·터치로 열고 닫을 수 있고 열린 본문을 가리지 않아야 한다.

### 08. 견적 문의 · #quote

- **V4 제목:** 告诉我们您的商品与出货计划
- **방문자가 이해할 내용:** 어떤 정보를 보내야 하는지, 모르는 항목을 어떻게 적는지, 견적은 자료와 범위 확인 후 협의한다는 점.
- **핵심 행동:** 6개 필드 입력 → 개인정보 확인·동의 → `提交询价需求`.
- **참고 화면:** [Aurora 문의 폼](https://mobbin.com/sites/sections/a666acfc-2226-48e0-b10c-dc16764218b5). 라벨·입력·단일 제출 행동의 명확성을 참고하고 Aurora의 이름·회사명 등 입력 항목은 가져오지 않는다.
- **배치:** 옅은 중성 바탕의 왼쪽에는 제목·작성 안내, 오른쪽에는 기본 면 색상의 입력 필드. 필드 라벨은 입력창 위에 고정하고 설명은 해당 필드 아래에 둔다. 모바일에서는 안내 뒤에 1열 폼을 둔다. 다른 본문과 같은 테마를 유지한다.

| 순서 | 필드 | 유지할 안내·선택지 |
| --- | --- | --- |
| 1 | 产品类目 | 상품명 또는 카테고리 |
| 2 | 发货方式 | 海运整柜（FCL） / 海运拼箱（LCL） / 空运 / 未定 |
| 3 | 月出货量 | 물량과 단위(부피·무게·주문 수 등), 未定 허용 |
| 4 | 目的地 | FBA仓 / PNPLINE美国自营仓 / 最终消费者 / 美国企业或零售收货点 / 未定 |
| 5 | 是否需要IOR服务 | 需要 / 不需要 / 不清楚 |
| 6 | 联系邮箱 | 이번 문의에 사용할 이메일 |

데스크톱은 상품/운송 방식, 물량/목적지, IOR/이메일의 2열 3행을 기본으로 하되 긴 선택지는 잘리지 않도록 한다. 필드 순서는 모바일과 동일하다. 새 서비스·플랫폼·전화번호 필드를 추가하지 않는다. 필수 여부는 기존 인계 기준에 따라 운영 검수에서 확정한다.

동의 문구와 `/privacy/` 링크는 제출 버튼 바로 위에 둔다. `报价与执行条件将在资料及服务范围确认后沟通。`는 버튼 아래에 보존한다. 향후 미리보기에서는 실제 전송 없이 동작을 확인하고, 운영 화면의 접수 완료는 서버 확인 후에만 표시한다.

고객 유형·창고와 시스템 끝의 반복 견적 버튼은 생략한다. 공통 헤더의 견적 진입점을 유지하며 푸터는 V4의 텍스트 앵커를 사용한다. 메뉴에 8개 영역을 모두 늘어놓지 않고 V4의 5개 메뉴를 유지한다. 모바일은 로고·메뉴·견적 진입점을 간결하게 배치하며, 추가 하단 고정바가 폼을 가리는 구성을 피한다.

고정 헤더가 도착한 섹션 제목을 가리지 않게 여백을 확보하고, 키보드 이용자도 도착 지점을 알 수 있게 한다. 서비스나 견적으로 이동할 때 히어로의 스크롤 완료를 강제하지 않는다. 서비스·문의용 별도 경로는 만들지 않는다.

레이아웃의 간결함을 위해 서비스 인계 책임, 플랫폼 비인증 안내, IOR·HS·FDA·FCC의 확인 조건, 실제 시스템 지원 범위, 최소 과금·추가 비용을 제거하지 않는다. 내용 승인 전에는 이 문서의 축약 제안을 V4 원문 확정 변경으로 취급하지 않는다.

## 6. 구현 시 확인할 기준

- 방문자는 첫 화면에서 회사의 역할을 이해하고 #services 또는 #quote로 바로 이동할 수 있다.
- 스크롤 영상은 전진·역방향·정지 프레임 유지가 가능하고, 자동재생과 구분된다. 레퍼런스의 정적 캡처만으로 이 동작이 검증됐다고 주장하지 않는다.
- 서비스 범위와 고객 유형의 설명이 다른 역할을 수행하고 8개 영역의 핵심 정보가 빠지지 않는다.
- 실제 사진·시스템 자료가 없어도 완결된 텍스트 배치가 가능하다. 가짜 증빙이나 빈 자료 카드를 만들지 않는다.
- 중문 데스크톱·모바일에서 제목·조건·표·폼을 잘림 없이 읽을 수 있고 본문은 모션 완료를 기다리지 않아도 보인다.
- #services·#quote 등은 페이지 내 이동이며 `/privacy/`만 독립 페이지로 유지한다.

이 문서는 전체 구조의 계획 기록이다. 후속 작업에서 V5 로컬 구현과 브라우저 검증을 진행했으며, 공개 배포는 하지 않았다.
