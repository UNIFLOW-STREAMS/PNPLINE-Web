## 1. 디자인 해석과 적용 범위

중국 판매자가 미국 창고·물류 서비스를 비교하고 견적을 요청하는 B2B 랜딩이다. 큰 물류 장면과 선명한 중문 제목으로 시작하고, 정돈된 본문에서 작업 범위·운영 확인 사항·비용 조건을 읽게 한다.

디자인 방향은 **물류 장면의 몰입감과 읽기 쉬운 중문 정보 구조의 결합**이다. 공식 브랜드와 V4 내용을 보존하면서 기존 시안의 구도·타이포그래피·서비스 표현을 다시 설계한다. 특정 UI 프레임워크의 공식 디자인 시스템을 표방하지 않는다.

- DESIGN_VARIANCE: 6. 좌측 정렬과 비대칭 열을 사용하되 탐색 순서는 명확하게 유지한다.
- MOTION_INTENSITY: 4. 사용자 입력에 반응하는 히어로 영상이 중심이며, 본문은 즉시 읽힌다. 버튼·폼 상태 변화만 짧게 처리한다.
- VISUAL_DENSITY: 4. 설명은 충분히 남기고 제목·행간·영역 간격으로 밀도를 조절한다.

## 3. 브랜드와 색상

### 공식 로고

- 원본: `resources/logo/PNP-LINE.webp`. 비율·청록색과 회색·글자 형태를 그대로 사용한다.
- 제안 표시 폭: 데스크톱 144px, 모바일 120px, 359px 이하 104px. 세로 크기는 원본 비율에 따른다.
- 외부 안전 여백은 최소 12px. 원본 내부 여백은 자산을 잘라 제거하지 않는다.
- 밝은 헤더 위에 배치한다. 어두운 테마에서는 로고 주변에 밝은 중성 면을 둔다. CSS 필터로 흰색 로고를 만들지 않는다.
- 확인한 `resources/cargo-brand-color.png`는 다른 회사명이 포함된 참고 이미지이므로 공식 PNPLINE 자산으로 사용하지 않는다.

## 4. 중문 타이포그래피

제목과 본문 모두 **Noto Sans SC**를 사용한다. 기존 로컬 400·500·600·700 자산을 활용할 수 있으며 전체 V4와 상태 문구의 글리프 포함 여부는 구현 때 확인한다. 중국어 글리프를 지원하지 않는 영문 폰트로 제목을 지정하지 않는다. 대체 글꼴은 PingFang SC, Microsoft YaHei, sans-serif 순서로 한다.

| 요소 | 데스크톱 기준 | 모바일 기준 | 공통 규칙 |
| --- | --- | --- | --- |
| H1 | 56~64px / 600 / 행간 1.2 | 30~36px / 600 / 1.25 | 좌측 정렬. 2행 기준, 작은 화면은 자연스러운 의미 단위 줄바꿈 허용 |
| H2 | 36~44px / 600 / 1.35 | 26~30px / 600 / 1.4 | 제목 다음에 소개 문단. 긴 중문 제목을 한 줄에 억지로 넣지 않음 |
| 서비스·묶음 제목 | 22~24px / 500 / 1.45 | 20~22px / 500 / 1.5 | 서비스 이름 전체 표시 |
| 본문 | 17~18px / 400 / 1.75 | 16px / 400 / 1.75 | 읽기 폭은 기본 28~36em. 숫자·약어도 같은 서체 |
| 버튼 | 16px / 500 / 1.4 | 15~16px / 500 / 1.4 | 버튼 문구는 한 줄 |
| 라벨 | 15px / 500 / 1.5 | 동일 | 입력창 위에 고정 |
| 도움말·동의 | 14px / 400 / 1.65 | 동일 | 공간을 줄이기 위해 작게 만들지 않음 |

자간은 기본 0, 큰 제목에서만 -0.01em까지 허용한다. 영문 대문자 스타일의 넓은 자간·압축 서체·세리프 강조를 중문에 적용하지 않는다. 제목 안의 강조는 같은 서체의 굵기로 표현한다.

H1 줄 구성의 기준은 다음과 같다. 문자는 V4와 동일하다.

```text
美国自营海外仓，
衔接出货与订单履约
```

H1은 최대 약 680px 폭을 확보한다. 모바일 320px에서는 좌우 16px와 30px 제목을 기준으로 하여 9자인 두 번째 행이 들어갈 공간을 확보한다. 글자 확대 또는 대체 글꼴에서는 고정 줄 수보다 내용 보존을 우선하고 높이를 늘린다. 원고를 잘라 말줄임표로 처리하지 않는다.

## 5. 여백·열·모양

| 항목 | 데스크톱 | 태블릿 | 모바일 |
| --- | --- | --- | --- |
| 기준 폭 | 1200px 이상 | 768~1199px | 767px 이하 |
| 본문 최대 폭 | 1320px | 가용 폭 | 가용 폭 |
| 좌우 여백 | 48~64px | 32px | 20px, 359px 이하는 16px |
| 일반 영역 상하 여백 | 각 96px | 각 72px | 각 56px |
| 제목과 소개 문단 | 20px | 20px | 16px |
| 소개와 본문 묶음 | 40~48px | 32px | 28px |
| 열 간격 | 32px | 24px | 1열 |
| 필드 사이 간격 | 세로 24px / 가로 24px | 동일 | 세로 24px |
| 헤더 높이 | 72px | 64px | 64px |

일반 간격 단위는 8·12·16·24·32·48·64·96px다. 상담 절차처럼 짧은 영역은 데스크톱 상하 64px, 모바일 40px로 압축한다. 본문 전체를 한 화면 높이씩 늘리지 않는다.

본문의 제목·설명은 같은 축에 세로로 묶는다. 실제 상세 내용, FAQ 목록, 폼이 오른쪽에 오는 2열은 사용할 수 있다. 제목 옆 빈 공간을 짧은 장식 문장으로 채우지 않는다.

모서리는 모두 직각(0px)으로 통일한다. 헤더·버튼·입력·이미지·폼에 동일하게 적용하고, 구분은 면·선·간격으로 만든다. 큰 그림자·유리 패널·장식 배지는 사용하지 않는다. 번호는 실제 상담 순서를 표시할 때만 보조적으로 사용한다. 영역마다 영어 소제목과 장식 번호를 붙이지 않는다.

## 6. 버튼과 이동

- 주 행동: 청록 채움 + 짙은 글자. 문구는 `获取物流报价`, 목적지는 #quote로 통일한다.
- 서비스 행동: `查看服务范围` → #services. 히어로에서는 밝은 불투명 면 + 짙은 글자, 본문에서는 짙은 밑줄 링크를 사용한다.
- 제출 행동: `提交询价需求`. 견적 앵커 이동과 실제 제출을 구분한다.
- 버튼 높이: 본문 데스크톱 52px, 모바일 48px, 헤더 44px. 좌우 안쪽 여백은 24px, 좁은 헤더에서는 12~16px.
- 히어로 버튼 간격 12px. 375px 미만에서는 1열로 쌓고 각 버튼을 가용 폭으로 넓힌다. 버튼 글자를 줄이거나 두 줄로 나누지 않는다.
- hover는 채움·밑줄, pressed는 채움 변화로 표현한다. 상태 전환은 160ms 이내. 버튼이 포인터를 따라 움직이지 않는다.
- 키보드 focus는 3px 외곽선과 3px 간격. 영상 위에서는 밝은 외곽선과 짙은 보조 경계를 함께 써 장면 변화에도 식별한다.
- 내부 앵커 도착 시 제목이 헤더 아래에 나타나도록 헤더 높이 + 24px의 공간을 둔다. 키보드 탐색에서도 도착 지점을 인지할 수 있게 한다.

데스크톱 헤더는 로고와 V4 메뉴 `服务范围 / 仓库与系统 / 费用说明 / 常见问题 / 获取物流报价`를 한 줄로 배치한다. 1024px 미만은 로고·견적 버튼·메뉴 버튼으로 전환한다. 모바일 메뉴에는 V4 링크를 모두 제공하고 히어로의 서비스 버튼은 계속 보인다. 별도 하단 고정 CTA는 추가하지 않는다.

주 견적 CTA는 헤더·히어로·서비스 끝·비용 끝에 둔다. 각 영역마다 반복 배치하지 않는다. `/privacy/`는 독립 페이지로 유지하고 개인정보 페이지에서 견적으로 돌아갈 때는 `/#quote`를 사용한다.

## 7. 히어로의 문구와 영상

첫 화면은 영상 위의 브랜드 설명, H1, V4 첫 보조 문단, 주·보조 CTA로 구성한다. 두 번째 보조 문단은 앞선 섹션 계획대로 서비스 도입부로 옮긴다. 영문 단어 수 제한을 중문 원고에 기계적으로 적용해 내용을 삭제하지 않는다.

### 구도

- 데스크톱: 영상은 전체 폭. 텍스트는 본문과 같은 왼쪽 정렬선, 폭 최대 680px. H1 아래 설명은 약 560px 안에서 읽히게 한다. 영상의 주요 피사체를 피해 텍스트 안전 영역을 잡는다.
- 모바일: 같은 제목·설명·행동 위계를 유지한다. 텍스트는 화면 폭에 맞춘 고정된 영역에 배치하고 영상 크롭을 별도로 조정한다. 영상 프레임마다 텍스트가 다른 위치로 움직이지 않는다.
- 첫 화면에서 H1·설명·두 CTA에 접근할 수 있게 한다. 320×568처럼 높이가 낮을 때는 위아래 여백과 제목 크기를 먼저 조정하고, 강제 최소 높이로 버튼을 화면 밖으로 밀지 않는다. 글자 확대·가로 모드에서는 일반 문서 흐름으로 늘어날 수 있게 한다.

### 가독성

- 영상 위 글자는 #FCFDFD. 텍스트 전체 영역 뒤에 #102A33 계열의 어두운 scrim을 둔다. 바깥쪽으로만 점차 투명해지게 한다.
- 텍스트 영역에서는 약 80% 불투명도를 초기 기준으로 삼고, 그 영역 안에서 가장 밝은 장면이 와도 본문 대비 4.5:1 이상, 목표 7:1을 확보한다. 78% 어두운 면이 흰 장면 위에 놓인 근사 배경 #455961과 글자 #FCFDFD의 계산 대비는 약 7.22:1이다.
- 이 계산은 색상 조합의 근거다. 실제 영상 위 합성·글자 위치·프레임 전환을 검증했다는 뜻은 아니다. 최종 배치에서는 시작·중간·끝과 밝은 장면·어두운 장면·전환 장면 모두 확인한다.
- 영상 전체를 동일하게 어둡게 만들지 않는다. 텍스트 외 영역에서 영상이 충분히 보이도록 조정한다. 텍스트 그림자만으로 대비를 해결하지 않는다.
- 모바일 크롭 때문에 글자와 주요 장면이 계속 겹친다면 텍스트 부분을 같은 색의 불투명 면으로 처리한다. 정보와 CTA를 줄이지 않는다.

### 스크롤과 접근성

스크롤 진행도에 대응하는 영상 시점으로 이동한다. 아래로 스크롤하면 뒤 시점, 위로 스크롤하면 앞 시점, 정지하면 현재 프레임을 유지한다. 자동재생·루프·재생 버튼을 추가하지 않는다. 실제 매핑 시간은 전달된 최종 영상 명세에 따른다.

히어로가 고정된 동안 텍스트·CTA는 읽을 수 있는 위치를 유지한다. 장면별 해설 캡션을 넣거나 글자를 순차적으로 나타나게 하지 않는다. 고정 구간이 끝나면 서비스 영역이 일반 문서 흐름으로 이어진다.

서비스·견적 링크는 영상 로드 또는 전체 구간 감상 완료와 무관하게 사용할 수 있다. 앵커 이동에서 긴 구간을 부드럽게 통과하며 모든 프레임을 재생하지 않고 목적지로 바로 이동한다. 뒤로 스크롤할 때 영상 매핑을 복원한다.

모션 감소·미디어 실패에서는 대표 이미지와 일반 콘텐츠로 전환하고 긴 고정 구간을 해제한다. 히어로의 영상 품질·렌더·연출 완성도는 디자인 점수에 포함하지 않는다. 평가 대상은 글자 대비, 구도, 크롭에 따른 가독성, 시점 제어, 버튼 접근성이다.

전체 순서는 기존 섹션 계획을 유지한다. 서비스·비용은 제목 아래로 내용을 펼쳐 이전 계획의 반복적인 왼쪽 제목 열을 줄인다. 비교 행, 실제 자료, 3단 절차, 비용 표, FAQ, 폼이 각 정보의 성격에 맞는 차이를 만든다. 색이나 서체를 바꿔 구분하지 않는다.

본문에는 숨겨진 진입 애니메이션이나 장시간 고정 스크롤을 추가하지 않는다. 서비스 선택 범위·IOR와 통관의 확인 조건·플랫폼 비인증 안내·시스템 지원 범위·최소 과금·추가 비용은 읽을 수 있는 위치에 보존한다.

## 9. 입력 폼

- 순서: 产品类目 → 发货方式 → 月出货量 → 目的地 → 是否需要IOR服务 → 联系邮箱.
- 768px 이상은 2열 3행, 미만은 같은 읽기 순서의 1열. 폼이 차지할 수 있는 폭이 좁으면 태블릿에서도 1열로 전환한다.
- 라벨은 입력 위, 도움말·오류는 입력 아래. placeholder는 예시로만 사용한다.
- 필드 높이는 최소 52px, 입력 글자 16px, 내부 좌우 여백 16px, 직각 윤곽. 긴 목적지 옵션은 잘리지 않게 선택 목록과 선택 후 표시 방법을 검증한다.
- 기본 윤곽 #7B8B90, hover는 짙은 색, focus는 해당 테마의 focus 색과 외곽선. 상태를 색만으로 구분하지 않는다.
- V4의 `未定`·`不清楚` 옵션을 유지하고 서비스·판매 플랫폼·전화번호 같은 새 필드를 추가하지 않는다. 필수 항목은 운영 확정에 맞춘다.
- 동의 영역은 폼 전체 폭으로 배치한다. 체크박스 자체는 약 20px, 연결된 라벨 포함 터치 영역은 최소 44px. 동의 문구는 V4 기준을 유지한다.
- 개인정보 링크는 입력값을 잃지 않고 확인할 수 있게 설계한다. 제출 버튼은 동의 아래, 견적 조건 안내는 버튼 아래에 둔다.
- 빈 상태: 라벨·도움말·미정 선택지로 시작한다. 오류: 해당 필드 아래 설명과 입력값 보존. 제출 중: 버튼 크기를 유지하고 중복 제출을 막음. 접수 완료: 실제 서버 확인 뒤 상태 표시.
- 디자인 미리보기에서는 전송하지 않는다. 완료 문구를 실제 접수처럼 표시하지 않는다.
