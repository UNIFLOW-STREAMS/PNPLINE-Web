### 3. 실행 도구와 스킬

Codex 실행 환경에 실제 설치된 스킬과 사용 가능한 도구부터 확인하라. 이름만 적고 사용했다고 보고하지 마라.

우선 활용할 기능은 다음과 같다.
- creative-production/produce 또는 동등한 시각 제작 스킬: 무드보드, 스타일프레임 비교, 공통 스타일 유지. 설치되어 있으면 해당 SKILL.md를 읽는다. 일반적인 다안 탐색 기본값보다 이 작업의 3안·선택 방향 고정을 우선한다.
- imagegen 또는 기본 이미지 생성·편집 도구: 실제 정지 스타일프레임과 키프레임 제작. Codex의 추론 모델과 이미지 생성 모델은 구분해 기록한다. 장면 생성과 정확한 로고 재현을 분리하고, 로고는 원본 자산을 이용한 재현 가능한 합성을 우선한다.
- 이미지 합성 기능: 현재 환경에서 사용 가능한 편집·레이어 합성 도구 또는 기존 설치 라이브러리로 공식 로고의 투명도·비례를 보존하고 표면 원근·가림을 적용한다. 새 유료 도구나 전용 플러그인 도입을 전제하지 않는다. 시각 제작 스킬에 원본 보존·정확한 콘텐츠 처리 지침이 있다면 관련 부분을 읽는다.
- playwright 또는 playwright-interactive에 해당하는 브라우저 검증 스킬: 검토 페이지, 스크러빙, 모바일 구성, reduced-motion 확인.
- screenshot 또는 동등한 캡처 기능: 검토 화면과 오류의 시각적 증거 저장.
- openai-docs 또는 공식 문서 조회 기능: 사용하는 이미지 도구의 지원 규격·옵션을 확인해야 할 때만 사용.
- FFmpeg는 설치되어 있을 때 러프 animatic 내보내기에만 선택적으로 사용한다. FFmpeg 자체를 스킬이라고 보고하지 마라.

Higgsfield 등 외부 도구를 쓰더라도 이번 범위는 정지 이미지다. 영상 생성 워크플로를 자동 실행하지 마라.
새 유료 API·계정·과금 경로는 승인 없이 사용하지 마라. 이미 승인된 도구 범위 안에서 실행하고, 별도 예산이 없으면 유료 우회 경로를 임의로 선택하지 마라.
비밀키를 파일·로그·최종 응답에 기록하지 마라.

이미지 생성이 불가능하면 문서·구도 설계·마스크·프리뷰 골격까지 만들고, 실제 이미지 산출물은 blocked 또는 missing으로 표시하라.
CSS 박스, SVG 아이콘, 도식, 플레이스홀더를 산업형 미니어처 스타일프레임으로 제출하지 마라. 기술 도식은 마스크·카메라·전환 설명용으로만 사용한다.

### 4. 수정된 미술 방향 — 브랜드 강조형 산업 미니어처

선택 방향은 **`daylight logistics — brand-led industrial miniature`**다. 기존의 정밀 산업 미니어처를 유지하되, 익명의 물류 모형이 아니라 PNPLINE의 브랜드가 공간·동선·주요 객체에서 읽히는 캠페인형 물류 세계로 만든다. 미술 방향에 대한 사용자 지시는 확정됐지만, 앞으로 생성할 개별 자산의 시각 승인까지 받은 것은 아니다.

#### 4.1 첫 번째 이미지에서 가져올 것과 가져오지 않을 것

`REF-STYLE-01`을 다음 특성의 참고로 사용한다.
- 약간 높은 사선 시점에서 전경의 항만·컨테이너, 중경의 운송 수단, 후경의 연결 동선과 창고가 겹쳐 보이는 깊이 있는 구성.
- 흰색·라이트그레이 콘크리트와 딥네이비 산업 구조물, 정돈된 랙·박스, 금속·유리·물의 절제된 반사가 만드는 깨끗한 건축 시각화 수준의 질감.
- 창고 단면 또는 열린 파사드로 내부 물류 과정이 읽히는 구조.
- 넓고 명확한 경로 면, 완만한 곡선과 대각선이 방문자의 시선을 다음 공간으로 안내하는 방식.
- 주요 컨테이너·창고 파사드·운송 수단에 브랜드가 읽히게 배치된 방식. 배경 구석의 작은 로고만으로 브랜딩을 끝내지 않는다.
- 작은 작업자와 장비가 주는 축척감, 과도한 블러 없이 전·중·후경을 구별할 수 있는 심도, 하늘·수면·벽면 등의 여백.

다음은 따라 하지 않는다.
- 참고 이미지의 녹색 브랜드 도색·경로색·사선 두 줄 심벌·다른 형태의 PNPLINE 글자. 색과 로고의 기준은 `REF-LOGO-01`과 기존 토큰이다.
- 특정 도시·교량·항만·시설의 식별 가능한 복제 또는 실제 지리·자산 소유·노선의 주장.
- 한 이미지에 항만·항공·창고·배송을 전부 같은 비중으로 쌓아 넣는 구성. 6장면은 각 단계의 공정이 먼저 읽혀야 한다.
- 참고 이미지의 물리적·공정상 부자연스러운 연결. 물 위의 장식 경로, 이동 수단의 크기 불일치, 동선 충돌 등을 그대로 정답으로 채택하지 않는다.
- 첫 이미지를 그대로 복사해 로고와 초록색만 교체한 결과. 고유한 6장면과 별도 모바일 구도를 설계한다.

#### 4.2 고정할 조형·색·카메라 문법

- **표현:** 정밀한 산업형 미니어처이면서 프리미엄 브랜드 캠페인형 CGI의 정돈된 완성도. 장난감 플라스틱, 수공예 모형, 클레이·저폴리·아이소메트릭 아이콘 스타일로 바꾸지 않는다.
- **축척:** 약 1:87–1:100의 축척감을 지향한다. 이는 연출 지침이며 정확한 물리 축척을 측정했다는 뜻이 아니다. 작은 작업자·장비 비례·공간 깊이로 미니어처임을 읽히게 한다.
- **조명:** 밝고 흐린 낮의 부드러운 산업광과 절제된 자연 그림자. 재질을 읽을 수 있는 명암은 유지한다. 6장면에 같은 시간대의 외부광을 유지하고 실내 보조광만 조정한다.
- **재질:** 무광·반무광 금속, 밝은 콘크리트, 골판지, 반투명 포장 필름, 도장 컨테이너, 고무 바퀴, 철제 랙. 청결함을 유지하되 모든 표면을 유광 플라스틱이나 비현실적인 거울로 만들지 않는다.
- **기본 색:** 화이트·라이트그레이 공간 + 딥네이비 구조물 + 크라프트 박스. 기존 저채도 컨테이너 색은 보조로 남길 수 있으나 브랜드 블루와 경쟁하지 않게 한다.
- **브랜드 블루:** `#00ABE1`을 경로 테이프·선뿐 아니라 읽기 쉬운 경로 면, 선택한 컨테이너·차량 패널·브랜드 표식에 사용할 수 있다. 배경 전체를 블루로 틴팅하거나 모든 객체를 같은 블루로 칠하지 않는다.
- **녹색:** 나무·자연 식생과 필요한 기존 안전·상태 의미에는 남길 수 있다. PNPLINE의 브랜드 경로·로고·주 도색으로 참고 이미지의 녹색을 가져오지 않는다. 디자인 토큰의 성공 상태 녹색도 변경하지 않는다.
- **구도:** 전경·중경·후경의 층위와 대각선·완만한 S자 동선으로 하나의 연결된 세계를 만든다. 선정안의 기준 시점은 살짝 내려다보는 3/4 medium-wide이며, 완전 탑다운은 비교안 C에 한정한다.
- **심도:** 매크로·틸트시프트의 축척감은 살리되 핵심 공정·대표 로고·경로·텍스트 주변을 읽을 수 있는 충분한 심도를 확보한다. 강한 블러 자체를 미니어처의 증거로 삼지 않는다.
- **사람:** 소수의 작은 PPE 착용 작업자는 축척과 공정 설명에만 사용한다. 식별 가능한 얼굴·과장된 인물 주인공은 없다.
- **브랜드 우선순위:** 대표 키프레임에서는 핵심 물류 동작과 함께 주 브랜드 표식이 읽혀야 한다. 창고 간판이나 전경 컨테이너 측면 등 자연스러운 주 표면에 충분한 크기로 배치하고, 다른 표식은 보조로 정리한다. 큰 로고 자체를 금지하지 않는다. 로고를 모든 박스·벽·차량에 동일 크기로 반복하거나 공정을 가리는 것은 금지한다.
- **이동:** 카메라는 느린 한 방향 전진. 경로선과 컨테이너 모서리·기둥·랙·박스 벽의 전경 가림으로 다음 장면에 연결한다. 급회전·별도 역주행 연출·과도한 줌을 금지한다. 사용자의 역스크롤로 기존 타임라인을 역시킹하는 동작은 별개다.

대표 로고의 읽힘, 주요 물류 동작, UI 카피는 함께 성립해야 한다. 서로 충돌하면 카메라·객체 배치·브랜드 표면·여백을 조정한다. 로고를 거의 안 보이게 축소하거나 공정을 지우는 방식으로 타협하지 않는다. 구체적인 표식 수·면적 비율을 사용자 승인 수치처럼 만들지 마라.

#### 4.3 두 번째 이미지의 공식 로고 적용

`REF-LOGO-01` / `PNP-LINE.webp`만 로고 원본으로 사용한다.

1. PNP의 블루, LINE의 그레이, 글자 형태·결합·간격·비례를 원본대로 유지한다. 텍스트 폰트로 다시 쓰기, AI 재생성, 임의 트레이싱·리디자인, 일부 글자만 분리한 새 심벌, 참고 이미지의 사선 심벌 추가를 하지 않는다. 파일명의 하이픈을 워드마크에 추가하지 않는다.
2. 알파 투명도를 유지한다. 원본은 그대로 보존하고 필요하면 투명 여백만 줄인 파생 파일을 만든다. 캔버스 전체 1500×400의 비율과 실제 보이는 로고의 비율을 혼동하지 않는다. 여백 정리·균등 리사이즈는 허용하지만 글자 획이나 간격을 잘라내거나 늘리지 않는다.
3. **권장 파이프라인:** 로고를 넣을 비어 있는 표면을 설계해 장면을 생성 → 가짜 로고·문자 부재 확인 → 공식 원본을 별도 레이어로 합성 → 표면 원근·가림·재질 반응 조정 → 원본 대비 시각 검증. 생성 프롬프트로 “비슷한 PNPLINE 로고”를 그리는 것을 정확한 적용으로 인정하지 않는다.
4. 건축물·컨테이너·차량 표면의 투시를 따른 합리적인 원근 변환은 허용한다. 원근 변환 전 소스 로고의 비례는 유지한다. 거울 반전·글자 누락·오탈자·비균등 글자 변형·과도한 블러는 허용하지 않는다.
5. 어두운 파사드에서 그레이 LINE이 묻히면 밝고 중립적인 간판 패널이나 더 적합한 표면을 사용한다. 원본 외의 흰색 반전 로고·단색 로고·녹색 로고를 임의로 만들지 않는다. 별도 공식 변형이 필요하면 미확정 사항으로 남긴다.
6. S01 주 컨테이너·물류 거점 간판, S04 창고 파사드, S06 출고 차량 등에 눈에 띄는 적용을 허용한다. S02의 선박·항공기에도 상징적 브랜드 적용이 가능하지만, PNPLINE의 실제 보유 선박·항공기·전용 터미널·확정 노선을 증명하는 것으로 설명하지 않는다.
7. 로고가 표면에 붙어 보이도록 하고, 공간과 무관한 화면 고정 스티커로 대체하지 않는다. 단순 정지 이미지 animatic에서는 최종 합성 프레임 전체와 로고가 함께 움직이면 된다. 실제 동영상의 로고 추적·시간적 안정성은 #24에서 검증할 항목이다.
8. 합성 소스 해시·표면·위치·원근·레이어 관계를 추적 가능하게 기록한다. 저해상도 원본을 AI로 다시 그려 고해상도 공식 로고라고 만들지 않는다. 합성 크기에서 선명도가 부족하면 필요한 원본 규격을 보고하고 해당 항목을 미해결로 남긴다.

#### 4.4 카피와 사실성의 경계

중요한 중국어 카피, 단계명, CTA, `概念示意` 캡션은 별도 HTML/UI 텍스트다. 장면 내부에 합성한 공식 로고는 이 “카피를 굽지 않는다” 규칙의 예외다. 로고 사용을 금지하는 것으로 해석하지 않는다.

산출물 명칭을 구분한다.
- `base scene`: 로고·웹 카피를 넣기 전 생성한 장면.
- `clean branded keyframe`: 공식 로고까지 합성한, 웹 카피·UI·검토 마스크 없는 최종 정지 키프레임.
- `review overlay`: clean branded keyframe 위에 중국어 카피·CTA·캡션·마스크를 표시한 검토 화면.

모든 장면은 PNPLINE의 물류 서비스를 설명하는 **상징적 브랜드 세계**다. 로고가 있다고 해서 실제 소유 시설·선단·항공사·창고 규모·자동화 수준·처리량을 주장할 수 없다. 리뷰에는 `概念示意`를 명확히 표시하고 공개·운영 사실 검수 상태를 분리한다. 실제 증빙 영역에 전용하지 않는다.

검토 UI에는 기존 디자인 토큰을 재사용한다. 장면의 브랜드 원색 `#00ABE1`과 UI CTA·포커스 색 `--action-primary` / `--focus-ring`의 `#007FA8`을 혼동하지 마라. 이번 작업 때문에 토큰 원본이나 공통 UI 브랜딩을 바꾸지 않는다.

### 6. 실제 제작 순서

#### A. 출처가 추적되는 무드보드

조명, 재질, 축척감, 항만·창고 공간, 카메라, 경로·가림 전환, 브랜드 표면을 설명하는 시각적 무드보드를 만든다.
첫 번째 첨부 이미지는 시각 스타일 참고, 두 번째는 로고 원본으로 역할을 분리한다. “가져올 요소 / 제외할 요소 / PNPLINE 블루와 공식 로고로의 적용 방법”을 함께 보여 준다.
단순 URL 목록으로 끝내지 말고, 허용된 이미지·자체 생성 스터디·재질 및 색상 견본을 이용해 비교 가능한 보드로 구성한다. 참고 이미지의 녹색을 새 브랜드 팔레트로 등록하지 마라.

각 항목에 원문 URL, 창작자/권리자(확인 가능할 때), 확인일, 라이선스·이용 조건과 근거, 사용 목적, 가져올 요소와 배제할 요소를 기록한다.
출처·권한 불명 또는 워터마크가 있는 원본은 링크 참고로만 남기고 저장소·내보내기 파일에 재배포하지 마라. 워터마크 제거로 해결하지 마라.
사용자 첨부는 `user_supplied`로 구분하고 입력 ID·파일 해시·이번 대화에서 지정한 용도를 기록한다. 사용자 제공 원본은 로컬 검토용으로 다루고, 재배포 권한이 확인되지 않은 스타일 참고 원본을 공개 저장소·공개 산출물에 포함하지 않는다. 그 경우 공개본에서는 출처·설명과 직접 만든 스터디로 대체한다.
자체 생성 항목은 `generated`로 구분하고 생성 정보로 추적한다. 공식 로고의 후합성 결과는 `composited`로도 표시한다. 참조를 특정 보호 이미지의 복제 지시로 사용하지 마라.

#### B. 장면 1 스타일프레임 3안

동일한 장면과 비교 가능한 크기로 실제 이미지 3장을 제작한다.
A: daylight logistics — brand-led industrial miniature — 선택된 방향.
B: dusk cinematic — 비교용 미선택 방향.
C: top-down technical — 비교용 미선택 방향.

기존 이슈의 3안 비교 범위는 유지한다. 모든 안에 같은 공식 로고와 브랜드 원색을 사용하고, B는 조명·C는 카메라 관점만 비교 목적에 맞게 바꾼다. 이번 요청을 3개 신규 브랜딩 방향이나 추가 이미지 세트의 자동 승인으로 확대하지 마라.
각 안의 장단점을 물류 가독성, 축척감, 브랜드 인지, 로고 재현 충실도, 카피 공간, 6장면 확장성과 모바일 구성 관점에서 기록한다.
3안은 결정 근거를 보여 주는 비교 자료다. B·C의 조명이나 카메라를 선택된 6장면에 섞지 마라.
A가 품질 기준을 충족하는지 자체 검토하고 필요한 부분만 수정한 뒤 공통 기준 이미지로 사용한다. 방향 승인을 다시 요청하며 작업을 중단하지 마라.
기존 이미지를 편집할 때는 실제 참조 파일이 존재하고 사용 가능한지 확인한다. 이름만 있는 승인 이미지를 있다고 가정하지 마라.

#### C. 데스크톱 6장 + 모바일 6장

선택된 방향으로 S01–S06의 데스크톱 16:9 키프레임 6장과 모바일 9:16 키프레임 6장을 제작한다. 제출 기준은 공식 로고를 정확히 합성한 `clean branded keyframe`이다. 로고가 없는 base scene을 브랜드 적용 완료 이미지로 제출하지 않는다.
모바일은 주요 객체 배치, 깊이, 시선 흐름, 대표 로고 표면·크기, 텍스트 공간을 별도 설계한다. 데스크톱 중앙 크롭이나 object-fit: cover만으로 대체하지 마라. 가로형에서 읽히던 로고가 세로형에서 잘리거나 글자가 뭉개지면 별도 구도·표면으로 조정한다.
생성 도구가 지원하는 크기를 사용하고 원본·검토용 export의 실제 크기를 기록한다. 정확한 비율 보정이 필요하면 재구성·여백 확장을 우선하고 왜곡 확대를 하지 마라. 이 크기를 최종 납품 해상도로 확정하지 마라.

선택된 S01 이미지를 desktop S01로 재사용해도 된다. 같은 자산을 두 번 생성한 것처럼 계산하지 말고 manifest에서 재사용 관계를 명시한다. 로고 후합성·마스크·UI 캡처는 별도 생성 모델 호출로 세지 않는다.
base scene, 공식 로고 소스, 재현 가능한 합성 정보, 최종 키프레임의 관계를 보존한다. 최종본만 남기고 로고 출처와 합성 과정을 잃지 마라.
기준 이미지를 잠근 뒤 장면을 확장하고, 매 장면 결과를 실제로 열어 확인한다. 동시 생성은 실행 도구의 허용 범위 안에서만 진행한다.
실패한 자산만 제한적으로 재시도한다. 기본적으로 자산당 최초 시도 포함 2회 이내로 진행하고, 추가 시도가 필요하면 이유와 미해결 항목을 남긴다.

#### D. Safe-area 마스크

최종 검토 대상 키프레임 12장 각각에 별도 마스크를 만든다.
공식 로고가 포함된 clean branded keyframe, 마스크 파일, 텍스트를 올린 검토 화면을 구분한다. 여기서 “clean”은 웹 카피·검토 UI가 없다는 뜻이며 로고 제거를 뜻하지 않는다.

마스크에는 제목·본문·CTA 허용 영역, 중요 객체 보호 영역, 대표 로고 보호 영역, 경로선 보호 영역, 헤더·모바일 하단 UI와의 간섭 영역을 표시한다.
기준 이미지 크기와 좌표 원점, 정규화 좌표 [0,1], 영역 용도를 기계가 읽을 수 있게 기록한다. 마스크와 프리뷰는 같은 데이터를 사용한다.
실제 중국어 카피와 기존 타이포·헤더 토큰을 올려서 검토한다. 승인 카피가 없으면 검토용 임시 문구로 표시하고 새로운 서비스 약속·수치를 만들지 마라.
안전 영역을 확보하려고 핵심 물류 동작이나 대표 로고를 읽을 수 없게 밀어내지 마라. 카피가 로고를 덮거나 경로선과 겹치면 배치부터 조정하고, 장면마다 달라지는 여백을 마스크에 반영한다.

#### E. 저해상도 scroll animatic

#61의 animatic을 정지 키프레임과 단순 레이어 모션으로 구현한다. 기본 산출 형식은 독립 HTML 모션 보드다.
MP4 내보내기는 도구가 준비되어 있을 때 추가하는 선택 항목이며, 최종 생성 비디오가 아니다.

데스크톱·모바일 각각 다음을 검토할 수 있어야 한다.
- 스크롤 또는 키보드로 조작 가능한 progress slider로 6장면을 앞뒤로 탐색.
- 장면 번호, 전체 진행도, 검토용 가상 재생 시간 표시.
- 일관된 전진 의도, 경로선 연결, 5개 장면 경계의 전경 가림 전환.
- 중국어 텍스트 등장·퇴장과 충분히 읽을 수 있는 정지 구간.
- 마스크 on/off, clean branded keyframe과 UI overlay 비교.
- 로고가 장면 표면과 함께 이동하는지, 가림 전환 중 로고가 이중으로 겹치거나 UI 카피와 충돌하는지 확인.
- prefers-reduced-motion에서 이동·줌·패럴랙스 없이 6개 정적 장면과 일반 콘텐츠 표시.

단순 crossfade 슬라이드쇼만 만들지 마라. 가림 객체나 별도 단순 마스크로 전환 의도를 보여 주되, 정지 이미지에 없는 실제 3D 카메라 연속성을 검증했다고 주장하지 마라.
휠·터치 기본 동작을 불필요하게 가로채거나 긴 강제 스크롤 구간을 만들지 마라.

timeline 데이터에 전체·장면별 정규화 진행 구간, 검토용 시간 구간, 텍스트 진입/퇴장, 전환 방식, 가림 객체, 다음 장면을 기록한다.
검토용 길이·해상도·스크롤 거리는 preview-only로 표시한다. 최종 영상 길이, 시킹 지연, 코덱, 대역폭 예산의 확정으로 취급하지 마라.

### 7. 프롬프트와 금지 요소 패키지

실제 생성에 사용한 다음 자료를 재사용 가능한 파일로 저장하라.
- Master prompt: 브랜드 강조형 미니어처 세계관, 참고 이미지에서 취한 공간·재질, 축척감, 조명·색·카메라, 경로색, 인물 밀도, 주·보조 브랜드 표면, 텍스트 처리. 이미지 생성 단계에서는 공식 로고를 합성할 비어 있는 표면을 요청하고 가짜 브랜드 글자·심벌을 생성하지 않도록 한다.
- S01–S06 scene delta: 공통 문법을 바꾸지 않고 장소·동작·객체·전환만 변경.
- Desktop/mobile composition delta: 같은 장면의 별도 가로·세로 구도.
- Shared negative prompt와 금지 요소 목록.
- 고정 상수와 허용 변화, 참조 자산 ID, 실제 실행 prompt와 수정 이력.
- Logo placement guide: 공식 소스, 파생 파일, 표면 선택, 보호 여백, 위치·원근·가림·레이어 규칙, 주·보조 위계와 대표 크기에서의 검토 방법.
- 재현 가능한 후합성 기록: base scene → REF-LOGO-01 적용 → clean branded keyframe. 생성 모델에 넘긴 참조 이미지와 후합성에만 사용한 원본을 구분한다.

금지 요소: 장난감 플라스틱, 수공예 모형 질감, 클레이·저폴리 스타일, 로고 도배, 공정·카피를 가리는 브랜딩, AI가 재생성한 가짜 PNPLINE 글자, 비공식 심벌·녹색 브랜드 로고, 참고 이미지의 사선 심벌, 로고 오탈자·반전·잘림·임의 변색, 식별 가능한 실제 시설·항만·주소·타사 로고, 가짜 중국어, SF 홀로그램, 네온 위주 표현, 군중, 식별 가능한 얼굴, 위험한 작업, 지저분한 창고, 기능이 깨진 물류 공정, 급회전·역주행 연출·과도한 줌.

“대형 로고 금지”, “브랜딩은 작은 표시만”, “모든 실제 브랜드 금지” 같은 이전 문구를 이번 master/negative prompt에 남기지 않는다. 큰 공식 PNPLINE 로고와 선별한 브랜드 면은 허용된다. 금지하는 것은 비공식·변형 로고, 통제되지 않은 반복과 정보 방해다.

특정 도구에 negative prompt나 seed 항목이 없으면 지원한다고 가정하지 마라. 금지 조건을 본문에 통합하고 seed는 not_available로 기록한다. 낮 조명·3/4 카메라 고정은 선정안 A와 12개 키프레임에 적용하고, 비교안 B·C의 의도된 조명·시점 차이를 오류로 처리하지 않는다.

이미지는 상징적 콘셉트다. 실제 PNPLINE 시설·노선·규모·통관 성과의 증빙처럼 쓰지 마라. `概念示意` 캡션과 중국어 카피는 검토 UI에 표시한다. clean branded keyframe에는 공식 로고만 장면 브랜드로 합성하고 웹 카피·캡션·가짜 운영 문자는 굽지 않는다.

외부 CDN·원격 이미지에 불필요하게 의존하지 마라. 기존 토큰과 문서의 상대경로가 실제로 작동해야 한다.

assets.json에는 asset_id, scene_id, direction/variant, orientation, 파일 경로, 실제 가로·세로 크기, 용량, 생성 도구·모델, prompt/reference ID, base/clean-branded/review 구분, 원본→합성본 관계, 로고 소스 ID·해시, 마스크 경로, 생성·합성·검토·승인 상태를 기록한다.
logo-placements.json에는 프레임·표면 ID, 사용한 로고 원본/파생 파일, 필요시 투명 여백 crop 정보, 기준 크기·좌표 체계, 배치 사각형 또는 표면 모서리 좌표, 원근·가림·레이어 정보, 주·보조 위계를 기록한다. 좌표는 임의 미확인 값이 아니라 실제 합성 결과와 일치시킨다. 세부 데이터 구조는 재현성과 검증 가능성을 유지하는 범위에서 조정할 수 있다.
노출된 경우에만 실제 생성 비용·시도 횟수·seed를 기록한다. 알 수 없는 값은 unknown/not_available로 구분한다.
이 manifest는 concept-review용이며 #62의 production asset manifest가 아니다.

### 9. 수용 기준, 검증과 후속 이슈 인계

필수 수용 기준을 AC별로 판정하라. 시각적 충족과 기술적 검사, 사람의 최종 승인을 구분한다.

자동 검증을 실행하라.
- 필수 파일 존재·비어 있지 않음, JSON 유효성, 내부 경로·이미지 링크 정상.
- 비교용 3안, 데스크톱 6장·모바일 6장, 최종 키프레임별 12개 마스크의 대응 관계.
- 이미지 비율·크기, 마스크 좌표 범위, 장면 ID·프롬프트·참조 연결.
- 원본 로고 파일의 무결성·알파와 파생본 관계, 최종 프레임의 logo placement 참조, 합성 정보의 좌표 범위·내부 파일 존재. 파일 검사만으로 로고의 시각적 정확성을 판정하지 않는다.
- timeline 구간의 순서와 의도하지 않은 누락·중복 여부.
- git diff --check와 저장소에서 적용 가능한 기존 검사. 실행하지 못한 검사는 별도 표시.

브라우저에서 실제로 확인하라.
- 데스크톱 1440×900, 모바일 390×844와 360×800의 레이아웃·중국어 줄바꿈·가로 넘침.
- 모든 장면, 모든 전환 경계, safe-area 토글과 UI 중첩.
- 스크롤·키보드 조작·포커스, reduced-motion에서 6개 정적 장면 접근.
- 이미지 오류 시 안내와 읽을 수 있는 콘텐츠, 콘솔 오류·깨진 링크.
핵심 상태의 스크린샷과 실제 수행한 검사 결과를 저장하라. JSON 검사 통과를 미술 품질 승인으로 대신하지 마라.

스타일 검토에서는 6장면의 동일한 낮 조명·재질·사람 밀도·축척감·전진 문법, 브랜드 강조의 일관성, 공식 로고의 형태·색·비례와 표면 합성, 물류 동작의 가독성, 로고·경로·카피의 비경쟁, 모바일 독립 구도, 실제 보유 자산·운영 성과로 오인될 요소를 확인하라. 첫 참고 이미지와 무조건 같은 구도인지가 아니라 채택한 시각 특성과 이번 수정 규칙을 충족하는지 검토한다.

#24 인계에는 S01+S02의 desktop/mobile branded 키프레임, base scene, 공식 로고 원본·합성 정보, 프롬프트, 마스크, 연결 의도와 파일럿 판정표를 제공하라. 정확한 로고를 유지할 실제 영상 제작·후합성 방식은 파일럿에서 비교·검증할 항목으로 남긴다.
판정표는 “검사 항목 / 검사 방법 / 통과 조건 / 실패 예 / #24에서 얻을 증거”로 작성한다.
카메라·물체·로고의 시간적 안정성, 로고가 표면에서 미끄러지거나 변형되는지, 장면 간 연결, UI 가독성, 모바일 구도, 실제 시킹·초기 표시·프리로드·fallback, 재생성·로고 후처리 횟수와 비용을 포함한다.
성능·비용 수치가 아직 없으면 측정 필요로 표시하고, 제안 임계값은 미승인 제안임을 명시한다.
#62에는 확정된 미술 제약과 파일럿 후에 결정할 미디어 규격을 분리해 전달하라. #42 구현을 선행하지 마라.

### 10. 완료와 보고 기준

“미술 방향 승인”, “파일 생성”, “기술 검사 통과”, “사람의 시각 승인”은 서로 다른 상태다.
daylight logistics 기반의 브랜드 강조형 방향과 사용자 지정 로고 사용은 이번 지시의 결정이다. 이번에 생성한 자산의 시각 승인이나 운영 공개 승인까지 받은 것으로 기록하지 마라. GitHub 본문·댓글은 별도 반영 요청이 없으면 변경하지 않는다.
필수 자산과 검토 기능이 준비되면 ready_for_review로 보고한다. 누락·도구 장애가 있으면 partial/blocked와 영향을 명시한다.
사람의 승인 없이 #61을 닫거나, #24가 통과했다고 처리하거나, production-ready 미디어라고 주장하지 마라. 요청받지 않은 push·PR 병합·배포를 하지 마라.

최종 응답에는 다음을 제공하라.
1. 생성·수정 파일과 바로 열어 볼 검토 페이지 경로/실행 방법.
2. 3안 비교와 브랜드 강조형 daylight logistics 적용 근거, 공식 로고의 적용 방식, desktop/mobile 핵심 구성 차이.
3. 실제 생성 자산 수, 재사용·누락 자산, 사용 도구·모델과 수행 검사.
4. 품질상 한계, 미승인 가정, 아직 검증하지 못한 항목.
5. #24의 2장면 파일럿으로 넘기는 패키지와 #62에 남긴 결정.

관련 검증은 실제 저장소에서 확인한 스크립트·도구로 수행한다. 존재하지 않는 lint·타입 검사·테스트·빌드 명령을 추측하지 않는다. 검사 체계가 없다면 그 사실과 파일·브라우저 검증 등 최소 대안을 보고한다. 검증 로그는 현재 diff/결과 커밋·브라우저 환경에 연결한다.

### 11. 중단 조건과 안전 경계

- 테스트 삭제·비활성화·규칙 완화로 통과를 꾸미지 않는다. 비밀키·실제 개인정보를 코드·로그·샘플·생성 프롬프트에 넣지 않는다.
- 기존 무관한 변경을 보존한다. 승인 없는 운영 데이터 변경·운영 배포·유료 호출·강제 push·무관한 변경 덮어쓰기를 금지한다. 별도 요청 없이 커밋·push·PR 생성/병합·이슈 종료를 하지 않는다.
- 라이브러리 추가가 필요하면 이유·영향을 먼저 보고한다. 이번 콘셉트 검토를 이유로 Three.js·실시간 3D·본서비스 GSAP 시스템을 도입하지 않는다.
- 알려진 브랜딩 규칙 변경은 2절대로 처리한다. 그 외 요구사항 충돌, 새 유료 서비스, 핵심 인터페이스 변경, 개인정보·보안·사용권 위험, 파괴적 변경 또는 범위 밖 구조 변경은 관련 작업을 멈추고 근거·영향·대안을 보고한다.
- 입력 자산 누락·원본 로고의 선명도 부족·합성 도구 부재는 해당 AC를 blocked로 표시한다. 가짜 로고로 대체하거나 완성됐다고 하지 않는다. 범위 내 작은 구도·합성 조정은 이유를 기록하고 진행한다.

일반적인 개선 제안이나 계획만 반환하지 말고 파일 제작과 검증까지 수행하라. 진행을 막는 도구·권한 문제가 있어도 가능한 범위는 완성하고, 불가능한 부분을 성공으로 위장하지 마라.
