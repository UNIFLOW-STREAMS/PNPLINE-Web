이번 작업은 #63의 A안 1종을 실제 검토 가능한 PNG 패키지로 제작하는 하위 작업이다.
B/C안, 최종 방향 선정, 프로덕션 개발, #63 전체 완료는 포함하지 않는다.

A안의 핵심은 ‘밝은 브랜드 블루를 사용하는 업무 선택형 B2B 랜딩’이다.
서비스 정체성 → 내 업무 선택 → 운영 자료 확인 → 시스템 이해 → 비용 이해 → FAQ → 견적 요청의 판단 흐름을 시각화한다.
최종 승인 대상은 PNG와 설명 문서이며, HTML/CSS는 그 이미지를 만드는 편집·렌더링 보조물이다.

사용자 입력 원문: ‘붙여넣은 마크다운(1).md’의 A안 개정안.
원문 SHA-256: 0560efa706ac3ac2e4def85b716eacc5d5cac5bd053cc2f858ad992e78468180
아래에 실행에 필요한 디자인·카피·상태·제약을 포함한다. ChatGPT 대화나 /mnt/data 경로가 Codex에 자동 공유된다고 가정하지 않는다.
원문 파일을 함께 받은 경우 표 헤더 병합·불필요한 Markdown 이스케이프만 정리하고 중국어 문구의 의미·서비스 범위는 바꾸지 않는다.

승인 상태를 구분한다.
- A안 제작 기준으로 지정된 브리프이며, 클라이언트의 최종 디자인 선택은 아니다.
- 중국어 카피는 검토용 초안이다. 사실·중국어·법무 검수를 완료했다고 표시하지 않는다.
- 현재 디자인 시스템은 초안이다. 이번에는 최신 블루 토큰을 재사용하며, 전역 명세를 A안에 맞춰 확정·변경하지 않는다.
- #61에는 daylight logistics 미술 방향의 승인 기록이 있다. 이는 개별 이미지 파일의 제작·사용 승인 완료를 뜻하지 않는다.

레이아웃 확정 뒤 파일명 정리·재캡처 같은 제한된 반복 작업은 medium을 사용할 수 있으나 동일한 수용 기준을 적용한다.

모델과 effort는 사용자의 Codex 환경에서 실제 선택 가능한 목록으로 확인한다.
이 지시서를 읽었다는 이유만으로 모델이 변경됐다고 말하지 않는다. 실제 세션 모델·effort가 확인되면 보고하고, 확인할 수 없으면 미확인으로 기록한다.
추천 모델이 없으면 현재 제공되는 코드 작업·이미지 검토 가능 모델 중 대안을 보고한다. 임의의 모델 식별자나 Pro/Codex 접미사를 만들지 않는다.
전역 Codex 설정 변경, 유료 서비스 가입, 별도 API 호출은 이 지시서의 권한이 아니다.

1. 시각 구성 후보:  imagegen-frontend-web, frontend-design 또는 design-system,
   실제 설치되어 있고 이번 작업에 맞는 경우 사용한다. 제목·본문·CTA 위계, 섹션 리듬, 카드 정렬, 중국어 조판을 다듬는 데 한정한다.

   없다면 설치를 전제로 막히지 말고 아래 디자인 계약을 직접 적용한다. 사용했다고 허위 보고하지 않는다.

2. 캡처·검수 우선 후보: playwright
   설치된 스킬의 필수 사전 점검과 브라우저 설정을 읽는다. 실제 브라우저 렌더링, 고정 viewport, DOM 검사, 전체 페이지·영역 PNG 생성에 사용한다.
   설치된 도구와 브라우저를 우선한다. 스킬에 설치 예시가 있어도 저장소 루트에 npm init이나 의존성 설치를 자동 실행하지 않는다.
   스킬이 없으면 이미 사용 가능한 브라우저 자동화·headless 캡처 도구로 같은 결과를 만든다.

3. 보조 후보: screenshot
   브라우저 전용 캡처가 부족할 때만 사용한다. OS 전체 화면 캡처 한 장으로 전체 페이지 PNG를 대체하지 않는다.

playwright-interactive는 필수가 아니다. 현지 지침과 환경이 안전하게 지원할 때만 검토한다.
스킬 사용을 위해 sandbox 해제, danger-full-access 전환, 권한 확대를 하지 않는다.
Figma·이미지 생성·Higgsfield·배포 스킬은 기본 경로에 포함하지 않는다. 이번에는 HTML/CSS → PNG 한 경로를 사용한다.

브랜드 원색은 제한된 큰 그래픽·미디어 포인트에 사용한다.
흰 글자의 주 버튼에는 #007FA8을 사용하며 #00ABE1로 대체하지 않는다.
녹색은 성공·실제 검증 상태에만 사용한다. 기존 브랜드 녹색·세이지를 A안 브랜드 스타일로 되살리지 않는다.
장식 이외의 텍스트·상태 구분은 색상만으로 전달하지 않는다. 밝은 블루 배경 위 링크·포커스도 실제 조합을 따로 확인한다.

데스크톱: 콘텐츠 최대 1200px, 12열 정렬, 히어로 좌6/우6, 최소 좌우 여백 40px.
모바일: 좌우 16px, 주요 콘텐츠 1열, 히어로 제목 → 설명 → CTA → 세로 미디어.
주요 섹션 간격 64~96px, 반경 4/8px, 제한적인 그림자와 얇은 구분선.
서로 다른 섹션을 모두 동일한 카드 격자로 만들지 않는다. 서비스는 2×2 카드, 시스템은 도식+설명, 비용은 표, FAQ는 질문 행, 견적은 2열 폼이다.

실제 접수 성공/알림만 실패/저장 실패의 분리는 후속 구현 검토 사항으로 남긴다.

실제 법인·주소·전화·이메일·WeChat은 확인·승인된 자료가 있을 때만 넣는다.

[정적 제작과 상호작용 경계]
웹 페이지와 모든 상태는 고정된 HTML/CSS 또는 빌드 시 조립으로 렌더링한다. 캡처 자동화 코드는 허용하지만 사용자용 동작 엔진을 만들지 않는다.
주 버튼·폼·FAQ의 상태는 상태별 파일/클래스/프레임으로 선택하며 실제 처리 로직과 혼동하지 않는다.

허용: 정확한 DOM 텍스트, CSS 레이아웃·media query·hover/focus 견본, 로컬 이미지, 정적 도식, 캡처 보조 스크립트.
제외: 실제 폼 전송, 서버/API/DB, 이메일, 분석, 쿠키 추적, localStorage 리드 저장, ScrollTrigger/GSAP, 영상 시킹, 실시간 3D, 외부 리소스 요청.
HTML 제출 버튼·Enter 입력 때문에 기본 form 전송이나 URL query에 입력값이 실리지 않도록 한다. type=button 등으로 비전송 상태를 보장한다.
프리뷰에 개인정보를 입력·수집하도록 유도하지 않는다. 캡처에는 합성 fixture만 쓴다.

링크는 README의 목적지 표로 설계한다. #quote, #services는 의도상 앵커다. 간단한 로컬 앵커는 가능하나 사이트의 스크롤 UX를 구현할 필요는 없다.
미구현 상세 경로의 활성 href나 가짜 사이트 페이지를 만들지 않는다. PNG의 링크 모양과 실제 연결 가능 여부를 구분한다.
원문의 ‘미공개 경로는 숨기거나 상담 문구로 대체’ 원칙을 적용하고, 바꾼 라벨·이유·원래 계획 경로를 기록한다.
프리뷰는 로컬 loopback으로만 열고 외부 배포·공유 URL·Figma 파일 게시를 하지 않는다.

모바일 하단 견적 CTA 의도:
- 히어로 CTA가 보일 때: 숨김
- 히어로 CTA가 화면을 벗어나고 폼은 보이지 않을 때: 표시
- 견적 폼이 보이거나 키보드가 열릴 때: 숨김
위 상태는 프레임으로 표현한다. IntersectionObserver·키보드 감지 로직을 구현하지 않는다.

[실행·검증 순서]
1. 기준·환경·스킬·자산·콘텐츠 상태 조사 → 짧은 제작 계획 기록.
2. 카피 원본과 콘텐츠 ID/조건부 상태/링크 목적지/자산 manifest 정리.
3. 헤더·히어로·서비스 카드로 위계를 잡고 S3~S7·푸터까지 같은 시각 체계로 확장.
4. 390px 핵심 구간, Scroll World 3상태, 폼·FAQ·fallback 보드 제작.
5. 실제 브라우저에서 렌더링 → PNG 생성 → 모든 PNG를 열어 시각 검수 → 원본 수정 → 다시 캡처.
6. 카피 대조, 범위·토큰·자산·네트워크 검증, diff 자기 검토 후 보고.

캡처 전 이미지 decode와 실제 폰트 로딩을 기다린다. 모션·caret·불안정한 로딩 상태를 고정하고 viewport와 배율을 명시한다.
전체 페이지 캡처와 별도 상태 프레임을 혼합해 실제 페이지에 없는 구성을 만들지 않는다.
픽셀 편집으로만 수정하지 말고 HTML/CSS 원본에서 수정해 재현 가능한 PNG를 다시 만든다.
캡처 한계를 우회하려고 원본을 축소하지 않는다. 분할 캡처가 불가피하면 누락·중복 없는 조합임을 검증하고 방법을 기록한다.

기존 lint/타입 검사/테스트 명령이 존재하고 이번 변경에 적용되면 실행한다.
