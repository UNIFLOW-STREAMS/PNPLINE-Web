# PNPLINE 중국어 사이트 페이지별 IA

기준일: 2026-09-13  
대상 도메인: `https://www.pnpline.cn`  
기준 사이트맵: [PNPLINE 중국어 사이트맵](pnpline-cn-sitemap.md)

## 문서 목적

이 문서는 중국어 사이트맵에 포함된 32개 페이지의 정보 구조를 정의합니다. 각 페이지의 방문 목적, 검색 의도, H1 방향, 섹션 순서, CTA, 내부 링크, 필요한 증빙을 개발과 콘텐츠 제작에 바로 사용할 수 있는 수준으로 정리합니다.

페이지는 중국 크로스보더 셀러가 `검색 → 서비스 이해 → 운영 실체 확인 → 가격 확인 → 상담` 순서로 이동하도록 설계합니다. 한국어 사이트의 섹션을 그대로 옮기지 않고, 중국 셀러가 실제로 비교하는 비용, 처리 범위, 통관 책임, 창고 실체, 시스템 연동 정보를 앞부분에 배치합니다.

## 공통 IA 규칙

### 헤더

헤더는 로고, 7개 메뉴, 견적 CTA로 구성합니다.

1. `美国海外仓`
2. `头程运输`
3. `清关与合规`
4. `平台方案`
5. `系统`
6. `关于我们`
7. `资讯`
8. CTA `免费获取报价`

`价格与报价`는 견적 CTA가 연결되는 `/pricing/`에서 제공하고, `联系我们`는 모바일 메뉴와 푸터에서 상시 노출합니다. `合作伙伴`와 `隐私政策`은 주 내비게이션에 넣지 않습니다.

### 공통 페이지 순서

서비스 페이지는 아래 순서를 기본으로 사용합니다.

1. 문제와 해결 범위를 설명하는 히어로
2. 적합한 고객과 화물 조건
3. 제공 서비스와 제외 범위
4. 실제 업무 절차
5. 요금 구조와 추가 비용
6. 창고·통관·시스템의 신뢰 근거
7. FAQ
8. 견적 또는 상담 CTA

### 공통 전환 요소

- 주 CTA는 페이지 의도에 맞게 `获取报价`, `咨询方案`, `提交需求` 중 하나를 사용합니다.
- 보조 CTA인 `加微信咨询`은 중국어 실시간 응대가 가능할 때만 노출합니다.
- 견적 폼은 `产品类目`, `发货方式`, `月出货量`, `目的地`, `是否需要IOR`, `微信号或手机号码`의 6개 필드를 기본으로 사용합니다.
- 정책·통관 페이지는 일반 견적 폼보다 `상품 유형`, `HS Code 보유 여부`, `IOR 필요 여부`를 먼저 묻는 상담 폼이 적합합니다.

### 공통 신뢰 요소

- Gardena(CA)와 Katy(TX)의 실제 주소, 시설 사진, 면적, 도크, 처리 능력은 운영팀이 확인한 값만 사용합니다.
- IOR, Bond, FDA·FCC, 관세 관련 표현은 미국 통관팀이 공개 전에 검수합니다.
- 리드타임, 요율, 처리량, 배송 범위에는 기준일과 적용 조건을 표시합니다.
- 실제 시설 페이지에서는 생성 이미지나 스톡 사진을 사용하지 않습니다.

### 공통 내부 링크

- 모든 L2 페이지는 상위 서비스 페이지 또는 홈에서 최소 한 개 이상의 링크를 받습니다.
- 모든 서비스 페이지는 `/pricing/`, `/about/facilities/`, `/contact/` 중 최소 두 페이지로 연결합니다.
- 운송 페이지는 관련 통관 페이지와 창고 페이지로 연결합니다.
- 플랫폼 페이지는 관련 창고 서비스, WMS·API, 통관 페이지로 연결합니다.
- 정책 콘텐츠는 관련 서비스 페이지로 연결하고, 서비스 페이지의 FAQ에서는 관련 정책 콘텐츠로 되돌아갑니다.

  1. S1 정책 적용 범위와 운영 주체를 설명합니다.
  2. S2 수집하는 개인정보 항목과 수집 경로를 설명합니다.
  3. S3 이용 목적과 법적 근거를 설명합니다.
  4. S4 보관 기간, 삭제, 국외 이전 또는 제3자 제공 여부를 설명합니다.
  5. S5 쿠키와 분석 도구 사용 방식을 설명합니다.
  6. S6 정보주체의 권리와 요청 방법을 제공합니다.
  7. S7 담당자 연락처, 시행일, 개정 이력을 제공합니다.
- CTA: 별도 영업 CTA를 두지 않고 `返回报价页面`만 제공합니다.
- 핵심 내부 링크: `/pricing/`, `/contact/`로 연결합니다.
- 필수 검수: 중국어 번역만으로 확정하지 않고, 실제 데이터 처리 위치와 중국 관련 법률 적용 여부를 법무 담당자가 검토합니다.

## 브레드크럼 규칙

- L1 페이지: `首页 > 当前页面` 형식을 사용합니다.
- `/warehouse/*/`, `/freight/*/`, `/customs/*/`, `/about/*/`, `/news/*/`는 URL 계층과 동일한 3단계 브레드크럼을 사용합니다.
- `/solutions/*/`는 별도 허브 URL이 없으므로 `首页 > 当前平台方案`의 2단계로 구성합니다.
- `/system/*/`도 별도 허브 URL이 없으므로 `首页 > 当前系统页面`의 2단계로 구성합니다.
- 현재 페이지를 제외한 브레드크럼 항목은 클릭할 수 있어야 하며, BreadcrumbList 구조화 데이터를 함께 사용합니다.

## 내부 링크 우선순위

1. `/customs/ior/`는 홈, 모든 운송 페이지, 통관 페이지, Amazon 페이지에서 연결합니다.
2. `/about/facilities/`는 홈, 해외창고 상위, 보관, 가격, 회사 소개에서 연결합니다.
3. `/pricing/`은 모든 상업적 서비스 페이지의 마지막 CTA와 헤더 견적 버튼에서 연결합니다.
4. `/system/wms/`와 `/system/api/`는 창고·플랫폼 페이지에서 운영 근거로 연결합니다.
5. `/news/ior-2026/`와 `/news/de-minimis/`는 관련 서비스 FAQ에서 연결하고, 각 글은 대응 서비스 페이지로 되돌아갑니다.
6. `/partner/`와 `/privacy/`는 푸터와 관련 전환 문맥에서만 연결해도 고립 페이지가 되지 않습니다.

## 구현 검수 기준

- 각 페이지에는 H1이 하나만 있어야 합니다.
- 각 페이지의 첫 두 섹션만 읽어도 대상 고객, 제공 범위, 다음 행동을 이해할 수 있어야 합니다.
- 모든 페이지는 홈에서 세 번 이내의 클릭으로 접근할 수 있어야 합니다.
- 각 페이지에는 최소 한 개의 유입 내부 링크와 두 개의 관련 페이지 링크가 있어야 합니다.
- CTA 문구는 페이지의 검색 의도와 동일해야 합니다.
- 가격, 리드타임, 정책, 자격, 시설 수치는 출처와 검수일이 없는 상태로 공개하지 않습니다.
- 모바일에서는 섹션 순서와 정보 우선순위를 유지하며, 표는 카드 목록이나 가로 스크롤 표로 전환합니다.
